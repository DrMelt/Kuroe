# 快速开始

从环境准备到完成第一个任务的最短路径。产物与工作目录见[安装与运行](usage/安装与运行.md)。

## 环境

目标机需要 .NET 10 运行时，以及可读键盘的交互终端，输入被重定向时拒绝启动。从 release 页面下载编译产物压缩包并解压，产物与操作系统和处理器架构无关。

## 启动

在产物目录执行：

```powershell
dotnet Kuroe.Console.dll -d <工作目录>
```

`-d` 省略时用启动进程的当前目录。

## 注册模型

工作目录里还没有提供商与模型时，先注册再接通。提供商是模型的宿主，有名字、端点与凭据；模型注册到提供商名下。模型名是本地命名，与模型实际使用的名字无关，例如注册名 `gpt-4o` 指向提供商 `openai`。

主菜单进入「模型与提供商」，依次：

1. 「添加提供商」，用输入表填写名称、端点与凭据
2. 「注册模型」，选择提供商后填写模型名
3. 「选择模型」，选中刚注册的模型

未选择模型也能启动；对话或提交任务时才需要。

## 第一个任务

流程库初始为空，提交任务前先给出一条流程。流程模板存在工作目录 `.kuroe/` 的 `flows.json`，写入下面这条最小流程。提交任务时 Kuroe 把当前选中的模型写入流程，流程文件不写模型名：

```json
{
  "Flows": [
    {
      "Name": "第一个任务",
      "Start": { "Outputs": [
        { "Name": "目标", "Type": "Text", "Description": "要让模型完成的目标。" },
        { "Name": "MODEL_NAME", "Type": "Text", "Constant": true }
      ] },
      "HostStartInputs": { "MODEL_NAME": "MODEL" },
      "Nodes": [
        {
          "Name": "整体",
          "Kind": "Container",
          "Inputs": [{ "Name": "目标" }, { "Name": "MODEL_NAME", "Type": "Text", "Static": true }],
          "In": { "目标": "Start@目标", "MODEL_NAME": "Start@MODEL_NAME" },
          "Nodes": [
            {
              "Name": "撰写",
              "Kind": "Llm",
              "Static": { "MODEL_NAME": "@MODEL_NAME" },
              "Prompt": "完成目标，交回结果。",
              "Inputs": [{ "Name": "目标" }],
              "Outputs": [{ "Name": "结果", "Type": "Text" }],
              "From": [{ "目标": "@目标" }]
            }
          ]
        }
      ]
    }
  ]
}
```

这条流程只有三段：开始入口 `Start` 交一个「目标」，模型由 Kuroe 在任务启动时给出，执行节点「撰写」经静态输入 `MODEL_NAME` 取用模型把目标写成结果，根容器「整体」把节点组织成流程。`整体` 声明传入端口 `目标` 与静态输入 `MODEL_NAME`，用 `In` 接 `Start@目标` 与 `Start@MODEL_NAME`，成员用 `@目标` 与 `@MODEL_NAME` 取用容器传入内容。节点字段、节点库与容器复用见[流程定义](reference/流程定义.md)。

接着提交并查看：

1. 主菜单进入「流程」，选「+ 导入流程」，用输入表填 `flows.json` 的路径，导入刚写的流程
2. 回主菜单进入「任务」，选「+ 提交任务」，选流程后在输入表填「目标」并确认提交
3. 在任务列表选中任务查看概览，可继续进入执行详情、节点树或过程记录

流程可手工编辑，改动后重新导入或重启 Console 生效。主菜单的「Kuroe 助手」进入常驻对话任务，随时可答，见[操作指南](console/操作指南.md)。
