# 任务操作

## 任务与执行

任务是执行的单位：按流程模板建任务，流程由节点组成：执行节点的模型选择由装配层输入，能力工具与指令在节点上声明，执行的上下文由上游装配后传入，不继承未声明的内容。用户任务由主菜单的「任务」管理。主菜单的「Kuroe 助手」进入内置助手的「对话」任务；对话任务属于私有任务域，不出现在任务菜单与 `KuroeInfo`，不占用户任务号，由「Kuroe 助手」页的「重置对话」管理，见[交互操作](交互操作.md)。

任务菜单的「提交任务」先选流程，再用输入表填写不带固定值的开始端口；输入表每次重印全部开始端口与已填内容，带固定值的端口作为上下文，全部填完后确认提交。流程来自 `.kuroe/flows.json`，或用「流程」菜单的「导入流程」导入。

## 查看

任务菜单打开任务列表：任务列表 → 任务概览 → 执行详情，逐级进入，用 `Esc` 或选择「返回」退一级。任务列表是一张表，列出任务号、标题、流程、创建时间、状态、待处理节点数、最近活动。任务概览给出任务字段、待处理节点与执行清单，执行菜单项带节点路径。节点树不在概览里直接展开，选择「查看节点树」时进入节点树页：按流程树列出容器、执行节点与执行，执行作为执行节点的子行。任务级过程记录由「查看过程记录」进入过程记录页打印。执行详情可跳转到装配时引用的上游执行。节点树页与过程记录页停在页内，可刷新，返回后回任务页。

浏览器用页面标题划分层级，每层顶部打印一条横线，标题写成从主菜单开始的进入路径，例如 `── 主菜单 › 任务 › 任务 #1 修复登录超时 ──`；页内内容各占一个带标题的框，例如 `概览`、`执行 2 次`。返回上一层后重新打印该层页面标题与内容。

用户任务的后台执行过程不写入终端，只有异常、停驻与取消输出一行通知。过程记录与执行详情按需查看。

执行详情分三块：执行概要、输入取值与过程记录。执行概要包含所属任务、节点序号、轮次、模型、状态、开始与结束时刻、耗时。输入取值按来源列成表，内容过长时截断。过程记录按时间列出类型与内容，一次工具调用占调用与结果两行。

「流程」菜单的「查看流程详情」先给出流程字段块，包含执行节点数、容器数、模型选择数与说明，再按节点树打印流程：开始端口、容器端口、执行节点的类型、模型、输入输出端口、工具、提问、执行上限与上游接线。上游按启动组给出，组内全部齐备，组间任一齐备。详情自成页面，可刷新，返回后回流程列表。

## 等待批准与返工

任务停在待批准或阻塞时，任务内菜单直接给出批准、返工、取消这几个动作，见[交互操作](交互操作.md)。取消整个任务要再确认一次，确认项默认停在保留任务。

等待不构成任务状态：停在待输入或待批准的节点计入任务列表的待处理列，并在任务概览的待处理表与节点树的节点一行里标出「待输入」或「待批准」及提问。任务状态与模型侧 `GetTask` 显示为「执行中」。

- `Kind: Approval` 的审批节点在上游启动条件齐备后停在待批准，选择「批准待批准的节点」放行全部待批准节点，下游随之启动。
- 执行节点失败、未收口或文件节点读写失败时停在阻塞，选择「返工被阻塞的节点」重跑被阻塞的目标或重新读写文件。

## 等待输入

`Kind: Input` 的输入节点不启动执行：依赖齐备后停在待输入。任务内菜单选择「回答等待输入的节点」后列出待输入节点与提问，选中节点后输入表给出节点与完整提问，回答即该节点产出并放行下游。回答会随下游执行装配进入输入取值，取消任务可随时终止等待。

## 收口上限

超出时不报错，按下列方式收口，都不需要通过配置调整：

| 位置                   | 上限                                      | 超出后                                                 |
| ---------------------- | ----------------------------------------- | ------------------------------------------------------ |
| 过程记录               | 400 条                                    | 丢最早的记录，任务与执行详情里标出被丢的条数           |
| 详情视图里的过程记录   | 最近 40 条                                | 更早的只报条数                                         |
| 过程记录里的一段文本   | 4096 字                                   | 另起一段，避免逐字增量反复拷贝整段                     |
| 执行输入取到的单条内容 | 2000 字                                   | 截断并加省略号                                         |
| 任务标题               | 40 字，超出加省略号                       | 未指定标题时取第一个开始输入的首行                     |
| 节点执行次数             | 100 次，执行节点、文件节点与容器可用 `MaxExecutions` 配置 | 达到上限不再重跑，未成功的停在阻塞                     |

## 任务工作目录

Console 提交任务时在启动工作目录的 `.kuroe_tasks/` 下为任务建立目录。目录命名与编号规则见[安装与运行](../usage/安装与运行.md#任务目录)。

- 任务号与任务列表显示的一致。
- 「改任务标题」只改任务标题，不重命名目录。
- 「清理已完成与已取消的任务」只清已完成与已取消且没有执行在跑的内存任务，不删目录；阻塞的任务不在清理范围内。
- 常驻对话任务在私有任务域内从 1 单独编号，不进入 `.kuroe_tasks/`，也不影响用户任务号的续号；回话节点的工具白名单不含 `file`，见[内置助手与专属工具](内置助手与专属工具.md)。
