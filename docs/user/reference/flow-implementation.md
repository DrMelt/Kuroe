# 流程实现

`.kuroe/flows.json` 的每条流程由图流程与 MAF 流程各装配一次。装配成功的实现各自提供一个流程变体，同一流程名可以有图流程变体与 MAF 变体。

流程定义仍只写在 `.kuroe/flows.json`。实现不写入配置文件，由装配结果决定。

## 规则

- 两个实现都支持时，流程目录出现两个变体，按引擎区分。
- 只有一个实现支持时，流程目录只出现该变体。
- 两个实现都不支持时，流程不可用，启动时给出两份装配失败原因。
- 提交任务必须选定实现。CLI 使用 `--engine`，Console 在流程列表中选择变体，KuroeInfo 的 `GetFlow` 使用 `engine` 参数。
- 已有任务按任务记录中的实现恢复，不受之后流程目录变化影响。
- 导入流程后图流程立即重新编译。MAF 变体在下次启动重新装配。

## MAF 支持范围

MAF 装配支持：

- 端口种类 `Context`、`Signal` 与自定义类型。
- 触发模式、常量模式、控制角色、正向与反向条件。
- 同端口多来源、组内 AND、组间 OR、运行期常量与多入口。
- `Emission.Once`。
- 容器成员提升，容器输出解析到成员端口。

MAF 暂不支持：

- 等待外部输入的节点类型。
- 从输入派生的输出。
- 不派发执行的节点类型。
- 环与多次执行。
- 容器成员齐备与容器输入接线中尚未实现的组合。
- 固定 `MODEL_NAME` 开始端口。

需要模型的 MAF 流程由宿主当前模型给值，提交时不需要填写 `MODEL_NAME`。当前没有选择模型时提交失败。

## 图流程支持范围

图流程支持流程描述语言的全部构造，包括等待外部输入、环、容器整体推进与多次执行。节点类型支持范围由宿主注册的节点库决定。

## 提交

CLI 的 `run` 与 `flow show` 接受 `--engine graph` 或 `--engine maf`。流程只有一个实现时可以省略。存在多个实现且未给 `--engine` 时命令返回可用实现列表。

Console 的流程列表与提交选择都按变体列出，选择项同时给出流程名与引擎。流程详情也按选中的变体展示。

流程变体的开始端口与输入要求可以不同，提交输入必须与选中的变体匹配。
