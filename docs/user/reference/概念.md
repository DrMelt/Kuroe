# 概念

本文定义文档反复使用的对象与术语。字段写法与操作步骤见对应页面。

## 工作区

工作目录由 `-d` 给出，是 Kuroe 的工作区根。命令里的文件参数、路径校验与工具路径基准都相对它解析，与启动进程的当前目录无关。工作目录下的目录布局见[安装与运行](../usage/安装与运行.md#工作目录)。

## 流程

流程是任务模板，由步骤组成。步骤拓扑来自节点图或宿主提供的代码定义。

节点图流程写在 `.kuroe/flows.json`，由节点组成，每条流程有且只有一个根节点，根节点可以是执行节点或容器。开始入口声明流程接收的输入，写在顶层 `Ports`。

代码流程与 MAF 流程由宿主以代码给出，不进入 `.kuroe` 目录。MAF 流程把步骤推进交给 Microsoft Agent Framework 运行期，每个步骤的运行仍是一次执行。

节点库写在 `.kuroe/nodes.json`，存放具名的节点定义，流程用 `Use` 引用。节点定义与引用的字段见[流程定义](流程定义.md)。

## 节点

节点按 `Kind` 分为容器与执行节点。

- 容器组合成员并限定作用域，自身不执行。
- 执行节点调用模型或执行外部动作，每次启动产生一次执行。
- `Input` 与 `Approval` 启动执行，由执行函数内部等待外部输入。

## 端口

端口是节点之间的内容通道。输出端口交回内容供下游读取，输入端口接收上游内容或静态值。

- 静态输入在任务内只确定一次值，只由下游 `Bindings` 读取。
- 动态输入由上游新产出驱动，写在 `From`。
- `Plain` 是普通动态端口，`Trigger` 携带触发值并门控下游启动组，`Constant` 在任务内只确定一次值。

端口类型、模式与组合规则见[流程定义](流程定义.md#端口与模式)。

## 作用域

容器限定成员的可见范围。成员只能引用本容器子树内的节点与容器传入端口，容器外的节点与端口不可见。开始端口只在流程作用域可见，根节点与根容器用 `@端口` 取用，容器成员经容器传入端口取用。

## 任务

任务是流程的一次提交，有任务键、标题、流程、开始输入与状态。任务启动后流程、开始输入与模型不再变化。任务数据与状态见[任务与执行](../usage/任务与执行.md)。

## 执行

执行是一次执行节点的运行，承载模型请求与工具往返，也承载等待外部输入的运行。一次执行记录请求次数、token 用量、过程记录与恢复数据。执行节点按上游产出反复启动，`Emission: Once` 首次成功发布后冻结。等待中的执行按运行中记录，占用调度额度。

流程控制给每次执行分配执行步骤标识，用来区分同一任务内的执行、计算轮次、恢复与登记等待。执行单元只透传标识，不解释其结构。

## 助手会话

助手会话是一条独立的对话任务，有任务键、标题、模型、回复语言、模式与历史。每个会话由多轮组成，一轮对应一次 Llm 执行。

每轮执行收口时把会话快照写入恢复数据。恢复数据同时作为下一轮上下文的起点与历史展示的来源。最后一份恢复数据之后的执行用执行记录补齐输入与状态。会话存档与用户任务存档分开，位置见[安装与运行](../usage/安装与运行.md#工作目录)。

## 停驻与恢复

停驻是流程安排的一次等待，分等待输入与等待批准。停驻由步骤的执行函数产生，不由工具调用产生。等待登记写在任务级输入通道，键是任务标识与流程步骤路径，等待中的执行占用调度额度。恢复指中断后从中断处继续同一次执行，重新执行指放弃恢复并新建一次执行，两者的操作后果见[任务与执行](../usage/任务与执行.md#暂停与恢复)。

## 宿主开始输入

开始端口默认由提交者给值。宿主开始输入表把指定的开始端口交给 Kuroe 给值，可取工作区根、任务目录与当前模型。表的结构见[宿主开始输入](宿主开始输入.md)。
