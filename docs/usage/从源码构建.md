# 从源码构建

使用编译产物见[安装与运行](安装与运行.md)。

## 环境要求

构建机需要 .NET SDK 10.0。

## 依赖准备

ApiHub 未发布到 nuget.org，`nuget.config` 的 local 源指向仓库内的 `packages/`，该目录不入库。克隆后在仓库根目录下载 release 的四个包：

```powershell
$ver = '0.2.0'
'ApiHub', 'ApiHub.ChatClient', 'ApiHub.Json', 'ApiHub.Shared' | ForEach-Object {
    Invoke-WebRequest "https://github.com/DrMelt/ApiHub/releases/download/v$ver/$_.$ver.nupkg" -OutFile "packages/$_.$ver.nupkg"
}
```

## 构建与测试

在仓库根目录执行：

```powershell
dotnet build Kuroe.slnx
dotnet test Kuroe.slnx
```

## 源码运行

### Kuroe.Console

```powershell
dotnet run --project Source/Kuroe.Console -- -d <工作目录>
```

### Kuroe.Cli

```powershell
dotnet run --project Source/Kuroe.Cli -- <命令> -d <工作目录>
```

入口的运行方式见[Console 快速上手](../console/快速上手.md)与[CLI 快速上手](../cli/快速上手.md)。

## 发布

发布时不指定运行时标识，得到与操作系统和处理器架构无关的产物：

### Kuroe.Console

```powershell
dotnet publish Source/Kuroe.Console -c Release -p:UseAppHost=false -o <输出目录>
```

### Kuroe.Cli

```powershell
dotnet publish Source/Kuroe.Cli -c Release -p:UseAppHost=false -o <输出目录>
```

两个入口可以发布到同一目录。`source/` 由 Kuroe.Console 产出，由它的 `source` 工具组读取，见[内置助手与专属工具](../console/内置助手与专属工具.md)。产物形态、目标机要求与工作目录见[安装与运行](安装与运行.md)。

单文件、自包含与 AOT 发布都要求指定运行时标识，产物按平台生成，不能作为跨平台产物分发。
