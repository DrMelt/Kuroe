# 工具扩展

本篇讲两个入口共用的工具机制与工具面。Console 专属的对话任务、导出资料与 `KuroeInfo/ListTools` 见[内置助手与专属工具](../console/内置助手与专属工具.md)，入口差异见[入口与分工](入口与分工.md)。

## 工具载体

模型可调用的能力由工具载体声明。实现 `ITool` 的类提供 `Functions`：每个函数由定义 `ToolDefinition` 与调用体绑定而成，定义给出工具路径、说明与参数，调用体把结果交回模型。工具路径形如 `分组/函数名`，是白名单匹配的层级，末段是函数名供宿主展示；交给模型的调用名由路径派生，把分隔符 `/` 换成 `_`。路径段只能写字母、数字、下划线与连字符，模型接口只接受这些字符。路径不同而调用名相同的工具会在装配时报错。

```csharp
public sealed class TimeTool : ITool
{
    private static readonly ToolDefinition GetLocalTime =
        new(new ToolPath("GetLocalTime"), "获取当前系统时区与准确当地时间", []);

    public IReadOnlyList<ToolFunction> Functions { get; } =
    [
        GetLocalTime.Bind(_ =>
        {
            DateTimeOffset now = DateTimeOffset.Now;

            return $"当前系统时间是：{now:yyyy-MM-dd HH:mm:ss}，时区 UTC{now:zzz}";
        }),
    ];
}
```

`ToolParameter` 声明参数：名字、给模型的说明、是否布尔值、是否必填、是否列表与是否路径。路径参数在调用体执行前统一校验，交给模型的 JSON Schema 里仍是字符串。宿主按定义里的参数拼装 JSON Schema，随请求交给模型。定义是独立的值，可带到别处复用或派生；调用体把结果文本交回模型，拒绝也写成文本。

需要按执行绑定的工具实现 `IScopedTool`，`ForExecution` 返回绑定到该执行的载体，过程记录与提交身份据此归属。

## 工具面

执行节点的工具由 `Tools` 白名单限定：按工具路径前缀匹配，写上级路径即放行整棵子树，写完整路径只放行单个函数，匹配按原文大小写敏感。非法路径（段为空、含字母数字下划线与连字符以外的字符，或以 `/` 开头结尾）匹配不到任何工具，写入白名单在流程装配时报错。声明 `Text` 或 `Signal` 输出端口的执行节点自动附上契约工具 `SubmitPortValues`：`Text` 端口交回端口内容，`Signal` 端口只交回端口名、取值不承载内容；`Context` 输出端口由来源透传，不附这个工具。所有执行节点都附上 `GetStatus` 与 `ReportCannotComplete`。两个入口装配的工具面不同，内置对话的固定白名单见[内置助手与专属工具](../console/内置助手与专属工具.md)。

内置状态查询工具整组在 `KuroeInfo` 下：`KuroeInfo/ListTasks`、`KuroeInfo/GetTask`、`KuroeInfo/GetExecution`、`KuroeInfo/GetCatalog`、`KuroeInfo/ListFlows`、`KuroeInfo/GetFlow`、`KuroeInfo/GetConfig`。它们从各服务的只读快照读取内容并交回文本，可用自然语言询问 Kuroe 状态；凭据不交给模型，目录工具只报凭据是否已设置。任务与执行查询只覆盖用户任务域。默认不在执行节点的工具面中，需要时在节点 `Tools` 白名单里显式声明。`KuroeInfo/ListTools` 只随 Kuroe.Console 装配，见[内置助手与专属工具](../console/内置助手与专属工具.md)。

内置文件访问工具整组在 `file` 下，按只读与改动再分两个子分组：不改变文件的函数在 `file/read`，改动文件的函数在 `file/write`；白名单写 `file` 即两个子分组一起放行，写 `file/read` 只放行只读函数。

| 函数                      | 作用                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `file/read/ReadFile`      | 读取工作目录内文本文件指定行号范围，`from`/`to` 是行号，缺省读前 50 行，超出文件行数读到文件尾                                               |
| `file/read/ReadFiles`     | 一次读取多个文本文件，结果按 `paths` 顺序分段交回；路径越界或缺参整次拒绝，文件不存在等读取错误不阻断其它条目                            |
| `file/read/ListDirectory` | 列出目录直接子项，`path` 缺省为工作目录根                                                                                                    |
| `file/read/GetFileInfo`   | 取文件的文件系统信息：字节大小、创建/修改/访问时间与只读、隐藏、系统、归档属性；只受理文件，目录用 `ListDirectory` 列出条目                  |
| `file/write/WriteFile`    | 覆盖写入文本，`content` 为空时生成空文件，上限 40000 字符，父目录缺失自动创建                                                                |
| `file/write/PatchFile`    | 按 `from`/`to` 行号范围替换内容，`original` 必须是该范围当前原文、不一致时拒绝并回给实际内容，`replacement` 为空时删除该范围，写回统一换行符 |
| `file/write/MoveFile`     | 移动文件或目录，`source` 与 `target` 是相对工作路径，同目录改名即重命名；目标已存在时拒绝，父目录缺失自动创建                                |

路径是相对工作目录的写法，路径参数在调用前统一校验：解析后必须落回工作目录内，`..` 与绝对路径逃出时整次调用被拒绝；路径参数给空字符串或空白也拒绝，根目录通过省略 `path` 表达。校验按路径字符串进行，不解析目录联接点与符号链接。文本按 UTF-8 解码，带 BOM 时识别。写回编码由 `encoding` 指定，支持 `utf-8`、`utf-8-bom`、`utf-16`、`utf-16be`，缺省 `utf-8` 不带 BOM。单个文件超 8000 字符截断，批量读取整体超 40000 字符截断，目录列表超 200 条时截断。文件信息的时间按本地时区输出，格式为 `yyyy-MM-dd HH:mm:ss`；属性只报只读、隐藏、系统、归档四项，四项都没有时写「无」。

## 内置 git 工具

内置 git 工具整组在 `git` 下，按只读与改动再分两个子分组：不改变仓库的函数在 `git/read`，改动暂存区、工作树与分支的函数在 `git/write`；白名单写 `git` 即两个子分组一起放行，写 `git/read` 只放行只读函数。九个函数都是命令工具定义，模板与参数在 `Tool\Implementation\Git\Core` 声明，模板展开与进程执行由命令模板工具承担，命令在项目工作目录里执行。

| 函数                | 作用                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `git/read/Status`   | 查看工作树的改动状态：当前分支与各项的暂存、未暂存、未跟踪情况                            |
| `git/read/Diff`     | 查看改动差异，`staged` 为真时比较暂存区与 HEAD，`revision` 指定比较对象，`paths` 限定路径 |
| `git/read/Log`      | 查看提交历史，单行概述并按新到旧排列，`count` 是要看的条数，`paths` 限定路径              |
| `git/read/Show`     | 查看一个提交的说明与改动，`revision` 是提交号或修订号                                     |
| `git/read/Branches` | 列出全部分支及其当前提交，含远端分支                                                      |
| `git/write/Add`     | 把 `paths` 的改动放入暂存区                                                               |
| `git/write/Commit`  | 提交暂存区的改动，`message` 是提交说明，`paths` 限定提交范围                              |
| `git/write/Switch`  | 切到 `branch` 分支，`create` 为真时新建分支并切过去                                       |
| `git/write/Restore` | 丢弃 `paths` 的改动，`staged` 为真时把路径移出暂存区并保留工作树内容                      |

`paths` 是路径参数，经 `--` 收尾，`--` 与路径项一起增删；模型给出的路径按项目工作目录解析，越出工作目录时调用被拒绝且不启动进程，通过后原样交给 git。开关是布尔参数，命令行文字由模板固定，模型只能决定开关的真假。修订号与分支名不做校验，非法值由 git 报错并按命令模板工具的方式交回文本。全部是本地操作，推送、抓取等远端操作不在其中。

## 内置 dotnet 工具

内置 dotnet 工具整组在 `dotnet` 下，按只读与改动再分两个子分组：只查环境与项目信息的函数在 `dotnet/read`，会编译、改写项目或产生产物的函数在 `dotnet/write`；白名单写 `dotnet` 即两个子分组一起放行，写 `dotnet/read` 只放行只读函数。函数都是命令工具定义，模板与参数在 `Tool\Implementation\Dotnet\Core` 声明，模板展开与进程执行由命令模板工具承担，命令在项目工作目录里执行，程序固定为 `dotnet`。

| 函数                       | 作用                                                           |
| -------------------------- | -------------------------------------------------------------- |
| `dotnet/read/Info`         | 查看本机 .NET 环境：SDK 与已装运行时的版本、安装位置与当前 RID |
| `dotnet/read/ListSdks`     | 列出本机已安装的 SDK 版本与安装位置                            |
| `dotnet/read/ListPackages` | 列出项目顶层的包引用，`outdated` 为真时只列出有新版本的包      |
| `dotnet/read/NugetSources` | 列出配置的 NuGet 包源，读到项目工作目录及其上级的 NuGet 配置   |
| `dotnet/write/Build`       | 编译项目，`configuration` 是 Debug 或 Release 之类的生成配置   |
| `dotnet/write/Test`        | 运行测试，`filter` 是测试筛选表达式                            |
| `dotnet/write/Run`         | 运行项目，`arguments` 是传给应用的参数                         |
| `dotnet/write/Restore`     | 还原项目的包依赖                                               |
| `dotnet/write/Format`      | 按项目里的代码风格设置整理源码                                 |
| `dotnet/write/Publish`     | 发布项目到输出目录，`configuration` 是生成配置                 |
| `dotnet/write/AddPackage`  | 给项目添加包引用，`package` 是包名，`version` 是版本号         |

`project` 是路径参数，给出项目、解决方案或目录的相对路径，按项目工作目录解析并限制在工作目录内，越界时调用被拒绝且不启动进程；缺省时 dotnet 在项目工作目录里查找。`configuration`、`filter`、`version` 是可选参数，与命令行里的选项项一起增删，缺省时命令行里没有 `--configuration`、`--filter`、`--version`。`outdated` 是布尔开关，`arguments` 是独立的参数列表，写在 `--` 之后。`package` 是必填参数，缺省时调用被拒绝。

命令不在交互模式下运行。查询环境与项目的函数超时 120 秒，包列表与添加包的函数超时 300 秒，编译、测试、运行、还原、整理、发布的函数超时 600 秒；应用在超时前不结束会被连同进程树终止。推送包、部署到远端这类动作不在其中。

## 命令模板工具

无需写代码也能加工具：在工作目录 `.kuroe/tools.json` 里声明命令工具，模板以参数项数组给出，启动时按定义注册到工具面；文件不存在时没有命令工具，条目不合法时启动报错。下例 RunDiff 与 RunLog 同属 `git` 分组，完整路径分别是 `git/RunDiff` 与 `git/RunLog`，模型按完整路径调用，白名单写 `git` 即整组放行，写 `git/RunDiff` 只放行一个。参数项按字符串或对象区分，写法见[参数规则](#参数规则)。

```json
{
  "Tools": [
    {
      "Name": "RunDiff",
      "Group": "git",
      "Description": "查看指定文件或目录相对 HEAD 的改动。",
      "Template": ["git", "diff", "{path}"],
      "Parameters": [
        { "Name": "path", "Description": "要查看的文件或目录路径", "Required": true, "Path": true, "Deny": [".kuroe"] }
      ]
    },
    {
      "Name": "RunLog",
      "Group": "git",
      "Description": "查看指定文件列表的提交历史。",
      "Template": ["git", "log", "--oneline", "--", "{files}"],
      "Parameters": [
        { "Name": "files", "Description": "限定查看的文件路径列表", "List": true, "Path": true, "Allow": ["Source", "docs"] }
      ]
    },
    {
      "Name": "RunCurl",
      "Description": "携带可省略的访问令牌请求一个 URL。",
      "Template": ["curl", "-f", { "Text": "Authorization: Bearer {token}", "OmitWhenMissing": "token" }, "{url}"],
      "Parameters": [
        { "Name": "token", "Description": "访问令牌，可省略" },
        { "Name": "url", "Description": "请求地址", "Required": true }
      ]
    }
  ]
}
```

| 字段             | 类型                 | 含义                                                                                                                                                                                                                     |
| ---------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Name`           | string               | 函数名，构成完整路径的末段；省略 `Group` 时完整路径即它。只能写字母、数字、下划线与连字符                                                                                                                                |
| `Group`          | string               | 工具路径的分组部分，与 `Name` 拼出完整路径 `分组/函数名`；每段只能写字母、数字、下划线与连字符。完整路径是节点白名单的匹配项，不能与其他已注册工具重复，写上级路径即放行整棵子树；路径不同而模型调用名相同的工具装配报错 |
| `Description`    | string               | 给模型的说明                                                                                                                                                                                                             |
| `Template`       | (string \| object)[] | 命令行模板，数组每一项是一个参数项，对象写法见[参数规则](#参数规则)                                                                                                                                                      |
| `Parameters`     | object[]             | 参数声明：`Name`、`Description`、`Flag`、`Required`、`List`、`Path`、`Allow`、`Deny`                                                                                                                                     |
| `Directory`      | string               | 命令执行目录，相对工作目录，缺省为工作目录根；不限制在工作目录内，含路径参数时必须在工作目录内                                                                                                                           |
| `TimeoutSeconds` | int                  | 命令超时秒数，缺省 120，最大 2147483                                                                                                                                                                                     |
| `OutputLimit`    | int                  | 交回文本上限，缺省 8000 字符                                                                                                                                                                                             |

### 参数规则

标量参数：`Required` 必填的参数缺省时调用被拒绝，可选参数缺省时对应的参数项整体消失；缺省指未给出或 JSON null。非路径标量参数的空字符串是有效值，会原样传给命令。

`List` 声明字符串列表参数，模型以数组给出，模板里必须写成独立的 `{files}` 参数项，不传或空数组时该项消失；列表参数不能嵌在其他文字里，如 `"--flag={files}"` 不合法。

模板参数项对象把参数项与参数显式关联：`Text` 是命令行文字，可含占位符也可完全不含，`OmitWhenMissing` 是关联参数名，两个字段都必须给出。关联参数缺省（未给或 JSON null，列表未给或空数组）时整个参数项从命令行去掉，包括项里的文字；关联参数必填且缺省时调用被拒绝。字符串项内嵌占位符缺省时保留字面量原样传给命令。固定文字的项靠关联参数增删，例如 `{ "Text": "--", "OmitWhenMissing": "paths" }` 在 `paths` 缺省时连同 `--` 一起去掉；不含占位符的项，其关联参数要么是布尔参数，要么在模板别处作为占位符出现。

`Flag` 声明布尔参数，模型以真假给出。布尔参数只作开关：模板里写成关联该项的 `OmitWhenMissing`，为真时整个参数项加入命令行，为假或缺省时去掉，参数本身不出现在命令行文字里；布尔参数不能同时是列表参数或必填参数。

`Path` 声明路径参数，模型给出的是路径。路径按执行目录解析，解析后必须落在工作目录内，绝对路径与 `..` 越出工作目录时拒绝，该边界不因白黑名单配置而关闭。路径参数不能是 `Flag`，可以与 `List` 组合，列表逐项校验，任一项不通过即整次调用拒绝且不启动进程。路径参数给空字符串或空白时拒绝，缺省只指未给出或 JSON null。

`Allow` 与 `Deny` 是路径参数的白名单与黑名单，只用于 `Path` 为真的参数。条目按工作目录解析，每个条目都必须在工作目录内。匹配按目录段前缀，目标等于条目或落在条目之下，`src` 覆盖 `src` 与 `src/...`，不覆盖 `src2`。黑名单优先，命中即拒绝；白名单非空时未命中即拒绝，白名单为空或省略时不限制。

含路径参数的工具，其 `Directory` 必须在工作目录内，否则装载报错。路径校验只做字符串解析与归一，不解析符号链接与目录联接点；传给命令的仍是模型给出的原文。

模型调用时替代占位符、在 `Directory` 指向的目录启动进程，stdout 与 stderr 合并成文本交回模型，附退出码；超时或启动失败也写成文本。输出按 UTF-8 解码，用本地代码页输出的 Windows 工具其文本可能乱码。参数项经进程启动直接传入，不经 shell 解释，模板不支持管道、重定向等 shell 语法。

`tools.json` 声明模型有权调用的命令，是命令执行边界所在，采纳仓库或共享目录前先检查其模板与 `Directory`。模板第一项是程序本身。不要把占位符嵌进 `cmd /c`、`bash -c` 这类 shell 解释器命令串，模型实参里的元字符会被 shell 解释，等同于把任意命令执行能力交给模型。

内置工具的实现在 `Source\Kuroe\Tool` 下分两处。与工具面无关的共用件在区根：工具契约基座在 `Tool\Core`，工具文件的聚合在 `Tool\Json`，根目录内文件访问与行号范围的共用件在 `Tool\FileAccess`。工具面实现在 `Tool\Implementation` 下按面分项目，统一写成 `Tool\Implementation\<工具面>\Core`，取 `Time`、`File`、`Source`、`Command`、`Git`、`Dotnet`、`Contract`、`KuroeInfo`；命令模板工具另有定义层 `Shared` 与承载层 `Json`，命令定义与模板规则在 `Tool\Implementation\Command\Shared`，进程执行在 `Source\Kuroe\Process\Core`，命令模板工具与命令执行节点共用这一进程边界，路径类型、解析范围与准入在 `Tool\Core`，`tools.json` 的形状与读入在 `Tool\Implementation\Command\Json`，工具实现不接触承载格式。内置 git 工具与 dotnet 工具分别在 `Tool\Implementation\Git\Core` 与 `Tool\Implementation\Dotnet\Core` 只声明命令定义，模板展开与进程执行仍由命令面承担。各面的文件形状在 `Tool\Json` 的注册表里按文件名登记，宿主装配时一次装载全部工具文件，得到与承载格式无关的配置工具记录。`FileAccess` 被 `File` 与 `Source` 两个工具面经它取实现；工具项目不引用宿主。只读宿主状态的工具经共用契约层的只读视图取数：`ICatalogView` 在 `Source\Kuroe\Shared\Catalogs` 声明，`ISettingsView` 在 `Source\Kuroe\Shared\Configuration` 声明，两者由宿主实现，工具不接触目录与配置的实现类型。

新增工具在 `Source\Kuroe\Tool\Implementation\<工具面>\Core` 下建项目，在 `ServiceCollectionExtensions.RegisterTools` 的 `tools` 列表里追加载体，再由该方法的 `composition.AddTools(tools)` 统一注册为 `ITool`。重复路径与调用名冲突会在 `AddTools` 的校验中被拒绝：

```csharp
List<ITool> tools =
[
    new TimeTool(),
    new MyTool(),
];
ErrorOr<Success> added = composition.AddTools(tools);
```

内置的 `GetLocalTime` 是示例工具，状态查询、文件访问、git 操作与 dotnet 操作见上面的工具面一节；导出资料见[内置助手与专属工具](../console/内置助手与专属工具.md)。契约工具 `SubmitPortValues` 对应[节点定义](节点定义.md)里声明 `Text` 或 `Signal` 输出端口的执行节点，`GetStatus` 与 `ReportCannotComplete` 对应每个执行节点的本轮状态查看与无法完成上报。
