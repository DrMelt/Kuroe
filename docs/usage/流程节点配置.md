# 流程节点配置

流程模板存在工作目录 `.kuroe/` 的 `flows.json`，可以手工编辑，也可以 `/flow add <文件>` 导入。文件不存在时用内置「默认」流程。节点分为两层：顶层节点库定义可复用的节点，每条流程用一个根节点把节点装配成图。加载与导入时校验节点库与各条流程，全部非法项一次给出；导入的任一流程不合法就整体不生效。

文件形状：

```json
{
  "Nodes": [
    { "Name": "库节点名", ... }
  ],
  "Flows": [
    {
      "Name": "流程名",
      "Description": "可选说明",
      "Models": [],
      "Nodes": [
        {
          "Name": "根容器名",
          "Nodes": []
        }
      ]
    }
  ]
}
```

## 节点库

顶层 `Nodes` 是节点定义，作为复用单元供流程引用。两种定义：

- **执行节点定义**：声明模型选择引用、工具白名单与产出契约，不写接线。
- **容器定义**：`Nodes` 子数组组织一组有序成员，`Inputs` 声明传入端口，成员可用 `@端口名` 引用传入内容。

## 模型选择

`Models` 是按名引用的模型选择，执行节点用 `Model` 引用。模型选择未写 `Model` 时流程可以加载，但引用它的执行节点无法确定模型，提交任务或派发 run 时报错。

| 字段    | 类型   | 含义                                             |
| ------- | ------ | ------------------------------------------------ |
| `Name`  | string | 配置名，流程内唯一且不能为空                     |
| `Model` | string | 使用的模型名，省略时引用它的执行节点无法确定模型 |

## 节点

节点分执行节点与容器两类，写有 `Nodes` 子数组即是容器，否则是执行节点。两类节点共用基础字段：

| 字段   | 类型          | 含义                                                         | 适用     |
| ------ | ------------- | ------------------------------------------------------------ | -------- |
| `Name` | string        | 节点名，流程/定义内唯一且不能为空                             | 全部     |
| `Gate` | `Auto`/`Review` | 停在待批点等人批准；执行节点产出后、容器成员齐备后           | 全部     |

## 引用与装配

流程里的节点可以内联定义，也可以引用节点库定义。引用节点只写 `Name` 与 `Use`：

```json
{ "Name": "实施", "Use": "执行" }
```

| 字段   | 含义                                                                 |
| ------ | -------------------------------------------------------------------- |
| `Use`  | 引用的节点库定义名，引用容器时可用 `In` 绑定输入端口                  |
| `In`   | 端口绑定表：端口名到流程内节点名的映射，值可以是 `@外层端口名`        |
| `From` | 仅引用执行节点时注入接线，指向流程内更早的节点或容器                 |

引用容器时实例名省略则取定义名；引用同一个容器定义多次时必须给不同 `Name`，展开后成员名带 `实例名.` 前缀，实例之间互不冲突。绑定端口必须已由容器定义 `Inputs` 声明。

引用节点不带 `Gate`，门控由库定义决定；引用容器不写 `From`。装配层内联容器不声明 `Inputs`，输入端口声明只属于节点库容器定义。

每条流程的 `Nodes` 有且只有一个根节点；根节点通常是承载流程全部内容的容器，可以内联定义，也可以引用库容器定义，还可以是单个执行节点。

## 执行节点

执行节点是唯一真实执行的节点，内联定义由以下字段描述，库定义同样适用（接线除外）：

| 字段          | 类型                    | 含义                                                                             |
| ------------- | ----------------------- | -------------------------------------------------------------------------------- |
| `Model`       | string                  | 引用的模型选择名，必须定义在同流程的 `Models` 里                                 |
| `Prompt`      | string                  | 对执行单元的额外要求，与目标一起构成指令                                         |
| `Tools`       | string[]                | 能力工具白名单，按函数名匹配；省略或空时不给出任何能力工具                       |
| `Output`      | `Plain`/`Plan`          | 交回什么：普通文本、条目拆分，决定收口方式与契约工具                             |
| `Mode`        | `Single`/`PerItem`      | 整节点一个 run，还是按拆分条目各派一个                                           |
| `Branch`      | string                  | 只处理拆分中归属该分支的条目，未写时处理全部条目                                 |
| `Split`       | object                  | 拆分源的固定配置，只能写在规划执行节点上                                         |

`Output` 决定收口方式并自动附上契约工具：

- `Plain`：模型交回文本产出。
- `Plan`：模型通过 `SubmitPlanItems` 工具交回条目拆分。

`Mode: PerItem` 的执行节点按条目展开，条目集来自其引用的规划执行节点，见[依赖与展开](#依赖与展开)。

执行节点库定义不写接线，`From` 由引用处提供；内联执行节点直接写 `From`。

#### 拆分

`Split` 固定规划执行节点的拆分源：

| 字段         | 类型   | 含义                                            |
| ------------ | ------ | ----------------------------------------------- |
| `Items`      | array  | 静态条目清单，1 到 20 条                        |
| `ExtrasMax`  | int    | 模型最多补充的条数，0 到 20，0 或省略表示不补充 |
| `Acceptance` | string | 统一验收文本，覆盖模型补充条目的验收标准        |

静态条目 `Items` 每项：

| 字段          | 类型   | 含义                             |
| ------------- | ------ | -------------------------------- |
| `Title`       | string | 标题，必填                       |
| `Instruction` | string | 要做什么，必填                   |
| `Acceptance`  | string | 该条目的验收标准，省略视为未提供 |
| `Branch`      | string | 归属的分支，省略视为不分流       |

纯静态拆分指定义的 `Items` 非空且 `ExtrasMax` 为 0 或省略，拆分没有模型参与，此时规划节点不可声明 `Prompt`、`From` 与 `Gate: Review`。

有分支执行节点从本规划节点取拆分时，交回的条目必须写明 `Branch` 且落在已有分支上。

### 容器节点

容器组合执行节点并为子节点限定作用域，自身不执行、不派 run，成员产出齐备时作汇合点。容器定义额外支持：

| 字段     | 类型   | 含义                                                         |
| -------- | ------ | ------------------------------------------------------------ |
| `Nodes`  | array  | 有序子节点，至少一个，整棵子树至少含一个执行节点             |
| `Inputs` | string[] | 输入端口声明，成员可用 `@端口名` 引用，引用处用 `In` 绑定   |

容器不可声明执行配置、`From` 与 `In`。容器可声明 `Gate`，成员齐备后停在待批准。容器门控嵌套时逐层停批：子容器停在待批时父容器视为未齐备，子容器获批后父容器接续判断；容器成员里的执行节点停在待批时同样计为成员未放行。

库里容器定义的自包含要求：成员 `From` 只能引用容器定义内部的节点，或 `@` 已声明的输入端口——容器作为整体可被多处引用而不依赖外部名字。

## 依赖与展开

依赖由 `From` 直接表达：引用的执行节点必须先于本节点产出，多个来源的产出一并进入上下文；同一个来源可以派生出多个下游并行推进。边按来源与目标模式在编译期推导消费方式：

| 来源               | 目标      | 消费方式                                        |
| ------------------ | --------- | ----------------------------------------------- |
| 容器               | 任意      | 等整组齐备，取整份                              |
| 执行节点           | `Single`  | 取来源一整份产出                                |
| 执行节点           | `PerItem` | 来源 `PerItem` 时按条目对齐，规划节点时按条展开 |
| `PerItem` 执行节点 | `Single`  | 等来源全部条目实例产出齐备                      |

按条目展开的执行节点从引用的规划执行节点取条目清单，每条目一个 run。声明 `Branch` 时只处理拆分中归属该分支的条目；分支并行即多个声明不同 `Branch` 的执行节点引用同一个规划执行节点。

## 校验规则

启动时逐条校验，全部非法项一次给出。规则即任务推进依赖的不变量：

- 每条流程有且只有一个根节点。
- 节点库名非空且库内唯一，节点库定义不能是引用自身。
- 节点名不能为空且流程内唯一，模型配置名不能为空且流程内唯一。
- 节点引用的模型选择必须存在，引用的节点库定义必须存在。
- 执行节点库定义不写 `Inputs`、`From` 与 `In`；容器定义不写执行配置、`From` 与 `In`；引用节点不写执行配置、子节点、`Inputs` 与 `Gate`，引用容器不写 `From`。
- 引用节点不能同时声明执行配置或子节点，绑定端口必须已由容器定义声明。
- 容器定义自包含：成员 `From` 只指向定义内部节点或已声明端口，至少要包含一个执行节点。
- `From` 引用必须存在；容器不可被引用为容器的输入，但可作为执行节点的来源。
- 引用关系按容器成员展开成执行依赖后必须无环，成员从自身所在容器链取输入一并视作环拒绝。
- 按条目展开的执行节点必须从规划执行节点取拆分，或从其它展开执行节点对齐输入。
- 声明 `Branch` 的执行节点必须按条目展开并从规划执行节点取拆分；逐条对齐的两端必须来自同一个拆分。
- `Split` 只写在规划执行节点上。

## 内置流程

`flows.json` 不存在或 `DefaultFlow` 未写入用户层时，用内置「默认」流程：制定计划 → 分配执行。内置内容本身就是节点库加装配：库定义规划、执行两个执行节点与「交付」容器，流程用根容器包住「制定计划」与「交付」两个引用。两个模型选择都不写 `Model`，流程可加载但执行时无法确定模型。

## 示例

定义工具型的执行节点与「交付」容器，两条流程复用同一容器：

```json
{
  "Nodes": [
    {
      "Name": "允许工具",
      "Model": "执行者",
      "Tools": ["GetLocalTime", "GetWeather"],
      "Mode": "PerItem"
    },
    {
      "Name": "交付",
      "Inputs": ["计划"],
      "Nodes": [
        { "Name": "实施", "Use": "允许工具", "From": ["@计划"] }
      ]
    }
  ],
  "Flows": [
    {
      "Name": "单线交付",
      "Description": "制定计划、复用交付",
      "Models": [
        { "Name": "规划者", "Model": "<模型>" },
        { "Name": "执行者", "Model": "<模型>" }
      ],
      "Nodes": [
        {
          "Name": "整体",
          "Nodes": [
            { "Name": "制定计划", "Model": "规划者", "Output": "Plan", "Prompt": "把目标拆成可独立实施的条目。" },
            { "Name": "交付", "Use": "交付", "In": { "计划": "制定计划" } }
          ]
        }
      ]
    },
    {
      "Name": "并行实施",
      "Description": "规划后分两条分支并行实施",
      "Models": [
        { "Name": "规划者", "Model": "<模型>" },
        { "Name": "实施者", "Model": "<模型>" }
      ],
      "Nodes": [
        {
          "Name": "并行整体",
          "Nodes": [
            { "Name": "制定计划", "Model": "规划者", "Output": "Plan" },
            { "Name": "撰写", "Model": "实施者", "Mode": "PerItem", "Branch": "撰写", "From": ["制定计划"] },
            { "Name": "排版", "Model": "实施者", "Mode": "PerItem", "Branch": "排版", "From": ["制定计划"] }
          ]
        }
      ]
    }
  ]
}
```
