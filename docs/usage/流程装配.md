# 流程装配

流程里的节点可以内联定义，也可以引用节点库定义；引用节点写 `Name`、`Use`，模型由装配层输入。每条流程的 `Nodes` 有且只有一个根节点，根节点通常是承载流程全部内容的容器，可以内联定义，也可以引用库容器定义，还可以是单个执行节点。流程的起点是 `Start` 声明的来源节点，节点名即保留名 `Start`，它是唯一的来源，一切节点经 `From` 引用它取用初始输入；节点字段见[节点定义](节点定义.md)，节点库与文件装载见[流程文件与节点库](流程文件与节点库.md)。

## 模型选择

`Models` 是按名引用的模型选择。模型选择名只出现在流程装配层：装配层执行节点和引用执行节点用 `Model` 写选择名，引用节点组用 `Models` 把组内模型槽位绑定到选择名。模型选择未写 `Model` 时流程可以加载，但引用它的执行节点无法确定模型，提交任务或启动 run 时报错。

| 字段    | 类型   | 含义                                             |
| ------- | ------ | ------------------------------------------------ |
| `Name`  | string | 模型选择名，流程内唯一且不能为空                 |
| `Model` | string | 使用的模型名，省略时引用它的执行节点无法确定模型 |

## 引用与装配

引用节点写 `Name`、`Use`，模型由装配层输入：引用执行节点用 `Model` 写模型选择名，引用节点组用 `Models` 绑定组内槽位：

```json
{ "Name": "实施", "Use": "执行", "Model": "执行者" }
```

| 字段      | 含义                                                                   |
| --------- | ---------------------------------------------------------------------- |
| `Use`     | 引用的节点库定义名，引用容器时可用 `In` 与 `Models` 绑定               |
| `Model`   | 引用执行节点时的模型选择名，必须定义在同流程的 `Models` 里             |
| `Models`  | 引用节点组时的模型槽位绑定：槽位名到本流程模型选择名的映射             |
| `In`      | 端口绑定表：引用容器时端口名到流程内节点引用的映射，值写 `来源@端口` 或 `@更外层端口`；执行节点不写 `In`，接线一律用 `From` |
| `From`    | 仅引用执行节点时注入接线，指向流程内更早的节点或容器；条目形态见[上游接线](#上游接线) |
| `MaxRuns` | 引用执行节点时覆盖库定义的自身上限，引用容器时覆盖库定义的组内统一上限 |

引用容器时实例名省略则取定义名；引用同一个容器定义多次时必须给不同 `Name`，展开后成员名带 `实例名.` 前缀，实例之间互不冲突。绑定端口必须已由容器定义 `Inputs` 声明。

引用执行节点时 `Model` 必填，模型选择由此从装配层输入；引用节点组时用 `Models` 把组内执行节点的模型槽位绑定为本流程的模型选择名，组内任何槽位未绑定都会在加载时报错。库容器定义内嵌套引用节点组时，`Models` 的绑定值可以是当前节点组可见的槽位名，沿绑定链透传到装配层。

引用节点不带 `Gate`，门控由库定义决定；引用容器不写 `From`。装配层内联容器不声明 `Inputs`，输入端口声明只属于节点库容器定义。

装配层及其他容器不能直接引用容器实例内部的成员或成员端口，下游消费必须写 `容器名@端口`，容器对外只暴露 `Outputs` 声明的端口。

## 依赖与展开

依赖由 `From` 直接表达：引用的执行节点必须先于本节点产出，多个来源的产出一并进入上下文；同一个来源可以派生出多个下游并行推进。边按来源与目标模式在编译期推导消费方式：

| 来源               | 目标      | 消费方式                                            |
| ------------------ | --------- | --------------------------------------------------- |
| Start              | 任意      | 取端口一份，带 `Value` 的端口给固定值，其余端口给提交任务的初始输入 |
| 容器               | 任意      | 等整组齐备，按声明的命名端口取值                    |
| 执行节点           | `Single`  | 取来源一整份端口产出                                |
| 执行节点           | `PerItem` | 来源 `PerItem` 时按条目对齐，声明 `Items` 端口的执行节点时按条展开 |
| `PerItem` 执行节点 | `Single`  | 等来源全部条目实例产出齐备                          |

数据来源一律按边上端口取值：执行节点取该端口一份，PerItem 来源按目标模式对齐或拼接全部实例，容器来源取 `Outputs` 绑定转发。`Items` 种类端口只作用于按条目展开的目标，不注入文本内容。开始可声明多个 `Data` 端口，带 `Value` 的端口固定输出该值，不带 `Value` 的端口输出提交任务的初始输入，下游按端口精确消费。

`From: ["来源@上下文"]` 与端口引用同按单份消费：来源最近一次成功放行 run 的整个装配上下文整体注入，逐条保留角色与出处，指令单列，系统指令不随帧透传；PerItem 来源取各实例上下文。`Context` 条目同一来源产出单独置于上下文开头。

按条目展开的执行节点从引用的拆分源取条目清单，每条目一个 run。声明 `Branch` 时只处理拆分中归属该分支的条目；分支并行即多个声明不同 `Branch` 的执行节点引用同一个拆分源。

### 上游接线

```json
"From": [
  "计划@结论",
  { "Node": "审查@结论", "Or": "修改" },
  { "Node": "通知@结论", "Signal": true },
  { "Node": "背景@结论", "Context": true }
]
```

`From` 是执行节点的唯一接线字段，每条目标记来源引用与消费方式。无标记条目是数据来源，产出进入目标上下文，数据与可选组来源全部齐备且任一来源发布未消费的新版本时启动。带 `Or` 的条目标记可选启动组，组内条目齐备即满足该组，任一组满足即可启动；未声明数据来源时仅需任一组成员齐备。带 `Signal` 的条目不进上下文只作触发信号，有信号条目时由任一信号来源的新版本驱动启动，否则由任一数据或可选组来源的新版本驱动。带 `Context` 的条目把来源产出置于目标上下文最前，与系统指令构成稳定前缀，来源必须是非输入、非按条目展开的执行节点。来源可以是执行节点或容器，信号、可选组与上下文条目按单份消费，数据条目按来源与目标模式推导消费方式。条目引用必须落端口：容器只能写 `容器名@端口`，执行节点写 `来源@端口`，容器成员写 `@端口` 绑定容器传入端口。

`Or` 按组名聚合：同组内条目产出一并取用，同一来源可以跨组重复。条目按 来源与标记 整体判重，完全相同的条目不可重复，带不同标记的同源条目可以并存。声明可选组、信号或上下文的节点必须整节点执行，不与 `PerItem` 叠用；输入节点不声明可选组、信号与上下文。

库执行定义不写接线，装配层引用处注入的 `From` 就是该实例的全部接线；库容器成员内的执行节点直接写 `From`，引用只落在当前容器作用域内。

执行节点按来源产出版本记账：任一来源重新发布且齐备时重启本节点，启动即登记来源当前版本，同一版本不重复启动。`From` 引用的 PerItem 来源按整份实例一次性消费，实例集重新产出不再次驱动；可选组条目同样按版本记账，任一组发布新版本即驱动该组；信号条目只由信号来源新版本驱动。

容器同样按版本记账：容器版本跟随直接成员与子容器的内容版本，任一来源发布新版本且容器重新齐备即触发一次，与执行节点的发布语义一致；成员在执行或停驻时容器暂不齐备，成员恢复放行且来源有已消费过的新版本才再次触发。

### 输出校验

`Validate` 给执行节点一条输出校验规则：run 收口后按声明端口依声明序拼接出的端口文本做判定，未声明端口不能声明 `Validate`。不通过则节点停在阻塞等待返工，产出不发布、不交给下游。校验通过的节点按普通节点推进，同样随来源新版本重启。执行节点引用可以互相指回构成环，环必须有环外来源或环内输入节点才能启动，环内节点随来源新版本互相驱动；校验不通过则停在阻塞，通过则放行，闭环的收敛由输出校验阻塞或 `MaxRuns` 兜底。纯 From 互引做不成环：两个整节点互为前置时谁都不会启动，环内至少一侧必须是可选组或信号提供器节点，重启由它的新版本驱动：

```json
{ "Name": "计划", "Kind": "Executable", "Model": "执行者", "Outputs": [{ "Name": "结论", "Kind": "Data" }] },
{ "Name": "修订", "Kind": "Executable", "Model": "执行者", "Outputs": [{ "Name": "结论", "Kind": "Data" }], "From": [{ "Node": "计划@结论", "Or": "初始" }, { "Node": "审查@结论", "Or": "返工" }] },
{ "Name": "审查", "Kind": "Executable", "Model": "执行者", "Outputs": [{ "Name": "结论", "Kind": "Data" }], "From": ["修订@结论"], "Validate": { "Predicate": "TextContains", "Argument": "通过" } }
```

修订先随「初始」组启动产出初稿；审查对修订产出复核，不通过即停在阻塞；返工重跑审查通过并放行后，「返工」组的新版本再驱动修订重写。审查放行后若不加 `MaxRuns`，修订会被审查新版本继续重写、审查也随之重审，直到任一方到达执行上限，因此这类互驱动环按 `MaxRuns` 封顶收敛。

`Signal` 条目同样构成由来源新版本驱动的迭代环：目标随信号来源发布的新版本重启，环仍需环外来源或环内输入节点才能启动，收敛由输出校验或 `MaxRuns` 兜底，见[上游接线](#上游接线)。

| 字段        | 类型   | 含义                                                           |
| ----------- | ------ | -------------------------------------------------------------- |
| `Predicate` | enum   | `NonEmpty`、`TextContains`、`TextNot`、`TextEquals`、`Pattern` |
| `Argument`  | string | 谓词参数：指定文本或正则，`NonEmpty` 不需要                    |

声明 `Validate` 的节点必须整节点执行，必须声明至少一个 `Data` 输出端口供校验取文本，不与 `PerItem` 叠用；`Predicate` 必须是白名单内的名字，需要参数的谓词必须给参数，`Pattern` 的正则必须合法。校验失败后节点停在阻塞，返工目标即节点自身，重跑后再校验。环由引用自然产生；同一条执行路径的执行次数达到 `MaxRuns` 上限后不再重启。

### 对话环

含输入节点的环把输入节点当挂点：输入节点由 `From` 里的 `Start@端口` 触发，进入等待回答，每轮回答发布后沿环推进，回到输入节点时产出被消费并复位，重新挂着等下一轮，对话由此一轮接一轮。输入节点每轮从外部接收回答，是周期外源，但仍要由开始入口触发第一次挂起，见[依赖与展开](#依赖与展开)。

```json
{ "Name": "收话", "Kind": "Input", "Outputs": [{ "Name": "回答", "Kind": "Data" }], "From": ["Start@目标", "回话@回复"] },
{ "Name": "回话", "Kind": "Executable", "Model": "执行者", "Outputs": [{ "Name": "回复", "Kind": "Data" }], "From": ["收话@回答"] }
```

## 校验规则

启动时逐条校验，全部非法项一次给出。库定义与装载规则见[流程文件与节点库](流程文件与节点库.md#校验规则)，节点形状规则见[节点定义](节点定义.md#校验规则)：

- 每条流程有且只有一个根节点。
- 流程必须声明 `Start`，恰好一个不带 `Value` 的 `Data` 端口承接提交任务的初始输入，其余端口必须带 `Value`；节点名 `Start` 是保留名。
- 每个执行节点与输入节点都必须能从开始经 `From` 引用边到达，否则不会被触发。
- 模型选择名不能为空且流程内唯一；节点引用的模型选择必须存在，引用的节点库定义必须存在。
- 装配层执行节点与引用执行节点必须写模型选择名，且必须存在于同流程的 `Models`，未写或不存在报错。
- 引用节点组的 `Models` 绑定覆盖组内全部模型槽位，未绑定的槽位在加载时报错；引用执行节点不写 `Models`，引用节点组不写 `Model`。
- 引用节点不写执行配置、子节点、`Inputs` 与 `Gate`，引用容器不写 `From`；引用节点组不声明 `From` 与 `Validate`，两者只属于执行节点。库定义内的引用成员不写 `Gate`，门控由被引用的库定义决定。
- 引用节点不能同时声明执行配置或子节点，绑定端口必须已由容器定义声明。
- 容器外不能直接引用容器实例内部的成员或成员端口，`From` 条目必须落在引用节点的容器作用域内，或经容器 `Outputs` 端口消费。
- `From` 条目引用的来源必须存在；条目按 来源与标记 整体判重，完全相同的条目不可重复，带不同标记的同源条目可以并存，同一来源可跨可选组重复。
- 容器不可被引用为容器的输入，但可作为执行节点的来源。
- 引用关系按容器成员展开后，环必须有环外来源或环内输入节点才能启动；成员只从自身所在容器取输入视为无法启动。
- 按条目展开的执行节点必须从声明 `Items` 端口的执行节点取 `Items` 拆分，或从其它展开执行节点对齐输入。
- 声明 `Branch` 的执行节点必须按条目展开并从声明 `Items` 端口的执行节点取拆分；逐条对齐的两端必须来自同一个拆分。
- `From: ["来源@上下文"]` 消费来源声明的 `Context` 种类端口，注入来源最近成功放行 run 的装配上下文，不含来源的系统指令，来源必须是执行节点，输入节点不落 run 不可作来源。
- 装配层执行节点用 `From` 条目的 `Context` 标记接入上下文前缀段，来源必须是流程里的非输入、非按条目展开的执行节点，只能写节点名或 `来源@端口`，不能引容器或绑定端口；`Context` 条目的来源产出必须恒定以命中前缀缓存。
- 同一执行路径的执行次数达到 `MaxRuns` 上限后不再启动新 run。

## 示例

下面是一份完整的流程文件，场景是按大纲撰写文档：节点库把按条撰写与合成全文两个执行能力定义成可复用节点，再用容器「成稿」把它们组装成先逐章撰写、再合成全文的交付单元；两条流程都引用「成稿」，模型由各自装配层从外部输入。节点库不写模型，「成稿」组内成员用 `Model` 写槽位名，流程引用容器时用 `Models` 把槽位绑定到本流程的模型选择：
