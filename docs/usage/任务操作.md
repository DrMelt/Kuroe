# 任务操作

## 任务与执行

任务是执行的单位：按流程模板建任务，流程由节点组成：执行节点的模型选择由装配层输入，能力工具与指令在节点上声明，执行的上下文由上游装配后传入，不继承未声明的内容。用户任务由 `/task` 管理。普通输入进入内置助手的「对话」任务；对话任务属于私有任务域，不出现在 `/task` 与 `KuroeInfo`，不占用户任务号，由 `/reset` 管理，见[命令参考](命令参考.md)。

`/task new --flow <流程> <目标>` 按给定流程提交任务，流程来自 `.kuroe/flows.json` 或用 `/flow add <文件>` 导入。

## 查看

`/task` 打开任务浏览器：任务列表 → 任务概览 → 执行详情，逐级进入，用 `Esc` 或选择「返回」退一级。任务列表是一张表，列出任务号、标题、流程、创建时间、状态、待处理节点数、最近活动。任务概览给出任务字段、待处理节点与执行清单，执行菜单项带节点路径。节点树不在概览里直接展开，选择「查看节点树」或运行 `/task tree <任务号>` 时才打印：按流程树列出容器、执行节点与执行，执行作为执行节点的子行。执行详情可跳转到装配时引用的上游执行。

浏览器用页面标题划分层级，每层顶部打印一条横线，标题写成进入路径，例如 `── 任务列表 › 任务 #1 修复登录超时 ──`；页内内容各占一个带标题的框，例如 `概览`、`执行 2 次`。返回上一层后重新打印该层页面标题与内容。

用户任务的后台执行过程不写入终端，只有异常、停驻与取消输出一行通知；`/task show <任务号>` 与 `/task execution <执行号>` 是不进任务浏览器的等价查看方式。`/task show` 打印任务概览与过程记录，不打印节点树；`/task execution` 打印该执行的输入来源与过程。

执行详情分三块：执行概要、输入取值与过程记录。执行概要包含所属任务、节点序号、轮次、模型、状态、开始与结束时刻、耗时。输入取值按来源列成表，内容过长时截断。过程记录按时间列出类型与内容，一次工具调用占调用与结果两行。

`/flow show <流程>` 先给出流程字段块，包含执行节点数、容器数、模型选择数与说明，再按节点树打印流程：开始端口、容器端口、执行节点的类型、模型、输入输出端口、工具、提问、执行上限与上游接线。上游按启动组给出，组内全部齐备，组间任一齐备。

## 等待批准与返工

任务浏览器在任务停在待批准或阻塞时直接给出批准、返工、取消这几个动作，对应的命令见[命令参考](命令参考.md)。取消整个任务在浏览器里要再确认一次，确认项默认停在保留任务。

等待不构成任务状态：停在待输入或待批准的节点计入任务列表的待处理列，并在任务概览的待处理表与节点树的节点一行里标出「待输入」或「待批准」及提问。任务状态与模型侧 `GetTask` 显示为「执行中」。

- `Kind: Approval` 的审批节点在上游启动条件齐备后停在待批准，`/task approve <任务号>` 才放行，下游随之启动。多个审批节点同时待批准时用 `/task approve <任务号> @节点路径` 点名单个节点，节点路径写成从根到本节点的段序列，如 `@整体/审阅`。
- 执行节点失败或未收口时停在阻塞，`/task rework <任务号>` 重跑被阻塞的目标。

## 等待输入

`Kind: Input` 的输入节点不启动执行：依赖齐备后停在待输入。用 `/task answer <任务号> [<@节点路径>] <文本>` 回答，回答即该节点产出放行下游；多个待输入节点并存时必须用 `@节点路径` 点名单个节点，路径写成从根到本节点的段序列，如 `@整体/收话`；唯一待输入节点时无需点名，回答文本首词即使与节点路径相同也原样保留。任务浏览器选择「回答等待输入的节点」后列出待输入节点与提问，选中节点再输入回答。回答会随下游执行装配进入输入取值，取消任务可随时终止等待。

## 收口上限

超出时不报错，按下列方式收口，都不需要通过配置调整：

| 位置                   | 上限                                      | 超出后                                                 |
| ---------------------- | ----------------------------------------- | ------------------------------------------------------ |
| 过程记录               | 400 条                                    | 丢最早的记录，`/task show` 与执行详情里标出被丢的条数 |
| 详情视图里的过程记录   | 最近 40 条                                | 更早的只报条数                                         |
| 过程记录里的一段文本   | 4096 字                                   | 另起一段，避免逐字增量反复拷贝整段                     |
| 执行输入取到的单条内容 | 2000 字                                   | 截断并加省略号                                         |
| 任务标题               | 40 字                                     | 取目标首行截断                                         |
| 节点执行次数             | 100 次，执行节点与容器可用 `MaxExecutions` 配置 | 达到上限不再重跑，未成功的停在阻塞                     |

## 任务工作目录

`/task new` 提交的任务在启动工作目录的 `.kuroe_tasks/` 下各占一个目录，名字为 `任务号-流程-标题`，例如 `0003-审阅-修复登录超时`。

- 任务号与 `/task list` 显示的任务号一致，四位定宽，超过四位自然增长。
- 流程与标题在创建时取一次，`/task title` 只改任务标题，不重命名目录。
- 流程段不含连字符，标题段可以含；非法字符与控制字符替换为下划线，流程段截到 20 字符，标题段截到 40 字符。
- 启动时按已有任务目录的最大号加一续号，同名目录不会被复用。
- `/task clear` 只清已完成与已取消且没有执行在跑的内存任务，不删目录；阻塞的任务不在清理范围内。
- 常驻对话任务在私有任务域内从 1 单独编号，不进入 `.kuroe_tasks/`，也不影响用户任务号的续号；回话节点的工具白名单不含 `file`。
