# 任务操作

## 任务与 run

任务是执行单元：按流程模板建任务，流程由节点组成：执行节点的模型选择由装配层输入，能力工具与指令在节点上声明，run 的上下文由上游装配后传入，不继承未声明的内容。对话也是任务：普通输入进入常驻的「对话」流程任务，见[命令参考](命令参考.md)。

`/task new <目标>` 按默认流程提交任务，默认流程未设置或指定流程用 `/task new --flow <流程> <目标>`。

## 查看

`/task` 打开任务浏览器：任务列表 → 任务内已执行与在跑的 run → run 的详情，逐级进入，用 `Esc` 或选择「返回」退一级。列表同时给出在跑与已启动的 run 数，详情可跳转到装配时引用的上游 run。

后台 run 的过程不写入终端，只有异常、停驻与取消输出一行通知；`/task show <任务号>` 与 `/task run <run号>` 是不进任务浏览器的等价查看方式。

`/flow show <流程>` 打印节点的层级、节点类型、展开方式、上游引用与执行要求。

## 等待批准与返工

任务浏览器在任务停在待批准或阻塞时直接给出批准、返工、取消这几个动作，对应的命令见[命令参考](命令参考.md)。

等待不构成任务状态：停在待输入或待批准的节点只在任务浏览器与 `/task show` 的节点一行里标出，`/task list` 与模型侧 `GetTask` 显示为「执行中」。

- `Kind: Approval` 的审批节点在上游启动条件齐备后停在待批准，`/task approve <任务号>` 才放行，下游随之启动。多个审批节点同时待批准时用 `/task approve <任务号> @节点名` 点名单个节点。
- 执行单元失败或未收口时停在阻塞，`/task rework <任务号>` 重跑被阻塞的目标。按条目展开的节点逐条目隔离：一个条目停在阻塞不挡住同节点其它条目的启动与推进。

## 等待输入

`Kind: Input` 的输入节点不启动 run：依赖齐备后停在待输入。用 `/task answer <任务号> [<@节点名>] <文本>` 回答，回答即该节点产出放行下游；多个待输入节点并存时必须用 `@节点名` 点名单个节点，唯一待输入节点时无需点名，回答文本首词即使与节点名相同也原样保留。回答会随下游 run 装配进入上下文，取消任务可随时终止等待。

## 收口上限

超出时不报错，按下列方式收口，都不需要通过配置调整：

| 位置                   | 上限                                      | 超出后                                                 |
| ---------------------- | ----------------------------------------- | ------------------------------------------------------ |
| 过程记录               | 400 条                                    | 丢最早的记录，`/task show` 与 run 详情里标出被丢的条数 |
| 详情视图里的过程记录   | 最近 40 条                                | 更早的只报条数                                         |
| 过程记录里的一段文本   | 4096 字                                   | 另起一段，避免逐字增量反复拷贝整段                     |
| 装配进上下文的单条内容 | 2000 字                                   | 截断并加省略号                                         |
| `Context` 类型端口注入的内容 | 逐条 2000 字                              | 与装配内容同限，并按上下文帧计为多条                 |
| 任务标题               | 40 字                                     | 取目标首行截断                                         |
| 一个方案的条目         | 20 条                                     | 提交被拒绝，模型在同一轮里改正                         |
| 节点执行次数           | 100 次，执行节点与容器可用 `MaxRuns` 配置 | 达到上限不再重跑，未成功的路径停在阻塞                 |
