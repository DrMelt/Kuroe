# 流程文件与节点库

流程模板存在工作目录 `.kuroe/` 的 `flows.json`，可以手工编辑，也可以 `/flow add <文件>` 导入。文件不存在时用内置「默认」流程。节点分为两层：顶层节点库定义可复用的节点，每条流程用一个根节点把节点装配成图。节点库由程序内置节点与文件顶层 `Nodes` 同名合并，以文件定义覆盖。加载与导入时都校验：节点库不合法时只报节点库错误，节点库合法时逐条流程校验并一次给全。导入的任一流程不合法就整体不生效；导入的文件必须能独立装配，流程引用的节点要来自内置节点或写在同一文件里。

节点对象的字段见[节点定义](节点定义.md)，流程的引用与接线见[流程装配](流程装配.md)。

文件结构：

```json
{
  "Nodes": [
    { "Name": "库节点名", "Kind": "Executable", ... }
  ],
  "Flows": [
    {
      "Name": "流程名",
      "Description": "可选说明",
      "Models": [],
      "Nodes": [
        {
          "Name": "根容器名",
          "Kind": "Container",
          "Nodes": []
        }
      ]
    }
  ]
}
```

## 节点库

顶层 `Nodes` 是节点定义，作为复用单元供流程引用。节点定义有两个来源：程序内置节点随启动注册，文件顶层 `Nodes` 定义自定义节点。两者同名合并，以文件定义覆盖；同一文件内顶层节点名重复报错。内置节点是执行节点「规划」「执行」与容器「交付」。

两种定义：

- **执行节点定义**：声明输出端口、工具白名单与执行方式，不写接线，不声明模型。
- **容器定义**：`Nodes` 子数组组织一组有序成员，`Inputs` 声明传入端口，成员可用 `@端口名` 引用传入内容；`Outputs` 声明命名输出端口，条目写 `Name` 与 `Ref`，把内部成员产出透出为容器对外接口。

节点定义的对象形状见[节点定义](节点定义.md)；库定义只声明能力，模型与接线由装配层输入。

## 内置流程

`flows.json` 不存在或 `DefaultFlow` 未写入用户层时，用内置「默认」流程：制定计划 → 分配执行。内置节点「规划」「执行」与容器「交付」由程序注册，其中「规划」是声明 `Items` 端口的执行节点；内置流程用根容器包住「制定计划」与「交付」两个引用；装配层从外部输入模型，「制定计划」写规划者配置，「交付」把执行者配置绑定给组内实施节点。两个模型选择都不写 `Model`，流程可加载但执行时无法确定模型。

## 校验规则

启动时逐条校验。节点库不合法时只报节点库错误，不再校验流程；节点库合法时逐条流程校验，全部非法项一次给出。规则即任务推进依赖的不变量，下列规则属于库定义与文件装载，节点形状规则见[节点定义](节点定义.md#校验规则)，引用、展开与环的规则见[流程装配](流程装配.md#校验规则)：

- 节点库名非空且库内唯一，节点库定义不能是引用自身。
- 节点库执行定义与容器定义不声明模型，节点组内执行成员必须写模型槽位名。
- 执行节点库定义不写 `Inputs`、`From`、`In` 与容器形状的 `Outputs` 条目。
- 容器定义不写执行配置、`From`、`In`、`SystemPrompt` 与 `Validate`。
- 容器定义自包含：成员 `From` 只指向定义内部节点或已声明端口，至少要包含一个执行节点。
