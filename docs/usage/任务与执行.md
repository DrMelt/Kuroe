# 任务与执行

本文说明任务与执行的数据、状态与操作后果，术语见[概念](../reference/概念.md)。

## 任务数据

每次提交任务在 `.kuroe_tasks/` 下建立任务目录，名字是任务键，`TASK_WORK_PATH` 给出它的绝对路径，绑定方式见[宿主开始输入](../reference/宿主开始输入.md)。

任务数据保存在工作目录内，包含任务输入、过程记录、工具参数与输出、模型回复、流程快照与执行恢复数据，属于敏感数据，需要与工作目录一起保护。

Console 启动时加载未完成的任务，以暂停状态呈现，恢复后继续推进。CLI 的 `run` 生成的任务保留在工作目录，可由 Console 查看与继续。同一工作目录可以运行多个实例，各实例只推进自己持有的任务。

## 状态

- 任务：执行中、已阻塞、已暂停、已完成、已终止
- 执行节点：待执行、执行中、已阻塞、已完成、已取消
- 单次执行：排队中、执行中、已完成、失败、已中断

任务阻塞表示存在无法推进的节点。任务暂停表示停止派发新执行，可以恢复。

## 停驻

`Input` 与 `Approval` 表达停驻。等待人工内容或批准时任务进入等待，其他节点照常推进。

人工停驻只在交互入口提供，并一次放行任务内全部待批准节点，不能按节点挑选。需要逐个确认时应拆分任务或流程。非交互入口不读取输入，也不提供批准与回答，含停驻的流程不可运行。

停驻只阻止尚未发生的动作，已执行的命令、已写入的文件与已发出的请求不能由批准撤销。需要人工确认的写入或命令应放在停驻下游。

## 暂停与恢复

暂停任务停止派发新执行并中断在跑执行，任务可恢复。可恢复的中断收口后任务自动暂停，只停止新的调度，不中断在跑的执行。

恢复任务从上次中断处继续。恢复执行沿用来源执行的输入、工具面与已交回的端口，已交回端口无需再次提交。网络中断、超时、停止执行、暂停任务与进程退出使用同一套恢复语义。

重新执行让当前阻塞不再可恢复、作废目标节点已发布产出，并按当前输入新建一次执行，不继承上次执行的会话历史。已保存的恢复数据保留。

是否可恢复由节点类型判断，Llm 提供恢复，`Command`、`FileRead` 与 `FileWrite` 中断后只能重新执行。可恢复的节点在阻塞表与节点树里标记为可恢复。

## 过程记录

任务过程记录是任务级权威记录，记录任务提交、执行启动与收口、等待输入、生命周期动作、完成与退出。Console 呈现最近 40 条，更早的只报条数；KuroeInfo 给出最近 10 条。

执行过程记录只在运行中可见，进程重启后不再显示。执行恢复数据在重启后仍可查看。

## 用量

执行记录模型请求次数与 token 用量。请求次数按真正发出的请求统计，未返回用量的请求数附在次数后。

token 用量取自 provider 返回的 usage，分输入、输出与合计，另记缓存输入与推理 token，后两者属于输入与输出的子集，不重复计入合计。展示分输入、输出与合计三项，缓存输入写在输入项内，推理写在输出项内。输入与输出各给出占合计的比例，缓存输入给出占输入的比例，推理给出占输出的比例；基数未知、为 0 或子项大于母类时不显示比例。输入或输出任一未知时两者都不显示占合计的比例。

上下文取最近一次返回用量的请求的输入 token 数，不随请求累计；该请求没有给出输入 token 数，或其后有请求未返回用量时显示未提供。provider 不返回 usage 时该请求记为未返回用量，不按 0 计，并清除上下文。

请求次数与用量在执行运行中为当前累计，收口后为最终值。执行详情里的请求次数只统计本次执行。
