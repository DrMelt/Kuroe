# 安装与运行

## 环境要求

目标机需要 .NET 10 运行时。Kuroe.Console 要求可读键盘的交互终端，输入或输出被重定向时拒绝启动。

## 安装

从 release 页面下载编译产物压缩包，解压到任意目录。压缩包内含 `Kuroe.Console.dll` 与 `Kuroe.Cli.dll`。

## 运行入口

| 入口          | 用途                         |
| ------------- | ---------------------------- |
| Kuroe.Console | 交互终端、内置助手与任务浏览 |
| Kuroe.Cli     | 脚本与 CI 的一次性调用       |

两个入口都支持 `-d` 与 `-h`。`-d` 省略时用启动进程的当前目录，`-h` 打印用法，参数错误以非零退出码结束。

## 工作目录

`-d` 给出工作目录，其下的 `.kuroe/` 存放六个配置文件：

| 文件                   | 内容                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `settings.json`        | 偏好设置，见[设置](设置.md)                                          |
| `catalog.json`         | 提供商、模型及其凭据，含明文凭据，不要提交                           |
| `nodes.json`           | 节点库，流程引用的可复用节点，见[流程定义](../reference/流程定义.md) |
| `flows.json`           | 任务流程模板，见[流程定义](../reference/流程定义.md)                 |
| `hostStartInputs.json` | 宿主开始输入表，见[宿主开始输入](#宿主开始输入)                      |
| `tools.json`           | 命令模板工具，见[工具配置](../reference/工具配置.md#命令模板工具)    |

两个入口的命令里的文件参数相对该工作目录解析，与启动时的进程当前目录无关。`nodes.json`、`flows.json` 与 `tools.json` 含命令执行声明，来源不可信的工作目录不要直接运行，见[安全与权限](安全与权限.md)。

### 宿主开始输入

`hostStartInputs.json` 声明哪些开始端口由 Kuroe 给值。顶层只写 `HostStartInputs`，键是流程名，值是开始端口名到宿主输入名的映射：

```json
{
  "HostStartInputs": {
    "实施与检查": { "启动路径": "WORKSPACE_PATH", "模型": "MODEL" },
    "仓库实施与检查": { "任务目录": "TASK_WORK_PATH", "MODEL_NAME": "MODEL" }
  }
}
```

| 宿主输入         | 值                                       |
| ---------------- | ---------------------------------------- |
| `WORKSPACE_PATH` | 工作区根目录绝对路径，即 `-d` 给出的目录 |
| `TASK_WORK_PATH` | 本次任务目录绝对路径                     |
| `MODEL`          | 任务启动时选中的本地模型名               |

端口名不受宿主输入名约束，绑定只由这张表决定。表里的开始端口在任务提交时由 Kuroe 给值，不接受用户输入；表之外的开始端口按普通用户输入处理，端口名与宿主输入名相同也不发生绑定。没有表项的流程不获得宿主输入。表里的端口必须是 `Text` 端口，带 `Value` 的开始端口不能进表，带 `Default` 的开始端口可以进表，进表后由宿主值优先。

表随启动读取，改动后重启生效。启动时校验表的结构与名字，表与流程开始入口的一致性在任务提交时校验，流程导入与流程编译不涉及这份表。流程导入只导入流程结构，需要宿主给值的流程在导入后补这张表。

### 任务目录

每次提交任务在 `.kuroe_tasks/` 下建立任务目录，名字为 `任务键-流程-标题`，例如 `0199a7f2c3d54e8b9a1f2c3d4e5f6a7b-审阅-修复登录超时`。任务键是 32 位十六进制唯一标识。任务目录是宿主输入 `TASK_WORK_PATH` 的值，工作区根目录是 `WORKSPACE_PATH` 的值，两者的绑定方式见[宿主开始输入](#宿主开始输入)与[流程定义](../reference/流程定义.md#路径与任务目录)。

### 任务存档

`.kuroe_tasks/.records/` 下每个任务一个存档文件与一个租约文件。存档是任务级权威记录，保存写入时刻、任务级记录、全部执行记录、节点状态与端口发布历史，在任务提交、执行启动与收口、等待输入、生命周期动作、完成与退出时更新。状态变化先标记待写，由后台合并写盘，交互动作不等写盘；任务提交与终止在返回或释放租约前等待存档落盘，保证其他进程立即看到该状态。Console 启动时加载存档，未完成的任务以暂停状态出现，恢复后继续推进；CLI 写存档但不加载，`run` 生成的任务由 Console 查看与继续，任务目录保留。存档格式版本为 10，只读取版本 10，旧版本存档不再读取。端口发布历史作为顶层 `Ports` 保存，节点状态只记录当前活动发布版本。执行契约随执行记录保存，恢复执行继承来源执行已交回的端口与无法完成原因。可恢复的模型请求把节点恢复状态写入执行记录，重启后恢复任务即可从中断处继续；执行过程记录只在运行中可见，不写入存档。

租约的判据是 `.lock` 文件上的独占句柄，不是文件是否存在。任务创建或加载时获取，终止、清理与退出时释放。进程异常退出后锁文件保留，系统已关闭句柄，新进程可以直接接管。同一工作目录可以运行多个实例，各实例只加载自己持有的任务，启动横幅报告由其他实例占用的任务数。CLI 也获取租约，运行中的任务在 Console 中计入由其他进程持有。
