# 安装与运行

## 环境要求

目标机需要 .NET 10 运行时。交互终端只由 Kuroe.Console 提供；Kuroe.Cli 不提供交互，也不读取 stdin。

## 安装

从 release 页面下载编译产物压缩包，解压到任意目录。压缩包内含 `Kuroe.Console.dll` 与 `Kuroe.Cli.dll`。

## 运行入口

| 入口          | 用途                         | 说明                         |
| ------------- | ---------------------------- | ---------------------------- |
| Kuroe.Console | 交互终端、内置助手与任务浏览 | 见[快速开始](../快速开始.md) |
| Kuroe.Cli     | 脚本与 CI 的一次性调用       | 见[快速开始](../快速开始.md) |

两个入口都支持 `-d` 与 `-h`，`-d` 省略时用启动进程的当前目录，`-h` 打印用法，参数错误以非零退出码结束。平台相关的运行环境：内置 git 工具与 dotnet 工具调用 PATH 中的同名程序；命令模板工具的输出按 UTF-8 解码。

## 工作目录

工作目录的 `.kuroe/` 下存放四个配置文件：

| 文件            | 内容                                                                                                                |
| --------------- | ------------------------------------------------------------------------------------------------------------------- |
| `settings.json` | 偏好设置，见[设置](设置.md)                                                                                         |
| `catalog.json`  | 提供商、模型及其凭据，含明文凭据，不要提交                                                                          |
| `flows.json`    | 任务流程模板，见[流程定义](../reference/流程定义.md)；命令执行节点含命令执行声明，来源不可信的工作目录不要直接运行  |
| `tools.json`    | 命令模板工具，见[工具配置](../reference/工具配置.md#命令模板工具)；含命令执行声明，来源不可信的工作目录不要直接运行 |

两个入口的命令里的文件参数相对该工作目录解析，与启动时的进程当前目录无关。

### 任务目录

`.kuroe_tasks/` 下是用户任务的工作目录，两个入口提交任务时建立，名字为 `任务键-流程-标题`，例如 `0199a7f2c3d54e8b9a1f2c3d4e5f6a7b-审阅-修复登录超时`。

- 任务键是提交时生成的 32 位十六进制唯一标识，不需要按已有目录续号，多个入口可以并行提交。
- 界面与错误消息显示键的末尾 8 位，完整键用于目录名与任务查询。
- 流程与标题在创建时取一次；流程段不含连字符，标题段可以含；非法字符与控制字符替换为下划线，流程段截到 20 字符，标题段截到 40 字符。

任务目录即流程开始输入 `TASK_WORK_PATH` 的值，工作区根目录即 `WORKSPACE_PATH` 的值。流程在 `HostStartInputs` 里把这两个开始端口绑定到对应宿主输入，开始端口声明为常量端口，Kuroe 在提交时给值，不需要手工填写。提交输入也可以声明为常量端口，值只在任务启动时给一次，节点用 `Static` 读取。容器把静态输入经 `In` 逐层转发，节点用 `Static` 绑定取用。文件与命令节点的 `Path` 与 `Directory` 用 `Variables` 把路径变量映射到静态 `Text` 输入端口，`root` 变量作为相对路径的基准，解析结果必须落在工作区根目录内。把 `TASK_WORK_PATH` 转发到节点并绑定到静态输入端口，把 `Path` 写成 `{root}/...` 即可让相对路径落在本次任务目录下。Llm 节点的工具用 `ToolPorts` 把路径变量映射到输入端口，导入流程时要求完整映射；把 `TASK_WORK_PATH` 映射到工具的 `root` 变量即可让工具使用本次任务目录。静态输入没有 `Static` 绑定且没有默认值时导入流程报错，执行时只读取静态输入值。

### 任务检查点

`.kuroe_tasks/.checkpoints/` 存任务检查点与租约。每个任务一个 `<任务键>.json`，写入经临时文件替换，任务走完、状态动作与退出时更新；`<任务键>.lock` 是独占租约，进程退出时由系统释放，同一任务同一时刻只由一个进程接管。

Console 启动时加载全部检查点，未完成的任务以暂停状态出现，恢复后继续推进；无法读取的文件逐个报告且不阻止其他任务。CLI 不写检查点，`run` 的任务状态不跨进程保留。

任务状态的生命周期按入口不同：Console 的任务由「任务」菜单管理并在退出后保留，未完成任务下次启动以暂停状态恢复，见[操作指南](../console/操作指南.md)；CLI 的 `run` 只在提交进程内推进，不写检查点，进程退出后任务状态消失，目录保留，见[命令行接口](../cli/命令行接口.md#run)。

## 产物目录

产物目录的 `source/` 下是随产物导出的仓库源码与文档，保留仓库相对路径，生成物与 `.docs` 参考资料不入内。该目录只由 Kuroe.Console 的 `source` 工具组读取，见[内置助手](../console/内置助手.md)。Kuroe.Cli 不读取该目录。
