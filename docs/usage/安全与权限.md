# 安全与权限

Kuroe 不提供系统级沙箱。进程权限、能力边界、路径约束与人工停驻各自成立，任一层的限制都不替代其他层。需要系统级隔离时由运行环境提供。

## 运行权限

Kuroe 以启动账户的身份运行，进程拥有该账户的全部能力：启动程序、安装依赖、构建、运行测试、启动服务、读写文件、访问网络、读取环境变量与宿主凭据。执行期不逐次请求审批，也不拦截操作。

工具白名单、路径校验与人工停驻只决定模型能选择什么、实参能落到哪里、动作何时继续，不改变进程权限。命令或项目代码开始执行后，启动时的实参限制与工作区边界不再约束程序的行为。

## 能力边界

任务可用的能力由流程声明与模型工具白名单共同确定。白名单只约束模型能选择什么，不约束流程本身：流程里声明的命令与文件写入动作在任务启动后直接具备执行能力。未放行的能力不会出现在模型面前，已放行的能力由模型自行决定何时使用。能力在任务启动时确定，任务运行期间不会扩大。

内置助手只具备只读能力，不含写入、仓库改动与命令执行，见[内置助手](../console/内置助手.md)。

工具与节点的声明规则见[工具配置](../reference/工具配置.md)与[节点](../reference/nodes/index.md)。

## 路径约束

模型给出的路径实参在调用前解析，解析结果必须落在工作区根内。越界、不可解析、空字符串与空白都拒绝，拒绝时不启动进程。

面向模型的工具比流程声明更严：模型可用的文件工具还拒绝配置目录与版本库元数据，流程里声明的文件与命令动作只受工作区边界约束。命令的执行位置受工作区约束，程序与参数本身不受路径校验。

校验按字符串解析与归一，不解析符号链接、目录联接点与硬链接，工作区内指向外部的链接不被拦截。路径约束防越界实参，不是文件系统隔离。

规则见[文件工具](../reference/tools/file.md)与[流程定义](../reference/流程定义.md#路径与任务目录)。

## 人工停驻

审批是流程安排的一次停驻，不是工具级审批。输入齐备后节点停在待批准，外部批准后放行下游。批准的对象是节点，不是某次工具调用或命令参数。没有放置停驻的流程不会因工具调用停下。等待人工内容的节点同样只表达停驻，空内容不构成输入。

人工停驻只在交互入口提供，并一次放行任务内全部待批准节点，不能按节点挑选。需要逐个确认时，应拆分任务或流程。非交互入口不读取输入，也不提供批准与回答，含停驻的流程不可运行。

停驻只能阻止尚未发生的动作。已执行的命令、已写入的文件与已发出的请求不能由批准撤销。需要人工确认的写入或命令应放在停驻下游，让停驻发生在动作之前。

规则见[审批](../reference/nodes/approval.md)、[输入](../reference/nodes/input.md)、[操作指南](../console/操作指南.md#任务概览)与[命令行接口](../cli/命令行接口.md#流程支持范围)。

## 命令风险

命令以参数列表启动，不经 shell 解释，参数中的空格、引号与重定向符不会交给 shell 处理。启动方式不构成安全边界：模型参数一旦进入程序自行启动的 shell，就会被 shell 解释。不要把模型参数嵌入 shell 命令串，否则等同于把任意命令执行能力交给模型。

仓库操作可以改动工作树、暂存区与分支，相关钩子可能执行仓库内脚本。构建、测试、运行与发布类命令会执行项目代码、构建任务与测试运行器。命令的执行位置只决定启动目录，不限制程序访问的资源。

## 凭据与数据

凭据与模型接入信息保存在工作区配置中，凭据是明文，不要提交。Kuroe 不把凭据放入模型请求，查询接口只报告凭据是否已设置，导出的配置不含凭据原文。交互入口按掩码读取凭据，非交互入口可由环境变量提供凭据，写在命令行会进入 shell 历史。

发给模型的请求包含任务输入、读到的文件内容、工具输出与对话历史。状态查询可以读取任务输入与过程记录，这些内容同样进入请求。端点与凭据来自工作区配置，来源不可信的配置不要导入。

本地任务状态包含任务输入、过程记录、工具参数与输出、模型回复、执行恢复数据与流程快照，属于敏感数据，需要与工作目录一起保护。

见[模型接入](模型接入.md)与[安装与运行](安装与运行.md#任务存档)。

## 输入可信性

节点库、流程与工具配置包含可执行声明。工作区来源不可信时不要直接运行 Kuroe，也不要直接提交其中的节点库、流程与工具配置。采纳外部节点、流程或工具前，检查程序、参数、执行位置、写入路径与能力范围。

模型读到的文件内容、工具输出与对话输入都按不可信输入处理。提示注入不能越过能力边界与路径约束，但可以诱导模型使用已经放行的写入、仓库改动、构建与命令能力。收窄放行范围是收窄影响的主要手段。

见[流程定义](../reference/流程定义.md)与[工具配置](../reference/工具配置.md)。
