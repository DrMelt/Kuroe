# 模型接入

## 提供商与模型

提供商与模型保存在工作目录 `.kuroe/` 的 `catalog.json`，含明文凭据，不要提交。

- 提供商是模型的宿主，有名字、端点与凭据。
- 模型注册到提供商名下，由本地模型名引用。

每条模型有两个名字：

- 本地模型名：目录内的唯一名，`Runtime:Model` 与流程里 `MODEL_NAME` 的取值都是它。
- 提供商模型名：请求提供商时实际发送的模型名。

同一提供商模型可以注册到多个提供商下，只要各条记录的本地模型名不同。注册时提供商模型名可以省略，省略时取本地模型名。`Runtime:Model` 选中的模型与流程里固定的模型名都必须是已注册的本地模型名。两个入口的模型目录操作作用一致，完整菜单见[操作指南](../console/操作指南.md)，完整命令见[命令行接口](../cli/命令行接口.md)。

目录文件中的模型条目以 `modelName` 保存本地模型名，以 `providerModelName` 保存提供商模型名，`providerName` 是归属的提供商。旧文件没有 `providerModelName` 时按 `modelName` 读取。`contextLength` 表示模型上下文窗口，读取、导入与导出都保留原值，两个入口不提供设置。

## 模型来源

执行节点使用的模型只来自静态输入端口 `MODEL_NAME`。标准写法是在流程里声明一个常量开始端口，在 `.kuroe/hostStartInputs.json` 里把它绑定到宿主输入 `MODEL`，表的结构见[宿主开始输入](../reference/宿主开始输入.md)。

`Runtime:Model` 的值在任务启动时写入流程，节点静态输入 `MODEL_NAME` 是实际使用的本地模型名。开始端口名与执行节点的输入端口名不必相同，执行节点用 `Bindings` 取开始的 `模型` 端口。需要在流程里固定模型时，把常量开始端口的 `Value` 写成模型名，该端口不进宿主开始输入表。值不是已注册的本地模型名时提交任务与启动执行时报错。静态输入的完整来源见[流程定义](../reference/流程定义.md#静态输入与常量输出)。

任务是模型的作用边界，任务启动后模型不再变化。`Runtime:Model` 的切换影响之后提交的任务。内置对话的模型切换行为见[内置助手](../console/内置助手.md)。执行记录的请求次数、token 用量与上下文见[任务与执行](任务与执行.md#用量)。
