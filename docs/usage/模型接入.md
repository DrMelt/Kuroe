# 模型接入

## 提供商与模型

提供商与模型的接入目录由 [ApiHub](https://github.com/DrMelt/ApiHub) 提供，保存在工作目录 `.kuroe/` 的 `catalog.json`，含明文凭据，不要提交。

- 提供商是模型的宿主，有名字、端点与凭据。
- 模型注册到提供商名下，由名字引用。

模型目录中的名称是本地命名，注册时自行取名，`Runtime:Model` 与模型选择的 `Model` 字段填的都是它；这个名字与模型实际使用的名字无关。

节点引用的模型名、`Runtime:Model` 选中的模型都必须是目录里已注册的模型名。

两个入口的模型目录命令作用一致，语法不同：

| 操作 | Kuroe.Console | Kuroe.Cli |
| --- | --- | --- |
| 注册提供商 | `/provider add <名> <端点> <凭据>` | `provider add <名> <端点> [凭据]` |
| 注册模型 | `/model add <模型> <提供商>` | `model add <模型> <提供商>` |
| 选择模型 | `/model <模型>` | `model use <模型>` |

完整命令见[命令参考](../console/命令参考.md)与[命令行接口](../cli/命令行接口.md)。

## 模型选择

模型选择有三处：

| 位置                    | 含义                               |
| ----------------------- | ---------------------------------- |
| `Runtime:Model`         | 当前选中的模型，由模型选择命令维护 |
| 流程里的模型选择        | 装配层按模型选择名引用的 `Models` 项   |
| 模型选择的 `Model` 字段 | 执行节点实际使用的模型名           |

模型选择名只出现在流程装配层：节点库定义不引用模型，节点组内执行节点的模型由引用处在装配时从外部输入。执行节点解析模型时用引用的模型选择的 `Model` 字段，未写时无法确定模型，提交任务与启动执行时报错。`Runtime:Model` 是运行时模型，流程里的运行时模型选择在执行时取用户当前选中的模型；内置对话的用法见[内置助手与专属工具](../console/内置助手与专属工具.md)。

## 目录迁移

导出目录，凭据替换为占位符，可脱离本机分发；导入目录为合并导入，文件参数相对工作目录解析。命令见[命令参考](../console/命令参考.md)与[命令行接口](../cli/命令行接口.md)。
