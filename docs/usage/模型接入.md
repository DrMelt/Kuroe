# 模型接入

## 提供商与模型

提供商与模型的接入目录由 [ApiHub](https://github.com/DrMelt/ApiHub) 提供，保存在工作目录 `.kuroe/` 的 `catalog.json`，含明文凭据，不要提交。

- 提供商是模型的宿主，有名字、端点与凭据，`/provider add <名> <端点> <凭据>` 注册。
- 模型注册到提供商名下，`/model add <模型> <提供商>` 注册，由名字引用。

模型目录中的名称是本地命名，注册时自行取名，`Runtime:Model` 与模型选择的 `Model` 字段填的都是它；这个名字与模型实际使用的名字无关。

节点引用的模型名、`Runtime:Model` 选中的模型都必须是目录里已注册的模型名。命令见[命令参考](命令参考.md)的模型目录部分。

## 模型选择

模型选择有三处：

| 位置                    | 含义                               |
| ----------------------- | ---------------------------------- |
| `Runtime:Model`         | 前台对话使用的模型，`/model` 维护  |
| 流程里的模型选择        | 装配层按模型选择名引用的 `Models` 项   |
| 模型选择的 `Model` 字段 | 执行节点实际使用的模型名           |

模型选择名只出现在流程装配层：节点库定义不引用模型，节点组内执行节点的模型由引用处在装配时从外部输入。执行节点解析模型时用引用的模型选择的 `Model` 字段，未写时无法确定模型，提交任务与启动 run 时报错。`Runtime:Model` 只供前台对话使用，不参与流程节点。

切换 `Runtime:Model` 会使旧上下文不再适用，会话按模型重建；凭据与端点变化不影响历史。

## 目录迁移

`/catalog export <文件>` 导出目录，凭据替换为占位符，可脱离本机分发；`/catalog import <文件>` 合并导入，文件参数相对工作目录解析。
