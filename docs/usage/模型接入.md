# 模型接入

## 提供商与模型

提供商与模型的接入目录保存在工作目录 `.kuroe/` 的 `catalog.json`，含明文凭据，不要提交。

- 提供商是模型的宿主，有名字、端点与凭据。
- 模型注册到提供商名下，由名字引用。

模型目录中的名称是本地命名，注册时自行取名，`Runtime:Model` 的值与流程里 `MODEL` 输入的取值都是它；这个名字与模型实际使用的名字无关。

`Runtime:Model` 选中的模型与流程里固定的模型名都必须是目录里已注册的模型名。

两个入口的模型目录操作作用一致，操作方式不同：

| 操作       | Kuroe.Console                        | Kuroe.Cli                         |
| ---------- | ------------------------------------ | --------------------------------- |
| 注册提供商 | 「模型与提供商」菜单的「添加提供商」 | `provider add <名> <端点> [凭据]` |
| 注册模型   | 「模型与提供商」菜单的「注册模型」   | `model add <模型> <提供商>`       |
| 选择模型   | 「模型与提供商」菜单的「选择模型」   | `model use <模型>`                |

完整菜单见[操作指南](../console/操作指南.md)，完整命令见[命令行接口](../cli/命令行接口.md)。

## 模型来源

执行节点使用的模型只来自静态输入端口 `MODEL_NAME`。标准写法是流程在开始端口声明常量端口 `MODEL_NAME`，通过 `HostStartInputs` 绑定宿主输入 `MODEL`：

```json
"Start": { "Outputs": [
  { "Name": "目标", "Type": "Text" },
  { "Name": "MODEL_NAME", "Type": "Text", "Constant": true }
] },
"HostStartInputs": { "MODEL_NAME": "MODEL" }
```

| 位置                         | 含义                                                     |
| ---------------------------- | -------------------------------------------------------- |
| `Runtime:Model`              | 当前选中的模型，任务启动时写入流程                       |
| 节点静态输入 `MODEL_NAME`    | 执行节点实际使用的模型值                                 |
| 常量开始端口的 `Value`       | 流程固定模型时的模型名，此时不绑定 `MODEL`               |

模型通过静态输入传递，不写进 `From` 上游接线。Llm 执行契约声明模型输入 `MODEL_NAME`，流程把该输入配置为静态端口，并在节点或引用处写 `Static`，容器实例用 `In` 把模型传给成员。静态来源是开始端口 `Value`、宿主输入、任意常量输出的 `Value` 或对静态输入的引用。容器静态输入只负责把外层来源转发给成员，本身不是新的值终点。

执行节点从静态输入端口 `MODEL_NAME` 取模型值。开始端口的固定值直接使用，绑定到宿主输入的端口取任务启动时给出的值；未绑定时导入流程报错，值不是已注册模型名时提交任务与启动执行时报错。

任务是模型的作用边界：任务启动后模型不再变化。`Runtime:Model` 的切换影响之后提交的任务；内置对话在模型变化后的下一轮重建任务。需要用同一批任务固定模型时，把常量开始端口的 `Value` 写成模型名，不绑定 `MODEL`。内置对话的用法见[内置助手](../console/内置助手.md)。
