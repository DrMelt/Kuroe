# 模型接入

## 提供商与模型

提供商与模型保存在工作目录 `.kuroe/` 的 `catalog.json`，含明文凭据，不要提交。

- 提供商是模型的宿主，有名字、端点与凭据。
- 模型注册到提供商名下，由名字引用。

模型名是本地命名，注册时自行取名，`Runtime:Model` 与流程里 `MODEL_NAME` 的取值都是它，与提供商实际使用的模型名无关。`Runtime:Model` 选中的模型与流程里固定的模型名都必须是已注册的模型名。两个入口的模型目录操作作用一致，完整菜单见[操作指南](../console/操作指南.md)，完整命令见[命令行接口](../cli/命令行接口.md)。

## 模型来源

执行节点使用的模型只来自静态输入端口 `MODEL_NAME`。标准写法是在开始端口声明常量端口，通过 `HostStartInputs` 绑定宿主输入 `MODEL`：

```json
"Start": { "Outputs": [
  { "Name": "目标", "Type": "Text", "Mode": "Constant" },
  { "Name": "MODEL_NAME", "Type": "Text", "Mode": "Constant" }
] },
"HostStartInputs": { "MODEL_NAME": "MODEL" }
```

`Runtime:Model` 的值在任务启动时写入流程，节点静态输入 `MODEL_NAME` 是实际使用的模型。需要在流程里固定模型时，把常量开始端口的 `Value` 写成模型名，不绑定 `MODEL`。值不是已注册模型名时提交任务与启动执行时报错。静态输入的完整来源见[流程定义](../reference/流程定义.md#静态输入与常量输出)。

任务是模型的作用边界，任务启动后模型不再变化。`Runtime:Model` 的切换影响之后提交的任务。内置对话的模型切换行为见[内置助手](../console/内置助手.md)。
