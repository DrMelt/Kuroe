# 入口与分工

Kuroe 有两个可执行入口，共用同一工作目录与 `.kuroe/` 配置，运行方式与能力不同。

| 维度 | Kuroe.Console | Kuroe.Cli |
| --- | --- | --- |
| 用途 | 交互终端、内置助手与任务浏览 | 脚本与 CI 中的一次性调用 |
| 输入 | 键盘菜单与文本输入；「Kuroe 助手」进入常驻对话任务 | 命令行参数；不读取 stdin |
| 进程生命周期 | 进程内保留任务，退出时取消 | 每次调用完成一个操作后退出，不保留进程内状态 |
| 内置助手 | 有 | 无 |
| 注册的节点类型 | `Container`、`Llm`、`FileRead`、`FileWrite`、`Command`、`Input`、`Approval` | `Container`、`Llm`、`FileRead`、`FileWrite`、`Command` |
| 任务操作 | 提交、浏览、批准、返工、回答与取消 | `run` 提交并推进，进程退出即取消 |
| 流程库 | 要求整体可编译，`flow add` 严格导入 | 容忍不可用流程，`flow add` 只导入可编译流程 |
| 工具面 | 含 `source` 工具组与 `KuroeInfo/ListTools` | 不含 `source` 工具组与 `KuroeInfo/ListTools` |
| 产物 `source/` | 按产物位置装配并读取 | 不读取 |
| 配置 | 读写工作目录的 `.kuroe/` | 读写工作目录的 `.kuroe/` |

需要键盘交互、内置助手、等待输入与审批、任务浏览时用 Kuroe.Console。需要脚本化、由进程退出给出结果时用 Kuroe.Cli。CLI 提交的任务只存在于提交它的进程，Console 的任务列表不包含这些任务。

操作方式不同：Console 使用菜单，见[交互操作](../console/交互操作.md)；CLI 使用子命令，见[命令行接口](../cli/命令行接口.md)。

两个入口共用[安装与运行](安装与运行.md)描述的产物与工作目录，共用[模型接入](模型接入.md)、[设置与目录管理](设置与目录管理.md)、[流程文件与节点库](流程文件与节点库.md)、[节点定义](节点定义.md)、[流程装配](流程装配.md)与[工具扩展](工具扩展.md)描述的机制。
