# 节点定义

节点定义是节点库定义的形状，也是流程内联节点的形状；库定义只声明能力，模型与接线由装配层输入。文件装载与节点库合并见[流程文件与节点库](流程文件与节点库.md)，引用、绑定与接线见[流程装配](流程装配.md)。

## 节点

节点类型名由程序定义，文件必须显式写 `Kind`，取值 `Container`、`Llm`、`FileRead`、`FileWrite`、`Input`、`Approval`。`Container` 由引擎提供，其余由装配处注册。类型名对应程序里提供的节点类型，类型决定节点允许的字段与产出的来源：容器组织成员并限定作用域，Llm 节点由模型执行，文件读取节点读取工作目录内文件作为产出，文件写入节点把输入端内容写入工作目录内文件，输入节点等用户回答，审批节点等用户批准。节点的字段分两层：结构字段由引擎解释，类型专属参数由节点类型解释，写了类型不承认的字段即报错。结构字段名不区分大小写，类型参数名按原文精确匹配。两个入口注册的节点类型不同，见[入口与分工](入口与分工.md)。共用结构字段：

| 字段      | 类型                             | 含义                                                           | 适用       |
| --------- | -------------------------------- | -------------------------------------------------------------- | ---------- |
| `Name`    | string                           | 节点名，定义条目的名字，同一容器内唯一且不能为空，不能含 `@` 与 `/`；库定义的名字还须库内唯一 | 定义条目   |
| `Label`   | string                           | 节点标签，被使用的节点在图里的标识段，同一容器内唯一且不能为空，不能含 `@` 与 `/` | 引用条目   |
| `Kind`    | `Container`/`Llm`/`FileRead`/`FileWrite`/`Input`/`Approval` | 节点类型名，必填；引用节点不写，类型名由被引用的库定义决定 | 非引用节点 |
| `MaxExecutions` | int                                | 执行次数上限：执行节点与文件节点为自身配置，容器为组内执行节点的统一默认   | 全部         |

`Nodes` 里的条目分两种：没有 `Use` 的是节点定义，写 `Name`；有 `Use` 的是被使用的节点，必须写 `Label`。定义条目的标签取节点名的文本，节点在图里统一以标签标识，引用写 `来源@端口`，任务命令里的 `@路径` 由标签段拼成。

引用节点的 `Use`、`In`、`Models` 字段与接线见[流程装配](流程装配.md#引用与装配)。

## 执行节点

执行节点是唯一派发模型执行的节点，装配层内联定义由以下结构字段描述。节点库执行定义是复用模板，声明结构字段与类型参数，不声明模型与接线；节点库容器定义内的执行成员用 `Model` 写容器声明的槽位名，槽位由引用节点组处的 `Models` 绑定：

| 字段       | 类型                  | 含义 |
| ---------- | --------------------- | --- |
| `Model`    | string                | 节点组内：容器定义的槽位名；装配层内联与引用执行节点写模型选择名，见[流程装配](流程装配.md#模型选择) |
| `Inputs`   | array                 | 节点的输入端口表：执行节点写 `Name` 与可选 `Type`、`Description`、`Default`，容器定义写 `Name` 与可选 `Type`、`Description`，不写 `Default`；`Type` 取 `Text`、`Context` 或 `Signal`，未写按 `Text`；`Default` 只用于派发执行节点的 `Text` 输入端口；输入节点的输入端口取 `Text` 或 `Signal`；文件读取节点只取 `Signal`，文件写入节点恰好一个 `Text`，其余取 `Signal`；绑定一律经 `From`，见[输入端口](#输入端口) |
| `Outputs`  | array                 | 节点的输出端口表：执行节点、输入节点与文件节点写 `Name` 与 `Type`，`Type` 必填；容器写 `Name` 与 `Ref`，见[输出端口与系统指令](#输出端口与系统指令) |
| `From`     | array                 | 上游启动组：数组元素是一个组，组内是输入端口名到来源端口引用的映射，如 `{ "计划": "规划@计划" }`，值写 `来源@端口` 或 `@端口`；组间任一齐备即启动，组内全部齐备，组间来源端口不重复，见[流程装配](流程装配.md#上游接线) |
| `Validate` | object                | 输出校验：收口时校验模型产出，不通过则节点阻塞待返工，见[流程装配](流程装配.md#输出校验) |
| `MaxExecutions` | int                     | 同一节点的最高执行次数，达到后不再启动新执行；文件节点达到后不再重新读写；未写时继承最近容器的统一配置，最后默认 100 |

节点收口即交回声明的端口输出，Llm 类型的工具面按输出端口类型放行契约工具：

- 声明 `Text` 端口：模型经 `SubmitPortValues` 交回端口名到文本的对象，内容交给下游。
- 声明 `Signal` 端口：模型经 `SubmitPortValues` 只交回端口名，取值不承载内容，只以本执行的发布版本驱动下游。
- 声明 `Context` 端口：透出来源执行的输入取值，不需要模型交回。

每个执行节点都另外附上两个执行状态工具：`GetStatus` 查看本轮执行契约状态，报出节点与轮次、节点状态、尚缺的输出端口与已上报的无法完成原因；`ReportCannotComplete` 上报本轮无法完成并给出 `reason`。完成与否由引擎判定，模型不需要声明交付完毕；上报无法完成的执行直接停在阻塞待返工，不再发补交要求。

执行开始时，需交回的端口随契约工具的说明给出，工具说明随工具的调用面进入请求。契约工具的回执附上当前仍缺的产出。

声明了 `Text` 端口而模型没有交回时，执行收口前先向模型补发一条补交要求，缺项与要调用的契约工具写在其中，同一执行内最多补发两次；两次之后仍缺才停在阻塞待返工。

执行节点库定义不写接线，`From` 由引用处注入；装配层内联执行节点与引用执行节点直接写 `From`。

## 类型参数

类型专属声明与结构字段同级写在节点对象里，键由节点类型解释，写了类型不承认的键即报错；引用节点不声明类型参数。参数名按原文精确匹配，写错大小写即按未知字段报出。

| 参数 | 类型 | 归属 | 含义 |
| --- | --- | --- | --- |
| `Prompt` | string | Llm | 对本次执行的额外要求，构成本轮指令；开始输入经开始入口的接线进入输入取值 |
| `Tools` | string[] | Llm | 能力工具白名单，按工具路径前缀匹配，写上级路径即放行整棵子树；路径按原文大小写敏感比较，段只能写字母、数字、下划线与连字符，非法路径在装配时报错；省略或空时不给出任何能力工具 |
| `SystemPrompt` | string[] | Llm | 恒定系统指令块，按序拼接后整段作为请求的系统指令，块不能为空 |
| `Question` | string | Input、Approval | 等待型节点的提示文本：输入节点等待回答、审批节点等待批准时呈现 |
| `Path` | string | FileRead、FileWrite | 相对工作目录的文件路径：读取节点给出读取文件，写入节点给出写入文件；装载时解析，必须落在工作目录内 |
| `MaxChars` | int | FileRead、FileWrite | 单次读写的字符上限，0 表示不限制；读取未写时 8000，写入未写时不限制 |

类型是扩展点：一个节点类型由描述实例承载，描述给出类型名、静态形状、类型规则、运行期对象与模型侧内容；类型专属声明封在描述里，引擎只透传不解释。类型描述实现 `INodeTypeDescription`，契约位于 `Kuroe.Flow.Shared`，注册表接口是 `INodeTypeDescriptionRegistry`，默认实现是 `Kuroe.Flow.Compiler` 的 `NodeTypeDescriptionRegistry`。参数段的字段归属与值形状由构造层按描述读取，承载格式只负责把文本值转成中立描述值。派发执行的类型与组织成员的容器，其运行期对象由引擎按形状建立。

## 输出端口与系统指令

`Outputs` 给节点声明输出端口。执行节点、输入节点与文件节点条目写 `Name` 与 `Type`，`Type` 必填，取 `Text`、`Context` 或 `Signal`；容器条目写 `Name` 与 `Ref`，见[容器定义](#容器定义)。派发执行的节点由模型经 `SubmitPortValues` 交回 `Text` 与 `Signal` 端口，「端口名到文本」的 JSON 对象必须与声明一一对应，`Signal` 端口只认端口名、取值不承载内容，未交回时先在同一执行内追问补交，追问两次后仍缺才停在阻塞待返工；输入节点至多一个输出端口，回答写入该端口；文件读取节点把读取内容写入唯一的 `Text` 输出端口，文件写入节点的 `Text` 输出给出写入内容、`Signal` 输出只表示写入完成。下游用 `From: [{ "输入名": "来源@端口" }]` 精确消费指定端口。开始端口的条目可另写 `Value` 声明固定输出值，见[开始入口](流程文件与节点库.md#开始入口)。

Llm 参数的 `SystemPrompt` 声明系统指令块：按序拼接后整段作为请求的系统指令，与动态内容（输入取值、本轮指令）分离。声明块应是跨轮不变的约束，不要拼入开始输入、轮次等动态值；需交回的端口由契约工具的说明给出，不占声明块。系统指令不随 `Context` 端口透传，见[端口类型](#端口类型)。

## 端口类型

端口类型随声明落定，决定产出形态、取用方式与校验。输入与输出端口都取 `Text`、`Context`、`Signal`；审批节点对外的端口由自身输入端口派生：

| 类型 | 方向 | 含义 |
| --- | --- | --- |
| `Text` | 输入与输出 | 输出：模型交回命名段，内容交给下游。输入：来源取值按序进入目标执行的输入，未连接时取声明的默认值 |
| `Context` | 输入与输出 | 输出：来源执行输入侧取到的内容，逐条保留出处。输入：来源取值置于目标输入最前，与系统指令构成稳定前缀 |
| `Signal` | 输入与输出 | 不承载内容，输出仍要交回端口名，只以发布版本驱动下游；输入不消费产出，只在组内以来源的新版本驱动启动 |

端口条目用对象声明，名字自定义：

```json
"Inputs": [
  { "Name": "计划", "Description": "待实施的内容。" },
  { "Name": "格式", "Default": "按条目输出。" },
  { "Name": "背景", "Type": "Context" }
],
"Outputs": [
  { "Name": "结论", "Type": "Text" },
  { "Name": "上下文", "Type": "Context" }
]
```

`Context` 输出端口至多声明一个，派发执行的节点与容器都可声明，下游用 `From: [{ "上下文": "来源@上下文" }]` 消费。`SubmitPortValues` 覆盖 `Text` 与 `Signal` 输出端口：`Text` 交回内容，`Signal` 只需给出端口名；`Context` 输出端口由来源透传，不需要模型交回。

## 输入端口

输入端口声明目标侧的输入名，执行节点与容器定义共用：容器定义声明的输入端口由引用处的 `In` 绑定，执行节点的由自身 `From` 绑定。`Inputs` 可省略，省略时 `From` 的连接键按 `Text` 类型处理；声明后 `From` 的每个组必须覆盖全部不带默认值的输入端口，连接键必须落在声明内。

派发执行的节点可以为 `Text` 输入端口声明 `Default`。`Default` 只在当前生效组没有连接该端口时进入执行输入，显式连接优先；默认值不产生依赖边，不参与齐备判定与版本驱动。默认值在连接取值之后按输入声明序追加。默认值不能是空白文本。容器定义、输入节点、审批节点、文件节点以及 `Context`、`Signal` 输入端口都不接受 `Default`。

`Type: Context` 的输入端口把来源取值置于输入最前，与系统指令构成稳定前缀。来源必须是非输入执行节点。内容恒定才命中前缀缓存：重复消费相同来源取值时前缀稳定，拼入每轮动态值由使用者自担。

`Type: Signal` 的输入端口不消费来源内容，以来源的新版本驱动该组启动；输入节点的输入端口取 `Text` 或 `Signal`，声明 `Signal` 表示该连接只作回边的驱动。

## 输入节点

`Kind: Input` 的节点不启动执行、不需要模型选择：依赖输入齐备后停在「待输入」，用户回答后回答即产出放行下游，下游按依赖边消费。回答经 `Outputs` 声明的端口写入，数据消费须带端口，至多声明一个；未被数据消费可省略声明。`Question` 给提示文本，未写时用通用提示。

`Kind: Input` 的节点不声明模型与执行配置，`Tools`、`Prompt`、`SystemPrompt`、`Context` 输入端口与 `Validate` 都会被装配校验拒绝；回答见[任务操作](../console/任务操作.md#等待输入)，多个待输入节点时必须指定节点路径。

## 审批节点

`Kind: Approval` 的节点不启动执行、不需要模型选择：`From` 任一组齐备即停在「待批准」，用户批准后按输入端口转发上游产出，任务继续推进；来源出了新版本时重新停在待批准。

`Inputs` 是审批节点对外的端口：声明什么就把对应的上游产出原样转发出去，下游用 `From: [{ "正文": "审阅@正文" }]` 消费。`Text` 输入转发为同名 `Text` 输出，`Context` 输入转发为同名 `Context` 输出，`Signal` 输入转发为同名 `Signal` 输出，只驱动下游启动、不承载内容。至少声明一个输入端口，`Context` 输入至多一个。

`Question` 给待批准时的提示文本，未写时用通用提示。审批节点只声明 `Name`、`Kind`、`Inputs`、`From` 与 `Question`，`Model`、`Tools`、`Prompt`、`Validate`、`Outputs`、`SystemPrompt`、`Models`、`In`、`Nodes` 与 `MaxExecutions` 都会被装配校验拒绝。

审批节点是流程里的一步，对来源产出整体放行。要在执行节点之前放行计划，用 `Signal` 输入接在计划来源上，执行节点同一组里同时取计划与审批节点：

```json
{ "Name": "审阅", "Kind": "Approval", "Question": "确认计划", "Inputs": [{ "Name": "计划", "Type": "Signal" }], "From": [{ "计划": "制定计划@计划" }] },
{ "Name": "分配执行", "Kind": "Llm", "Model": "执行者",
  "Inputs": [{ "Name": "任务" }, { "Name": "批准", "Type": "Signal" }],
  "From": [{ "任务": "制定计划@计划", "批准": "审阅@计划" }] }
```

要在多个下游之前各自放行，改为在每个下游前各接一个审批节点。

## 文件读取节点

`Kind: FileRead` 的节点不启动执行、不需要模型选择：`From` 任一组齐备且来源有新版本时读取 `Path` 指向的文件，内容写入唯一的输出端口，下游按端口消费。输入只取 `Signal` 作触发，至少声明一个；输出恰好声明一个 `Text` 端口。`Path` 在装载时按工作目录解析，缺失或越出工作目录即报错。

读取按 UTF-8 解码并识别 BOM。`MaxChars` 给出单次读取的字符上限，未写时为 8000，0 表示不限制；超出上限时截断并在末尾标记。下游执行取用该内容时按执行输入上限 2000 字符再次截断。文件不存在或读取失败时节点停在阻塞，原因写入过程记录；修复后选择返工重新读取。来源出新版本时重新读取。

```json
{ "Name": "读入", "Kind": "FileRead", "Path": "docs/需求.md", "MaxChars": 12000,
  "Inputs": [{ "Name": "触发", "Type": "Signal" }],
  "From": [{ "触发": "Start@目标" }],
  "Outputs": [{ "Name": "正文", "Type": "Text" }] }
```

## 文件写入节点

`Kind: FileWrite` 的节点不启动执行、不需要模型选择：`From` 任一组齐备且来源有新版本时把唯一的 `Text` 输入内容覆盖写入 `Path` 指向的文件，其余输入只能是 `Signal` 触发。输出端口可省略，也可声明一个：`Text` 端口给出写入内容，`Signal` 端口只表示写入完成。

写入按 UTF-8 无 BOM，父目录缺失时建立。`MaxChars` 给出单次写入的字符上限，未写或为 0 时不限制；超出上限时节点停在阻塞且不写入。文件写入失败时同样停在阻塞，原因写入过程记录，返工后重试。

```json
{ "Name": "写出", "Kind": "FileWrite", "Path": "out/结果.md",
  "Inputs": [{ "Name": "正文" }],
  "From": [{ "正文": "实施@结论" }] }
```

## 容器定义

容器组合执行节点并为子节点限定作用域，自身不执行、不启动执行，成员产出齐备时作汇合点。容器定义声明传入端口、输出端口与模型槽位，构成容器的封装边界：

| 字段      | 类型   | 含义 |
| --------- | ------ | --- |
| `Nodes`   | array  | 有序子节点，至少一个，整棵子树至少含一个执行节点 |
| `Models`  | array  | 模型槽位声明：成员用 `Model` 引用，引用处用 `Models` 绑定到流程模型选择，声明与使用必须一致 |
| `Inputs`  | array  | 传入端口条目，写 `Name` 与可选 `Type`、`Description`，不写 `Default`，成员用 `From: [{ "输入名": "@端口名" }]` 引用传入内容 |
| `Outputs` | array  | 命名输出端口条目，写 `Name` 与 `Ref`，`Ref` 必须写 `成员@端口` 精确取成员命名段 |

槽位声明只属于节点库容器定义，装配层内联容器不声明 `Models`；引用节点用 `Models` 写槽位名到本流程模型选择的绑定对象。

`Inputs` 声明传入端口：容器定义只声明端口条目，条目写 `Name` 与可选 `Type`、`Description`，不写 `Default`，成员经 `@端口名` 取用，引用处用 `In: { "端口名": "来源" }` 绑定当前流程内的实际来源，见[流程装配](流程装配.md#引用与装配)。装配层内联容器不声明 `Inputs`，输入端口声明只属于节点库容器定义。

`Outputs` 把内部成员产出透出为容器对外接口，可以声明在节点库容器定义与装配层内联容器上，引用节点不可声明。`Ref` 必须指向容器子树内的执行节点，写 `成员@端口` 取该成员声明的输出端口，类型取自被绑定的成员端口。下游执行节点用 `From: [{ "输入名": "容器标签@端口" }]` 精确消费，编译期解析为对绑定成员执行的依赖。

容器是封装边界，对外只暴露 `Outputs` 声明的端口；容器没有整份产出，一切对外内容都经声明的命名端口。

容器不可声明执行配置、`Question`、`From` 与 `In`，也不接受任何类型参数。容器没有门控，成员齐备后内容即对外放行；需要人工放行时在容器下游接一个审批节点。

容器可声明 `MaxExecutions` 作为组内执行节点的统一执行上限：组内执行节点未写自身 `MaxExecutions` 时生效，嵌套容器可覆盖外层容器的统一值，执行节点自身配置始终优先。

库里容器定义的自包含要求：成员 `From` 只能引用容器定义内部的节点，或 `@` 已声明的输入端口——容器作为整体可被多处引用而不依赖外部名字。

## 校验规则

启动时逐条校验，全部非法项一次给出。库定义与装载规则见[流程文件与节点库](流程文件与节点库.md#校验规则)，引用、展开与环的规则见[流程装配](流程装配.md#校验规则)：

- 定义条目写节点名，引用条目必须写标签；节点名与标签都不能为空、不能含 `@` 与 `/`、不能用保留的 `Start`；同一容器内的标识唯一，库定义名还须库内唯一。`@` 是端口引用的分隔符，`/` 是节点路径的分隔符。不同容器里的同标识节点合法，节点以从根到本节点的路径区分，引用按作用域解析。
- `Kind` 必填且取值必须是已注册的节点类型名：引擎内置 `Container`，装配处注册 `Llm`、`FileRead`、`FileWrite`、`Input` 与 `Approval`；类型名与声明内容必须一致：容器必须有子节点且不写执行配置，其余类型不得有子节点；输入节点、审批节点与文件节点不写模型选择与 `Validate`，文件节点可用 `MaxExecutions`。
- `MaxExecutions` 必须是正整数：执行节点为自身上限，容器为组内执行节点的统一默认，未写时继承最近容器的统一配置，最后默认 100。
- `Outputs` 条目必须是对象：执行节点与输入节点写 `Name` 与 `Type`，`Type` 必填且取 `Text`、`Context`、`Signal`；容器写 `Name` 与 `Ref`，端口名在容器内唯一；审批节点不声明 `Outputs`，对外端口由 `Inputs` 派生；输出端口名在同一节点内唯一；`Text` 与 `Signal` 端口声明后必须经 `SubmitPortValues` 交回全部端口，`Text` 交回内容、`Signal` 只交回端口名，下游 `From` 引用的端口必须存在，引用一律写 `来源@端口`；`Context` 输出端口至多一个，输入节点只声明 `Text` 端口且至多一个，文件读取节点只声明恰好一个 `Text` 输出端口，文件写入节点至多声明一个 `Text` 或 `Signal` 输出端口。
- `Inputs` 条目必须是对象，写 `Name` 与可选 `Type`、`Description`、`Default`；类型取 `Text`、`Context`、`Signal`，容器定义与执行节点同一份规则；`Default` 只用于派发执行节点的 `Text` 输入端口且不能为空，容器定义、输入节点、审批节点与文件节点不接受 `Default`；输入节点的输入端口取 `Text` 或 `Signal`；审批节点至少声明一个输入端口且 `Context` 输入至多一个；文件读取节点只声明 `Signal` 输入端口且至少一个，文件写入节点恰好声明一个 `Text` 输入端口，其余输入只能是 `Signal`；输入端口名在同一节点内唯一。
- `From` 的每个组必须覆盖节点声明的全部不带默认值的输入端口，连接键必须落在声明内，组内输入名唯一，组间来源端口不重复；未声明 `Inputs` 时连接键按 `Text` 类型处理。
- 容器输出端口：可声明在节点库容器定义与装配层内联容器上，引用节点不可声明；绑定值必须指向容器子树内的执行节点，写 `成员@端口`，该端口必须是目标成员声明的输出端口，类型取自该端口；输入节点与子容器不可作绑定目标。
- 节点库容器定义用 `Models` 声明模型槽位，成员 `Model` 必须写在声明内，声明的槽位必须被成员使用；引用节点组的 `Models` 绑定键必须与被引用定义的声明一致。
- 类型参数只由声明它的类型接受：`Prompt`、`Tools`、`SystemPrompt` 属于 Llm，`Question` 属于输入与审批，`Path` 与 `MaxChars` 属于文件读取与文件写入；其余字段名一律报错，引用节点不声明类型参数。参数名按原文精确匹配，写错大小写即按未知字段报出。`Tools` 条目按工具路径校验，段只能写字母、数字、下划线与连字符。`Path` 在装载时按工作目录解析，越出工作目录即报错。`MaxChars` 必须是非负整数，负数即报错。
- `Kind: Input` 的节点不启动执行，不需要模型选择，也不接受 `Tools`、`Prompt`、`SystemPrompt`、`Context` 输入端口与 `Validate`；`Kind: Approval` 的节点同样不启动执行，只接受 `Question`，对外端口取自身输入端口。
- `Kind: FileRead` 与 `Kind: FileWrite` 的节点不启动执行，不接受 `Tools`、`Prompt`、`SystemPrompt`、`Context` 输入端口与 `Validate`；读取节点只接受 `Signal` 触发与一个 `Text` 输出，写入节点恰好一个 `Text` 输入且最多一个输出。`MaxExecutions` 对文件节点生效，达到后不再重新读写。
