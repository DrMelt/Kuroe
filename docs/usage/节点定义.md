# 节点定义

节点定义是节点库定义的形状，也是流程内联节点的形状；库定义只声明能力，模型与接线由装配层输入。文件装载与节点库合并见[流程文件与节点库](流程文件与节点库.md)，引用、绑定与接线见[流程装配](流程装配.md)。

## 节点

节点类型由程序定义，文件必须显式写 `Kind`，取值 `Container`、`Executable`、`Input`。类型决定节点允许的字段与产出的来源：容器组织成员并限定作用域，执行节点由模型执行，输入节点等用户回答。三类节点共用基础字段：

| 字段      | 类型                             | 含义                                                           | 适用       |
| --------- | -------------------------------- | -------------------------------------------------------------- | ---------- |
| `Name`    | string                           | 节点名，流程/定义内唯一且不能为空                              | 全部       |
| `Kind`    | `Container`/`Executable`/`Input` | 节点类型，必填；引用节点不写，类型由被引用的库定义决定         | 非引用节点 |
| `Gate`    | `Auto`/`Review`                  | 产出后停在待批准；执行节点产出后、容器成员齐备后               | 全部       |
| `MaxRuns` | int                              | 执行次数上限：执行节点为自身配置，容器为组内执行节点的统一默认 | 全部       |

引用节点的 `Use`、`In`、`Models` 字段与接线见[流程装配](流程装配.md#引用与装配)。

## 执行节点

执行节点是唯一实际执行的节点，装配层内联定义由以下字段描述。节点库执行定义是复用模板，声明能力字段（工具、输出端口、模式、分支），不声明模型与接线；节点库容器定义内的执行成员用 `Model` 写容器声明的槽位名，槽位由引用节点组处的 `Models` 绑定：

| 字段       | 类型                  | 含义 |
| ---------- | --------------------- | --- |
| `Model`    | string                | 节点组内：容器定义的槽位名；装配层内联与引用执行节点写模型选择名，见[流程装配](流程装配.md#模型选择) |
| `Prompt`   | string                | 对执行单元的额外要求，构成本轮指令；任务目标经开始入口的接线进入上下文 |
| `Tools`    | string[]              | 能力工具白名单，按工具路径前缀匹配，写上级路径即放行整棵子树；路径按原文大小写敏感比较，非法路径在装配时报错；省略或空时不给出任何能力工具 |
| `Question` | string                | 输入节点的提示文本，等待用户回答时呈现 |
| `Outputs`  | array                 | 节点的输出端口表：执行节点与输入节点写 `Name` 与 `Kind`，`Kind` 必填；容器写 `Name` 与 `Ref`，见[输出端口与系统指令](#输出端口与系统指令) |
| `SystemPrompt` | string[] | 恒定系统指令块，置于系统指令最前，内容应是跨轮不变的约束；系统指令末尾由引擎附上本轮接口说明，见[输出端口与系统指令](#输出端口与系统指令) |
| `Mode`     | `Single`/`PerItem`    | 整节点一个 run，还是按拆分条目各启动一个 |
| `Branch`   | string                | 只处理拆分中归属该分支的条目，未写时处理全部条目 |
| `From`     | array                 | 上游接线条目：字符串条目必须写 `来源@端口` 或 `@端口`，对象条目带 `Node` 同样必须写来源引用、再加 `Or`、`Signal`、`Context` 键；`Or` 归入可选启动组，`Signal` 只作触发信号不进上下文，`Context` 把产出置于上下文最前，见[流程装配](流程装配.md#上游接线) |
| `Validate` | object                | 输出校验：收口时校验模型产出，不通过则节点阻塞待返工，见[流程装配](流程装配.md#输出校验) |
| `MaxRuns`  | int                   | 同一执行路径的最高执行次数，达到后不再启动新 run；整节点一条路径，按条目展开时每条目一条路径，未写时继承最近容器的统一配置，最后默认 100 |

节点收口即交回声明的端口输出，契约工具按端口种类自动附上：

- 声明 `Data` 端口：模型经 `SubmitPortValues` 交回端口名到文本的对象。
- 声明 `Items` 端口：模型经 `SubmitPlanItems` 交回条目拆分。
- 声明 `Context` 端口：透出装配上下文，不需要模型交回。

每个执行节点都另外附上 `SubmitStatus`：模型经它声明本轮状态，`status` 取 `completed` 交付完毕或 `blocked` 无法完成，后者必须给出 `reason`。声明 `blocked` 的 run 直接停在阻塞待返工，不再发补交要求。

run 开始时，系统指令里附一段本轮接口说明：本节点的输入端口与取用方式、需要交回的端口与对应契约工具、以及 `SubmitStatus` 的取值。契约工具的回执附上当前仍缺的产出与本轮状态。

声明了 `Data` 或 `Items` 端口而模型没有交回时，run 收口前先向模型补发一条补交要求，缺项与要调用的契约工具写在其中，同一 run 内最多补发两次；两次之后仍缺才停在阻塞待返工。

`Mode: PerItem` 的执行节点按条目展开，条目集来自其引用的声明 `Items` 端口的执行节点，见[流程装配](流程装配.md#依赖与展开)。

执行节点库定义不写接线，`From` 由引用处注入；装配层内联执行节点与引用执行节点直接写 `From`。

## 输出端口与系统指令

`Outputs` 给节点声明输出端口。执行节点与输入节点条目写 `Name` 与 `Kind`，`Kind` 必填，取 `Data`、`Items` 或 `Context`；容器条目写 `Name` 与 `Ref`，见[容器定义](#容器定义)。`Data` 端口由模型经 `SubmitPortValues` 交回「端口名到文本」的 JSON 对象，端口必须与声明一一对应，未交回时先在同一 run 内追问补交，追问两次后仍缺才停在阻塞待返工；按条目展开时逐实例交回各自端口值，输入节点至多一个、回答写入该端口。下游用 `From: ["来源@端口"]` 精确消费指定端口。开始端口的条目可另写 `Value` 声明固定输出值，见[开始入口](流程文件与节点库.md#开始入口)。

`SystemPrompt` 声明系统指令块：装配时按序拼接，置于系统指令最前，随后接引擎生成的本轮接口说明，与动态内容（对话、上游产出、本轮指令）分离。声明块应是跨轮不变的约束，不要拼入任务目标、轮次等动态值；运行中变化的输入端口与需交回的产出由接口说明给出，不占声明块。系统指令不随 `Context` 帧透传，见[端口种类](#端口种类)。

## 端口种类

端口的种类随声明落定，决定消费方式与校验：

| 种类 | 方向 | 消费方式 |
| --- | --- | --- |
| `Data` | 输出 | 模型交回命名段，按边注入目标上下文 |
| `Items` | 输出 | 声明 `Items` 端口的执行节点的拆分支票，只驱动按条目展开，不注入文本 |
| `Context` | 输出 | 来源最近成功收口放行 run 的装配上下文，对话、上游产出、条目与指令逐条保留角色与出处，指令单列，上游系统指令只在它自己的请求通道里，不随帧透传 |

端口条目用对象声明，名字自定义：

```json
"Outputs": [
  { "Name": "结论", "Kind": "Data" },
  { "Name": "拆解", "Kind": "Items" },
  { "Name": "上下文", "Kind": "Context" }
]
```

`Items` 至多声明一个，按条目展开的目标用 `From: ["规划@拆解"]` 消费。`Context` 至多声明一个，任何非输入执行节点与容器都可声明，下游用 `From: ["来源@上下文"]` 消费。`SubmitPortValues` 只接受 `Data` 端口，`Items` 与 `Context` 端口不需要模型交回。

执行节点的上下文前缀段由来源的 `Context` 种类端口或 `From` 条目的 `Context` 标记承载，见[流程装配](流程装配.md#上游接线)。内容恒定才命中前缀缓存：重复消费相同来源产出时前缀稳定，拼入每轮动态值由使用者自担。

## 输入节点

`Kind: Input` 的节点不启动 run、不需要模型选择：依赖输入齐备后停在「待输入」，用户回答后回答即产出放行下游，下游按依赖边消费。回答经 `Outputs` 声明的端口写入，数据消费须带端口，至多声明一个；未被数据消费可省略声明。`Question` 给提示文本，未写时用通用提示。

`Kind: Input` 的节点不声明模型与执行配置，`Tools`、`Prompt`、`Mode`、`Branch`、可选启动组、触发信号、上下文输入、`Validate` 与 `Gate: Review` 都会被装配校验拒绝；回答见[任务操作](任务操作.md#等待输入)，多个待输入节点时必须指定节点名。

## 容器定义

容器组合执行节点并为子节点限定作用域，自身不执行、不启动 run，成员产出齐备时作汇合点。容器定义声明传入端口、输出端口与模型槽位，构成容器的封装边界：

| 字段      | 类型   | 含义 |
| --------- | ------ | --- |
| `Nodes`   | array  | 有序子节点，至少一个，整棵子树至少含一个执行节点 |
| `Models`  | array  | 模型槽位声明：成员用 `Model` 引用，引用处用 `Models` 绑定到流程模型选择，声明与使用必须一致 |
| `Inputs`  | array  | 传入端口条目，写 `Name` 与可选 `Description`，成员用 `From: ["@端口名"]` 引用传入内容 |
| `Outputs` | array  | 命名输出端口条目，写 `Name` 与 `Ref`，`Ref` 必须写 `成员@端口` 精确取成员命名段 |

槽位声明只属于节点库容器定义，装配层内联容器不声明 `Models`；引用节点用 `Models` 写槽位名到本流程模型选择的绑定对象。

`Inputs` 声明传入端口：容器定义只声明端口条目，条目写 `Name` 与可选 `Description`，成员经 `@端口名` 取用，引用处用 `In: { "端口名": "来源" }` 绑定当前流程内的实际来源，见[流程装配](流程装配.md#引用与装配)。装配层内联容器不声明 `Inputs`，输入端口声明只属于节点库容器定义。

`Outputs` 把内部成员产出透出为容器对外接口，可以声明在节点库容器定义与装配层内联容器上，引用节点不可声明。`Ref` 必须指向容器子树内的执行节点，写 `成员@端口` 取该成员声明的输出端口，端口种类取自被绑定的成员端口，`Items` 种类端口不透出。下游执行节点用 `From: ["容器名@端口"]` 精确消费，编译期解析为对绑定成员执行的依赖。

容器是封装边界，对外只暴露 `Outputs` 声明的端口；容器没有整份产出，一切对外内容都经声明的命名端口。

容器不可声明执行配置、`From` 与 `In`。容器可声明 `Gate`，成员齐备后停在待批准。容器门控嵌套时逐层停在待批准：子容器停在待批准时父容器视为未齐备，批准子容器后父容器接续判断；容器成员里的执行节点停在待批准时同样计为成员未放行。

容器可声明 `MaxRuns` 作为组内执行节点的统一执行上限：组内执行节点未写自身 `MaxRuns` 时生效，嵌套容器可覆盖外层容器的统一值，执行节点自身配置始终优先。

库里容器定义的自包含要求：成员 `From` 只能引用容器定义内部的节点，或 `@` 已声明的输入端口——容器作为整体可被多处引用而不依赖外部名字。

## 校验规则

启动时逐条校验，全部非法项一次给出。库定义与装载规则见[流程文件与节点库](流程文件与节点库.md#校验规则)，引用、展开与环的规则见[流程装配](流程装配.md#校验规则)：

- 节点名不能为空且流程内唯一。
- `Kind` 必填且取值只能是程序定义的 `Container`、`Executable` 或 `Input`；类型与声明内容必须一致：容器必须有子节点且不写执行配置，执行节点与输入节点不得有子节点，输入节点不写模型与执行配置。
- `MaxRuns` 必须是正整数：执行节点为自身上限，容器为组内执行节点的统一默认，未写时继承最近容器的统一配置，最后默认 100。
- `Outputs` 条目必须是对象：执行节点与输入节点写 `Name` 与 `Kind`，`Kind` 必填；容器写 `Name` 与 `Ref`，端口名在容器内唯一；`Data` 端口声明后必须经 `SubmitPortValues` 交回全部端口内容，下游 `From` 引用的端口必须存在，引用一律写 `来源@端口`；`Items` 与 `Context` 端口至多一个，输入节点只声明 `Data` 端口且至多一个。
- `Inputs` 条目必须是对象，写 `Name` 与可选 `Description`。
- 容器输出端口：可声明在节点库容器定义与装配层内联容器上，引用节点不可声明；绑定值必须指向容器子树内的执行节点，写 `成员@端口`，该端口必须是目标成员声明的输出端口，种类取自该端口，`Items` 种类端口不透出；输入节点与子容器不可作绑定目标。
- `SystemPrompt` 只能声明在非输入执行节点上，内容应是跨轮不变的约束，不能拼入任务动态值。
- 节点库容器定义用 `Models` 声明模型槽位，成员 `Model` 必须写在声明内，声明的槽位必须被成员使用；引用节点组的 `Models` 绑定键必须与被引用定义的声明一致。
- `Kind: Input` 的节点不启动 run，不需要模型选择，也不接受 `Tools`、`Prompt`、`Mode`、`Branch`、可选启动组、触发信号、上下文输入、`Validate` 与 `Review` 门控。
