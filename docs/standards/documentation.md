# 文档规范

- 同一事实只一处，别处写路径指向它。
- 文件名用英文小写，词间用连字符。
- 可直读代码得到的事实以代码为事实源：dev 层读者接触源码，不复述字段清单、方法签名与目录列表；用户层读者不接触源码，允许承载配置字段表。
- 统一用词：代码级调用口写接口，数据与容器的形状写形状，跨模块行为与数据语义写约定，一层的接口与形状合称契约时写契约。代码中已用 Contract 命名的类型按原名引用。
- 技术文档风格，直白且准确，不使用括号、比喻、修饰性形容词与感叹句。
- 依赖事实以工程文件的项目引用为准，各文档的依赖段与之一致。
- 跨文档引用写相对链接，路径以引用方所在目录为基准，只声明归属时写项目名。

## 分层

- `dev/architecture/architecture.md` 只写项目定位与索引，索引表按域分组，给出模块与边界文档链接。
- `dev/architecture/design.md` 只写运行时分层图，不重复模块职责与项目引用边。
- `dev/architecture/functional_boundary/` 一模块一篇，目录名与索引表的域一致，文件名 slug 由项目名点号改连字符、全小写得到。
- 边界文档结构固定为标题、简介、职责、边界外与依赖。简介一句话定性，职责由行为承诺组成，不写内部实现。
- 边界文档的跨模块约束写义务归属、传递可见性与门控条件，不写流程步骤，不写具体类型名、成员名、常量名与外部库框架名。
- `dev/architecture/mechanism/` 一主题一篇，写跨模块时序、类型名、方法名与扩展点，不写模块内部实现，不重复边界文档的职责。
