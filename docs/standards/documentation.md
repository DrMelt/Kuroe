# 文档规范

- 同一事实只一处，别处写路径指向它。
- 文件名用英文小写，词间用连字符。
- 可直读代码得到的事实以代码为事实源：dev 层读者接触源码，不复述字段清单、方法签名与目录列表；用户层读者不接触源码，允许承载配置字段表。
- 统一用词：代码级调用口写接口，数据与容器的形状写形状，跨模块行为与数据语义写约定，一层的接口与形状合称契约时写契约。代码中已用 Contract 命名的类型按原名引用。
- 技术文档风格，直白且准确，不使用括号、比喻、修饰性形容词与感叹句。
- 依赖事实以工程文件的项目引用为准，文档不复述引用清单。
- 跨文档引用写相对链接，路径以引用方所在目录为基准，只声明归属时写项目名。

## 分层

- `dev/architecture/architecture.md` 只写项目定位与命名空间规则，结构索引在边界文档树的根。
- `dev/architecture/functional_boundary/` 按层分组，每层一篇 index.md 写层结构图与项目索引表；层下按结构图节点建组目录，项目文档放在所属节点的组目录下，一项目一篇，文件名 slug 由项目名点号改连字符、全小写得到，组目录名由节点标识改连字符、全小写得到。结构见[结构文档结构](#结构文档结构)与[边界文档结构](#边界文档结构)。
- `dev/architecture/mechanism/` 一主题一篇，写跨模块时序、类型名、方法名与扩展点，不写模块内部实现，不重复边界文档的职责。

## 结构文档结构

一结构一篇，顶层为项目结构，其余为层结构。结构固定为标题、上层引用、结构图与索引表，不增设其他节：

````markdown
# 结构名

上层结构见[上层结构名](上层文件)。

```mermaid
结构图
```

| 项目 | 节点 | 边界文档 |
| --- | --- | --- |
| `项目名` | 节点名 | [文件 slug](slug.md) |
````

- 顶层省略上层引用，索引表列为层与文件。
- 层结构文档的索引表逐行给出项目、所属节点与边界文档，链接路径以组目录为前缀。
- 节点是项目组，标签列出该组覆盖的全部源代码目录；索引表的节点列与结构图节点对应，同一节点可对应多行。
- 每个节点对应一个组目录，项目文档位于所属节点的组目录下。

记法约定：

- 节点标签列出该节点覆盖的全部源代码目录。`Kuroe/X` 指 `Source/Kuroe/X`，`Kuroe.X/Y` 指 `Source/Kuroe.X/Y`，花括号列出同一前缀下的多个子目录。
- 每个源目录只出现在一个层结构图的节点中，每个节点对应一个组目录，顶层结构节点聚合列出其层结构图的全部目录。
- 箭头表示项目引用方向，从引用方指向被引用方。跨层连线画在顶层结构图的层节点之间，聚合层内项目的全部跨层引用；层内连线画在层结构图的节点之间。

## 边界文档结构

边界文档结构固定为标题、简介、职责与边界外，不增设其他节：

```markdown
# 项目名

一句话定性简介。

## 职责

- 行为承诺，不写内部实现。

## 边界外

- 不含什么，不写项目名。
```

- 边界外能力的归属由对应模块的边界文档承担。
- 跨模块约束写义务归属、传递可见性与门控条件，不写流程步骤，不写具体类型名、成员名、常量名与外部库框架名。
