# 文档规范

- 同一事实只一处，别处写路径指向它。
- 文件名用英文小写，词间用连字符。
- 可直读代码得到的事实以代码为事实源：dev 层读者接触源码，不复述字段清单、方法签名与目录列表；用户层读者不接触源码，允许承载配置字段表。
- 统一用词：代码级调用口写接口，数据与容器的形状写形状，跨模块行为与数据语义写约定，一层的接口与形状合称契约时写契约。代码中已用 Contract 命名的类型按原名引用。
- 技术文档风格，直白且准确，不使用括号、比喻、修饰性形容词与感叹句。
- 依赖事实以工程文件的项目引用为准，文档不复述引用清单。
- 跨文档引用写相对链接，路径以引用方所在目录为基准，只声明归属时写项目名。

## 分层

- `dev/architecture/architecture.md` 只写项目定位与索引，索引表按域分组，给出模块与边界文档链接。
- `dev/architecture/design/` 结构与记法见[系统结构文档结构](#系统结构文档结构)，不重复模块职责与项目引用边。
- `dev/architecture/functional_boundary/` 一模块一篇，目录名与索引表的域一致，文件名 slug 由项目名点号改连字符、全小写得到。结构见[边界文档结构](#边界文档结构)。
- `dev/architecture/mechanism/` 一主题一篇，写跨模块时序、类型名、方法名与扩展点，不写模块内部实现，不重复边界文档的职责。

## 系统结构文档结构

一结构一篇，顶层为系统结构，其余为分层。结构固定为标题、上层引用、结构图与子结构索引表，不增设其他节：

````markdown
# 结构名

上层结构见[上层结构名](上层文件)。

```mermaid
结构图
```

| 子结构 | 文件 |
| --- | --- |
| 子结构名 | [文件 slug](slug.md) |
````

- 顶层省略上层引用，叶子省略子结构索引表。
- 索引表行与结构图节点一一对应。

记法约定：

- 节点标签列出该节点覆盖的全部源代码目录。`Kuroe/X` 指 `Source/Kuroe/X`，`Kuroe.X/Y` 指 `Source/Kuroe.X/Y`，花括号列出同一前缀下的多个子目录。
- 每个目录只出现在一个叶子结构节点中，上层结构节点聚合列出其子结构的全部目录。
- 箭头表示项目引用方向，从引用方指向被引用方。跨子结构连线画在上层文档的结构节点之间，聚合子结构内项目的全部跨结构引用；子结构内连线画在子结构文档的节点之间。

## 边界文档结构

边界文档结构固定为标题、简介、职责与边界外，不增设其他节：

```markdown
# 项目名

一句话定性简介。

## 职责

- 行为承诺，不写内部实现。

## 边界外

- 不含什么，不写项目名。
```

- 边界外能力的归属由对应模块的边界文档承担。
- 跨模块约束写义务归属、传递可见性与门控条件，不写流程步骤，不写具体类型名、成员名、常量名与外部库框架名。
