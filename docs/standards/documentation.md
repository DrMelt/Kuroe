# 文档规范

## 用户文档

| 位置 | 内容 |
| --- | --- |
| `quick-start.md` | 从安装产物到完成第一个任务的最短路径 |
| `usage/` | 两个入口共用的安装、模型、设置、任务与安全主题 |
| `console/` | Kuroe.Console 的交互、页面与内置助手 |
| `cli/` | Kuroe.Cli 的命令、输出与退出码 |
| `reference/` | 概念、流程定义、示例、工具配置与内置节点和工具参考 |

- 用户文档的事实源是运行行为与配置文件，允许承载操作步骤、界面路径、配置字段表与示例。
- 用户文档只写用户可见的名称，包括入口名、命令、文件、配置字段、配置路径与界面项。入口名 Kuroe.Console 与 Kuroe.Cli 作为运行入口名使用，不写内部项目名、类型名、方法名与源码目录。
- 用户页按操作或对象组织小节。
- 术语在 `reference/concepts.md` 定义一次，其他页链接。
- 节点与工具按对象建页。条目多或存在跨条目规则时，在组目录建 `index.md`。

## 开发文档

| 位置 | 内容 |
| --- | --- |
| `architecture/functional-boundary/` | 结构文档与边界文档 |
| `architecture/mechanism/` | 跨模块机制 |
| `architecture-tests.md` | 架构测试覆盖范围与项目目录约束 |
| `build-from-source.md` | 源码构建、运行与发布 |

- 结构归属写 `functional-boundary/`，跨模块时序与扩展点写 `mechanism/`，项目引用与目录约束写 `architecture-tests.md`，构建与发布写 `build-from-source.md`。
- 开发文档的事实源是源码与工程文件。可直读代码得到的字段清单、方法签名、目录列表与项目引用清单不复述。
- 机制文档一主题一篇，不写模块内部实现，不重复边界文档的职责。
- 机制文档点名类型与方法作为定位，不抄签名与成员清单。
- 依赖关系以工程文件的项目引用为准，由结构图表达，正文不复述引用清单。
- 结构文档与边界文档的目录归属与固定结构见[结构文档](#结构文档)与[边界文档](#边界文档)。

### 结构文档

- 一结构一篇，顶层为项目结构，其余为层结构。顶层位于 `functional-boundary/index.md`，每层结构文档位于层目录的 `index.md`。
- 结构固定为标题、上层引用、结构图与索引表，不增设其他节：

````markdown
# 结构名

上层结构见[上层结构名](上层文件)。

```mermaid
结构图
```

| 项目 | 节点 | 边界文档 |
| --- | --- | --- |
| `项目名` | 节点名 | [文件名](slug.md) |
````

- 顶层省略上层引用，索引表列为层与文件。
- 层结构文档的索引表逐行给出项目、所属节点与边界文档，链接路径以组目录为前缀。
- 节点是项目组，标签列出该组覆盖的全部源代码目录。索引表的节点列与结构图节点对应，同一节点可对应多行。
- 每个节点对应一个子文件夹。
- 项目文档位于所属叶子节点的文件夹下。

记法约定：

- 节点标签列出该节点覆盖的全部源代码目录。`Kuroe/X` 指 `Source/Kuroe/X`，`Kuroe.X/Y` 指 `Source/Kuroe.X/Y`，花括号列出同一前缀下的多个子目录。
- 每个源目录只出现在一个层结构图的节点中，顶层结构节点聚合列出其层结构图的全部目录。
- 箭头表示项目引用方向，从引用方指向被引用方。跨层连线画在顶层结构图的层节点之间，聚合层内项目的全部跨层引用；层内连线画在层结构图的节点之间。

### 边界文档

- 一项目一篇，位于所属节点的组目录下。
- 文件名由项目名按 PascalCase 词边界与点号改为连字符，全小写。例如 `Kuroe.FlowDescription.Compilation` 对应 `kuroe-flow-description-compilation.md`。
- 结构固定为标题、简介、职责与边界外，不增设其他节：

```markdown
# 项目名

一句话定性简介。

## 职责

- 行为承诺，不写内部实现。

## 边界外

- 不含什么，不写项目名。
```

- 边界外能力的归属由对应模块的边界文档承担。
- 跨模块约束写义务归属、传递可见性与门控条件，不写流程步骤，不写具体类型名、成员名、常量名与外部库框架名。

## 规范文档

- 一主题一篇，条目式写约束与必要的结构模板，不写背景与操作指导。
- `standards/index.md` 列出全部规范页面。

## 通用规则

- 需要跨页定位时，在标题后写一句话范围与前置，不承担正文内容。
- 字段与取值用表，示例用代码块，操作步骤用有序列表。
- 同一事实只一处，其他位置写相对链接指向它。
- 文件与目录名用英文小写，词间用连字符。入口页命名 `index.md`。
- 文档只描述当前状态，不写修改历史、迁移说明与替代方案。
- 技术文档风格，直白且准确，不使用括号、比喻、修饰性形容词与感叹句。
- 引用方向固定：用户文档只引用用户文档，开发文档引用开发文档、用户文档与规范，规范文档引用规范、开发文档与用户文档。
