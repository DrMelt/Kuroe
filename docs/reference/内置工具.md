# 内置工具

内置工具是 Kuroe 提供的工具组，按工具路径分组。工具白名单见[工具配置](工具配置.md)；Console 专属的对话任务、导出资料与 `KuroeInfo/ListTools` 见[内置助手](../console/内置助手.md)。

## 契约工具

声明 `Text`、`TextTrigger`、`Signal` 或 `SignalTrigger` 输出端口的执行节点自动附上契约工具 `SubmitPortValues`：`Text` 端口交回端口内容，`TextTrigger` 端口交回文本或带 `text` 与 `trigger` 的对象，`Signal` 端口交回空文本或端口名、取值不承载内容，`SignalTrigger` 端口交回 `true` 或 `false` 或带 `trigger` 的对象；`Context` 输出端口由来源透传，不附这个工具。所有执行节点都附上 `GetStatus` 与 `ReportCannotComplete`。

## 状态查询

内置状态查询工具整组在 `KuroeInfo` 下：`KuroeInfo/ListTasks`、`KuroeInfo/GetTask`、`KuroeInfo/GetExecution`、`KuroeInfo/GetCatalog`、`KuroeInfo/ListFlows`、`KuroeInfo/GetFlow`、`KuroeInfo/GetConfig`。它们读取当前状态并交回文本，可用自然语言询问 Kuroe 状态；凭据不交给模型，目录工具只报凭据是否已设置。任务与执行查询只覆盖用户任务域。默认不在执行节点的可用工具中，需要时在节点 `Tools` 白名单里显式声明。`KuroeInfo/ListTools` 只在 Kuroe.Console 中可用，见[内置助手](../console/内置助手.md)。

## 文件访问

文件访问工具整组在 `file` 下，按只读与改动再分两个子分组：不改变文件的函数在 `file/read`，改动文件的函数在 `file/write`；白名单写 `file` 即两个子分组一起放行，写 `file/read` 只放行只读函数。

| 函数                      | 作用                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `file/read/ReadFile`      | 读取路径基准目录内文本文件指定行号范围，`from`/`to` 是行号，缺省读前 50 行，超出文件行数读到文件尾                                         |
| `file/read/ReadFiles`     | 一次读取多个文本文件，结果按 `paths` 顺序分段交回；路径越界或缺参整次拒绝，文件不存在等读取错误不阻断其它条目                            |
| `file/read/ListDirectory` | 列出目录直接子项，`path` 缺省为路径基准目录                                                                                                  |
| `file/read/GetFileInfo`   | 取文件的文件系统信息：字节大小、创建/修改/访问时间与只读、隐藏、系统、归档属性；只受理文件，目录用 `ListDirectory` 列出条目                  |
| `file/write/WriteFile`    | 覆盖写入文本，`content` 为空时生成空文件，上限 40000 字符，父目录缺失自动创建                                                                |
| `file/write/PatchFile`    | 按 `from`/`to` 行号范围替换内容，`original` 必须是该范围当前原文、不一致时拒绝并回给实际内容，`replacement` 为空时删除该范围，写回统一换行符 |
| `file/write/MoveFile`     | 移动文件或目录，`source` 与 `target` 相对路径基准，同目录改名即重命名；目标已存在时拒绝，父目录缺失自动创建                                  |

路径相对工具路径基准，基准由 `root` 路径变量给出。节点用 `ToolPorts` 把 `root` 映射到静态输入端口，值由 `Static` 绑定给出。路径参数在调用前统一校验：解析后必须落在工作区根内，`..` 与绝对路径逃出时整次调用被拒绝；路径参数给空字符串或空白也拒绝，根目录通过省略 `path` 表达。导入流程时要求 `ToolPorts` 覆盖 `root`；未映射 `root` 时该工具调用被拒绝且不读写文件。文件工具的全部路径参数拒绝工作区根下的 `.kuroe` 与 `.git`。校验按路径字符串进行，不解析目录联接点、符号链接与硬链接。文本按 UTF-8 解码，带 BOM 时识别。写回编码由 `encoding` 指定，支持 `utf-8`、`utf-8-bom`、`utf-16`、`utf-16be`，缺省 `utf-8` 不带 BOM。单个文件超 8000 字符截断，批量读取整体超 40000 字符截断，目录列表超 200 条时截断。文件信息的时间按本地时区输出，格式为 `yyyy-MM-dd HH:mm:ss`；属性只报只读、隐藏、系统、归档四项，四项都没有时写「无」。

## git

git 工具整组在 `git` 下，按只读与改动再分两个子分组：不改变仓库的函数在 `git/read`，改动暂存区、工作树与分支的函数在 `git/write`；白名单写 `git` 即两个子分组一起放行，写 `git/read` 只放行只读函数。这些函数执行 git 命令，命令在 `root` 变量给出的目录里执行。

| 函数                | 作用                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `git/read/Status`   | 查看工作树的改动状态：当前分支与各项的暂存、未暂存、未跟踪情况                            |
| `git/read/Diff`     | 查看改动差异，`staged` 为真时比较暂存区与 HEAD，`revision` 指定比较对象，`paths` 限定路径 |
| `git/read/Log`      | 查看提交历史，单行概述并按新到旧排列，`count` 是要看的条数，`paths` 限定路径              |
| `git/read/Show`     | 查看一个提交的说明与改动，`revision` 是提交号或修订号                                     |
| `git/read/Branches` | 列出全部分支及其当前提交，含远端分支                                                      |
| `git/write/Add`     | 把 `paths` 的改动放入暂存区                                                               |
| `git/write/Commit`  | 提交暂存区的改动，`message` 是提交说明，`paths` 限定提交范围                              |
| `git/write/Switch`  | 切到 `branch` 分支，`create` 为真时新建分支并切过去                                       |
| `git/write/Restore` | 丢弃 `paths` 的改动，`staged` 为真时把路径移出暂存区并保留工作树内容                      |

`paths` 是路径参数，经 `--` 收尾，`--` 与路径项一起增删；模型给出的路径按 `root` 变量给出的工作目录解析，越出工作区时调用被拒绝且不启动进程，通过后原样交给 git。开关是布尔参数，命令行文字由模板固定，模型只能决定开关的真假。修订号与分支名不做校验，非法值由 git 报错并交回文本。全部是本地操作，推送、抓取等远端操作不在其中。

## dotnet

dotnet 工具整组在 `dotnet` 下，按只读与改动再分两个子分组：只查环境与项目信息的函数在 `dotnet/read`，会编译、改写项目或产生产物的函数在 `dotnet/write`；白名单写 `dotnet` 即两个子分组一起放行，写 `dotnet/read` 只放行只读函数。这些函数执行 `dotnet` 命令，命令在 `root` 变量给出的目录里执行。

| 函数                       | 作用                                                           |
| -------------------------- | -------------------------------------------------------------- |
| `dotnet/read/Info`         | 查看本机 .NET 环境：SDK 与已装运行时的版本、安装位置与当前 RID |
| `dotnet/read/ListSdks`     | 列出本机已安装的 SDK 版本与安装位置                            |
| `dotnet/read/ListPackages` | 列出项目顶层的包引用，`outdated` 为真时只列出有新版本的包      |
| `dotnet/read/NugetSources` | 列出配置的 NuGet 包源，读到 `root` 变量目录及其上级的 NuGet 配置 |
| `dotnet/write/Build`       | 编译项目，`configuration` 是 Debug 或 Release 之类的生成配置   |
| `dotnet/write/Test`        | 运行测试，`filter` 是测试筛选表达式                            |
| `dotnet/write/Run`         | 运行项目，`arguments` 是传给应用的参数                         |
| `dotnet/write/Restore`     | 还原项目的包依赖                                               |
| `dotnet/write/Format`      | 按项目里的代码风格设置整理源码                                 |
| `dotnet/write/Publish`     | 发布项目到输出目录，`configuration` 是生成配置                 |
| `dotnet/write/AddPackage`  | 给项目添加包引用，`package` 是包名，`version` 是版本号         |

`project` 是路径参数，给出项目、解决方案或目录的相对路径，按 `root` 变量给出的工作目录解析并限制在工作区内，越界时调用被拒绝且不启动进程；缺省时 dotnet 在该工作目录里查找。`configuration`、`filter`、`version` 是可选参数，与命令行里的选项项一起增删，缺省时命令行里没有 `--configuration`、`--filter`、`--version`。`outdated` 是布尔开关，`arguments` 是独立的参数列表，写在 `--` 之后。`package` 是必填参数，缺省时调用被拒绝。

命令不在交互模式下运行。查询环境与项目的函数超时 120 秒，包列表与添加包的函数超时 300 秒，编译、测试、运行、还原、整理、发布的函数超时 600 秒；应用在超时前不结束会被连同进程树终止。推送包、部署到远端这类动作不在其中。

## 时间

内置的 `GetLocalTime` 返回当前系统时区与准确当地时间。
