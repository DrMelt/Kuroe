# 概念

本文定义文档反复使用的对象与术语。字段写法与操作步骤见对应页面。

## 工作区

工作目录由 `-d` 给出，是 Kuroe 的工作区根。命令里的文件参数、路径校验与工具路径基准都相对它解析，与启动进程的当前目录无关。工作目录下的目录布局见[安装与运行](../usage/安装与运行.md#工作目录)。

## 流程

流程是任务模板，由节点组成，写在 `.kuroe/flows.json`。每条流程有且只有一个根节点，根节点可以是执行节点或容器。开始入口声明流程接收的输入，写在 `Start`。

节点库写在 `.kuroe/nodes.json`，存放具名的节点定义，流程用 `Use` 引用。节点定义与引用的字段见[流程定义](流程定义.md)。

## 节点

节点按 `Kind` 分为容器与执行节点。

- 容器组合成员并限定作用域，自身不执行。
- 执行节点调用模型或执行外部动作，每次启动产生一次执行。
- `Input` 与 `Approval` 不启动执行，只表达停驻。

## 端口

端口是节点之间的内容通道。输出端口交回内容供下游读取，输入端口接收上游内容或静态值。

- 静态输入在任务内只确定一次值，只由下游 `Bindings` 读取。
- 动态输入由上游新产出驱动，写在 `From`。
- `Plain` 是普通动态端口，`Trigger` 携带触发值并门控下游启动组，`Constant` 在任务内只确定一次值。

端口类型、模式与组合规则见[流程定义](流程定义.md#端口与模式)。

## 作用域

容器限定成员的可见范围。成员只能引用本容器子树内的节点与容器传入端口，容器外的节点与端口不可见。开始节点只在流程作用域可见，根节点与根容器用 `Start@端口` 取用，容器成员经容器传入端口取用。

## 任务

任务是流程的一次提交，有任务键、标题、流程、开始输入与状态。任务启动后流程、开始输入与模型不再变化。任务数据与状态见[任务与执行](../usage/任务与执行.md)。

## 执行

执行是执行节点的一次运行，是模型请求与工具往返的单位。一次执行记录请求次数、token 用量、过程记录与恢复数据。执行节点按上游产出反复启动，`Emission: Once` 首次成功发布后冻结。

## 停驻与恢复

停驻是流程安排的一次等待，分等待输入与等待批准，只由 `Input` 与 `Approval` 节点产生，不由工具调用产生。恢复指中断后从中断处继续同一次执行，重新执行指放弃恢复并新建一次执行。两者的操作后果见[任务与执行](../usage/任务与执行.md#暂停与恢复)。

## 宿主开始输入

开始端口默认由提交者给值。宿主开始输入表把指定的开始端口交给 Kuroe 给值，可取工作区根、任务目录与当前模型。表的结构见[宿主开始输入](宿主开始输入.md)。
