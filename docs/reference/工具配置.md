# 工具配置

两个入口共用工具配置：节点 `Tools` 白名单限定可用工具，`.kuroe/tools.json` 声明命令模板工具。内置工具分组见[内置工具](tools/index.md)。

## 工具白名单

`Tools` 按工具路径前缀匹配，写上级路径放行整棵子树，写完整路径只放行单个函数，按原文大小写敏感。非法路径匹配不到任何工具，导入时报错。契约工具由执行节点自动附上，见[契约工具](tools/contract.md)。

## 命令模板工具

在工作目录 `.kuroe/tools.json` 里声明命令工具，启动时加载；文件不存在时没有命令工具，条目不合法时启动报错。路径变量由节点的 `ToolPorts` 映射到输入端口，见[流程定义](流程定义.md#工具变量)。下例 `RunDiff` 与 `RunLog` 同属 `git` 分组，白名单写 `git` 整组放行，写 `git/RunDiff` 只放行一个。

```json
{
  "Tools": [
    {
      "Name": "RunDiff",
      "Group": "git",
      "Description": "查看指定文件或目录相对 HEAD 的改动。",
      "Template": ["git", "diff", "{path}"],
      "Parameters": [
        { "Name": "path", "Description": "要查看的文件或目录路径", "Required": true, "Path": true, "Deny": [".kuroe"] }
      ]
    },
    {
      "Name": "RunLog",
      "Group": "git",
      "Description": "查看指定文件列表的提交历史。",
      "Template": ["git", "log", "--oneline", "--", "{files}"],
      "Parameters": [
        { "Name": "files", "Description": "限定查看的文件路径列表", "List": true, "Path": true, "Allow": ["Source", "docs"] }
      ]
    },
    {
      "Name": "RunCurl",
      "Description": "携带可省略的访问令牌请求一个 URL。",
      "Template": ["curl", "-f", { "Text": "Authorization: Bearer {token}", "OmitWhenMissing": "token" }, "{url}"],
      "Parameters": [
        { "Name": "token", "Description": "访问令牌，可省略" },
        { "Name": "url", "Description": "请求地址", "Required": true }
      ]
    }
  ]
}
```

| 字段             | 类型     | 含义                                                                                                                    |
| ---------------- | -------- | ----------------------------------------------------------------------------------------------------------------------- |
| `Name`           | string   | 函数名，完整路径的末段；省略 `Group` 时完整路径即它，只能写字母、数字、下划线与连字符                                   |
| `Group`          | string   | 分组，与 `Name` 拼出完整路径 `分组/函数名`，每段字符集同上，完整路径不能与其他工具重复                                  |
| `Description`    | string   | 给模型的说明                                                                                                            |
| `Template`       | array    | 命令行模板，元素是命令行文字或参数项对象，对象写法见[参数规则](#参数规则)                                               |
| `Parameters`     | object[] | 参数声明，见参数规则                                                                                                    |
| `Variables`      | string[] | 路径变量名；模板与 `Directory` 引用的变量必须在此声明，`Directory` 引用的变量自动并入；变量对模型不可见，不能与参数同名 |
| `Directory`      | string   | 命令执行目录，相对执行基准，可含路径变量，缺省为执行基准                                                                |
| `TimeoutSeconds` | int      | 命令超时秒数，缺省 120，最大 2147483                                                                                    |
| `OutputLimit`    | int      | 交回文本上限，缺省 8000 字符                                                                                            |

### 参数规则

- 标量参数：`Required` 为真时缺省即拒绝调用，可选参数缺省时对应参数项整体消失。缺省指未给出或 JSON null。
- `List` 声明字符串列表参数，模型以数组给出，模板里必须写成独立的 `{files}` 参数项，不传或空数组时该项消失。列表参数不能嵌在其他文字里。
- 模板参数项对象用 `Text` 给出命令行文字，用 `OmitWhenMissing` 关联参数名，两个字段都必须给出。关联参数缺省时整个参数项去掉；关联参数必填且缺省时调用被拒绝。字符串项内嵌的占位符缺省时保留字面量。不含占位符的项，其关联参数必须是布尔参数，或在模板别处作为占位符出现。
- `Flag` 声明布尔开关，模板里写成关联该项的 `OmitWhenMissing`。为真时整个参数项加入命令行，为假或缺省时去掉，参数本身不出现在命令行文字里。布尔参数不能同时是列表参数或必填参数。
- `Path` 声明路径参数，模型给出的是路径。解析后必须落在工作目录内，绝对路径与 `..` 越出时拒绝。路径参数给空字符串或空白时拒绝。可以是 `List`，逐项校验，任一项不通过即整次调用拒绝。路径参数不能是布尔参数。
- `Allow` 与 `Deny` 是路径参数的白名单与黑名单，只用于 `Path` 为真的参数。条目按工作目录解析且必须在工作目录内。匹配按目录段前缀，`src` 覆盖 `src` 与 `src/...`，不覆盖 `src2`。黑名单优先，命中即拒绝；白名单非空时未命中即拒绝。

内置文件工具的路径规则见[文件](tools/file.md)。

## 路径与执行

`Directory` 必须在工作目录内，越界时启动报错。含路径变量时按调用时的端口值解析并校验边界。路径校验只做字符串解析与归一，不解析符号链接、目录联接点与硬链接，传给命令的仍是模型给出的原文。

工具在 `Directory` 指向的目录启动，stdout 与 stderr 合并成文本交回模型并附退出码，超时或启动失败也写成文本。输出按 UTF-8 解码，用本地代码页输出的 Windows 工具其文本可能乱码。参数项直接传入进程，不经 shell 解释，模板不支持管道与重定向。

`tools.json` 声明模型有权调用的命令，是命令执行边界所在。采纳外部目录前先检查模板与 `Directory`。模板第一项是程序本身，不要把占位符嵌进 `cmd /c`、`bash -c` 这类 shell 命令串，模型实参里的元字符会被 shell 解释，等同于把任意命令执行能力交给模型。工具边界之外的进程权限见[安全与权限](../usage/安全与权限.md)。
