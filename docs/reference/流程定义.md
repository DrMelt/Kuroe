# 流程定义

流程模板存在工作目录 `.kuroe/` 的 `flows.json`，可以手工编辑，文件不存在时流程库为空。文件由 JSON 层读成描述，再由编译器装配成执行视图。节点字段见[节点](#节点)，引用与接线见[引用与装配](#引用与装配)。

## 文件结构

```json
{
  "Nodes": [ { "Name": "库节点名", "Kind": "Llm", "...": "..." } ],
  "Flows": [
    {
      "Name": "流程名",
      "Description": "可选说明",
      "Models": [],
      "Start": { "Outputs": [ { "Name": "目标", "Type": "Text" } ] },
      "Nodes": [ { "Name": "根容器名", "Kind": "Container", "Nodes": [] } ]
    }
  ]
}
```

顶层 `Nodes` 是可复用的节点库，`Flows` 是流程，每条流程有且只有一个根节点。

## 节点库

顶层 `Nodes` 是节点定义，作复用单元供流程引用。定义有两个来源：程序内置节点随启动提供，文件顶层 `Nodes` 定义自定义节点，两者同名合并，以文件定义覆盖。内置节点是执行节点「规划」「执行」与容器「交付」。

两种定义：

- 执行节点定义：声明输入端口、输出端口、工具白名单与执行方式，不写接线，不声明模型。
- 容器定义：`Nodes` 子数组组织一组有序成员，`Models` 声明成员需要的模型槽位，`Inputs` 声明传入端口，`Outputs` 声明对外端口。

库定义只声明能力，模型与接线由装配层输入。

## 开始入口

`Start` 声明流程唯一的来源节点，名与标签都是保留的 `Start`：`Outputs` 条目写 `Name`、`Type` 与可选 `Value`，`Type` 只能是 `Text`。至少一个端口不带 `Value`，提交任务时按端口逐个给输入；其余端口必须带 `Value`，是写死的固定输出。开始节点不属于任何容器，任何作用域都能引用，节点用 `From: [{ "输入名": "Start@端口" }]` 取用。

除流程声明的端口外，开始节点固定提供两个 `Text` 端口：`WORKSPACE_PATH` 是 `-d` 给出的工作区根目录绝对路径，未指定时为进程当前目录；`TASK_WORK_PATH` 是本次任务目录的绝对路径。两个端口由宿主在任务启动时给值，不写进 `Outputs`，提交任务时不填；流程直接写 `From: [{ "输入名": "Start@WORKSPACE_PATH" }]` 取用。两个名字是保留的，不能声明为开始端口。任务目录见[安装与运行](../usage/安装与运行.md#任务目录)。

## 节点

节点类型名由程序定义，文件必须显式写 `Kind`，取值 `Container`、`Llm`、`FileRead`、`FileWrite`、`Command`、`Input`、`Approval`。`Container` 由引擎提供，其余由装配处注册。

| 类型 | 作用 |
| --- | --- |
| `Container` | 组合成员并限定作用域 |
| `Llm` | 由模型执行 |
| `FileRead` / `FileWrite` | 读取 / 写入工作目录内文件 |
| `Command` | 在工作目录内执行命令并把输出作为产出 |
| `Input` | 等用户回答 |
| `Approval` | 等用户批准 |

共用结构字段：

| 字段 | 含义 |
| --- | --- |
| `Name` | 节点名，定义条目的名字，同一容器内唯一且不能为空，不能含 `@` 与 `/` |
| `Label` | 节点标签，被使用节点在图里的标识段，同一容器内唯一且不能为空，不能含 `@` 与 `/` |
| `Kind` | 节点类型名，必填；引用节点不写 |
| `MaxExecutions` | 执行次数上限，见各节点类型 |

`Nodes` 里的条目分两种：没有 `Use` 的是节点定义，写 `Name`；有 `Use` 的是被使用的节点，必须写 `Label`。定义条目的标签取节点名的文本，节点在图里统一以标签标识。

## 执行节点

执行节点是唯一派发模型执行的节点，由以下结构字段描述。

| 字段 | 含义 |
| --- | --- |
| `Model` | 节点组内：容器定义的槽位名；装配层内联与引用执行节点写模型选择名 |
| `Inputs` | 输入端口表，写 `Name` 与可选 `Type`、`Description`、`Default` |
| `Outputs` | 输出端口表，写 `Name` 与 `Type` |
| `From` | 上游启动组，见[上游接线](#上游接线) |
| `Validate` | 输出校验，见[输出校验](#输出校验) |
| `MaxExecutions` | 最高执行次数，未写继承最近容器统一配置，最后默认 100 |

执行的上下文由上游装配后传入，不继承未声明的内容。执行节点在收口时交回 `Outputs` 声明的全部端口，模型经契约工具 `SubmitPortValues` 交回；每个执行节点还附 `GetStatus` 与 `ReportCannotComplete` 上报本轮状态。契约工具见[内置工具](内置工具.md#契约工具)。

## 类型参数

类型专属声明与结构字段同级写在节点对象里，引用节点不声明类型参数。

| 参数 | 类型 | 归属 | 含义 |
| --- | --- | --- | --- |
| `Prompt` | string | Llm | 对本次执行的额外要求，构成本轮指令 |
| `Tools` | string[] | Llm | 能力工具白名单，按工具路径前缀匹配，写上级路径放行整棵子树，见[工具配置](工具配置.md#工具面) |
| `SystemPrompt` | string[] | Llm | 恒定系统指令块 |
| `Question` | string | Input、Approval | 等待型节点的提示文本 |
| `Path` | string | FileRead、FileWrite | 相对工作目录的文件路径 |
| `MaxChars` | int | FileRead、FileWrite、Command | 单次读写或命令输出的字符上限，0 不限制；读取与命令未写 8000，写入未写不限制 |
| `Program` | string | Command | 要执行的程序名或路径，必填 |
| `Arguments` | string[] | Command | 传给程序的参数，不经 shell 解释 |
| `Directory` | string | Command | 命令执行目录，相对工作目录 |
| `TimeoutSeconds` | int | Command | 命令等待上限秒数，未写 120 |

## 节点类型

### 输入节点

`Kind: Input` 不启动执行、不需要模型选择：依赖齐备后停在待输入，回答写入唯一输出端口。只声明 `Question`，输入端口取 `Text` 或 `Signal`，输出至多一个 `Text` 端口。

### 审批节点

`Kind: Approval` 不启动执行：上游启动条件齐备后停在待批准，放行后下游启动。只声明 `Question`，对外端口由自身 `Inputs` 派生。

### 文件读取节点

`Kind: FileRead` 不启动执行：`From` 任一组齐备且来源有新版本时读取 `Path` 指向的文件，内容写入唯一 `Text` 输出端口。输入只取 `Signal` 触发，至少一个。文件不存在或读取失败时停在阻塞。

### 文件写入节点

`Kind: FileWrite` 不启动执行：把唯一 `Text` 输入内容覆盖写入 `Path` 指向的文件，其余输入只能是 `Signal` 触发。输出端口可省略，也可声明一个：`Text` 给出写入内容，`Signal` 只表示写入完成。

### 命令执行节点

`Kind: Command` 不启动模型执行：`From` 任一组齐备且来源有新版本时在工作目录内执行一次命令，合并 stdout 与 stderr 写入唯一 `Text` 输出端口。输入只取 `Signal` 触发，至少一个。退出码非零、超时或无法启动时停在阻塞。

### 容器定义

容器组合执行节点并为子节点限定作用域，自身不执行。声明传入端口、输出端口与模型槽位，构成封装边界。

| 字段 | 含义 |
| --- | --- |
| `Nodes` | 有序子节点，至少一个 |
| `Models` | 模型槽位声明，成员用 `Model` 引用，引用处用 `Models` 绑定到流程模型选择 |
| `Inputs` | 传入端口条目，成员用 `From: [{ "输入名": "@端口名" }]` 引用传入内容 |
| `Outputs` | 命名输出端口条目，写 `Name` 与 `Ref`，`Ref` 写 `成员@端口` |

容器对外只暴露 `Outputs` 声明的端口，没有整份产出。容器不可声明执行配置、`Question`、`From` 与 `In`，也不接受任何类型参数。需要人工放行时在容器下游接审批节点。

## 端口

### 端口类型

| 类型 | 含义 |
| --- | --- |
| `Text` | 输出：模型交回命名段；输入：来源取值按序进入目标输入 |
| `TextTrigger` | 与 `Text` 相同文本语义，另带是否触发下游的布尔值 |
| `Context` | 输出：来源执行输入侧内容逐步保留出处；输入：置于目标输入最前 |
| `Signal` | 不承载内容，只以发布版本驱动下游 |
| `SignalTrigger` | 与 `Signal` 相同驱动语义，另带是否触发下游的布尔值 |

端口类型注册时自动产生普通版与 Trigger 版。普通端口触发值恒为 `true`，Trigger 版由模型交回，省略为 `true`。

### 输入端口

输入端口声明目标侧的输入名。`Inputs` 可省略，省略时 `From` 连接键按 `Text` 处理；声明后 `From` 每个组必须覆盖全部不带默认值的输入端口。派发执行的节点可以为普通 `Text` 输入端口声明 `Default`，未连接时进入执行输入。

### 输出端口与系统指令

`Outputs` 声明输出端口，派发执行的节点由模型经 `SubmitPortValues` 交回 `Text`、`TextTrigger`、`Signal`、`SignalTrigger` 端口；`Context` 输出由来源透传，不需要模型交回。未交回时同一执行内追问补交最多两次，仍缺才停在阻塞待返工。

`SystemPrompt` 声明系统指令块，按序拼接后整段作为请求的系统指令；声明块应是跨轮不变的约束，不要拼入动态值。

## 模型选择

`Models` 在流程层是按名引用的模型选择。

| 字段 | 含义 |
| --- | --- |
| `Name` | 模型选择名，流程内唯一且不能为空 |
| `Model` | 使用的模型名，省略时引用它的执行节点无法确定模型 |
| `Runtime` | 取宿主当前选中的模型，与 `Model` 互斥 |

模型选择未写 `Model` 时流程可以加载，但引用它的执行节点在提交任务或启动时报错。

## 引用与装配

引用节点写 `Label`、`Use`，模型由装配层输入。

```json
{ "Label": "实施", "Use": "执行", "Model": "执行者" }
```

| 字段 | 含义 |
| --- | --- |
| `Use` | 引用的节点库定义名，引用容器时可用 `In` 与 `Models` 绑定 |
| `Model` | 引用执行节点时的模型选择名，必须定义在同流程的 `Models` 里 |
| `Models` | 引用节点组时的模型槽位绑定 |
| `In` | 引用容器时端口名到来源的映射，值写 `来源@端口` 或 `@更外层端口` |
| `From` | 仅引用执行节点时注入接线 |
| `MaxExecutions` | 覆盖库定义的自身上限（执行节点）或组内统一上限（容器） |

引用同一个容器定义多次必须给不同 `Label`。引用执行节点时 `Model` 必填；引用节点组时 `Models` 绑定键必须与容器定义的槽位声明一一对应。引用容器不写 `From`，容器对外只暴露 `Outputs` 声明的端口，下游消费写 `容器标签@端口`。

## 上游接线

`From` 是执行节点的唯一接线字段，数组元素是一个启动组，组内是目标输入端口名到来源端口引用的映射。

```json
"From": [
  { "计划": "计划@结论" },
  { "计划": "评审@结论" }
]
```

组间任一齐备即启动，组内全部齐备。组内可省略带默认值的输入端口。来源可以是执行节点或容器：容器写 `容器标签@端口`，执行节点写 `来源@端口`。执行节点按来源产出版本判定启动，同一版本不重复启动；组内有信号输入时只由该组信号来源的新版本驱动。组内任一 Trigger 绑定取到 `false` 时该组不驱动启动。

## 输出校验

`Validate` 给执行节点一条输出校验规则：执行收口后按声明端口拼接出的文本判定，不通过则停在阻塞等待返工。

| 字段 | 含义 |
| --- | --- |
| `Predicate` | `NonEmpty`、`TextContains`、`TextNot`、`TextEquals`、`Pattern` |
| `Argument` | 谓词参数，`NonEmpty` 不需要 |

声明 `Validate` 的节点必须声明至少一个文本语义的输出端口。执行节点引用可以互相指回构成环，环必须有环外来源或环内输入节点才能启动，收敛由输出校验或 `MaxExecutions` 兜底。

## 关键约束

加载时逐条校验，非法项一次给出。要点：

- 每条流程有且只有一个根节点，必须声明 `Start`，至少一个不带 `Value` 的 `Text` 端口；开始端口不能用 `WORKSPACE_PATH` 与 `TASK_WORK_PATH` 这两个宿主固定端口名。
- 每个执行节点、输入节点与审批节点都必须能从开始经 `From` 引用边到达。
- 节点名与标签不能为空、不能含 `@` 与 `/`、不能用保留的 `Start`，同一容器内唯一，库定义名库内唯一。
- `Kind` 必填且取值必须是已注册类型；引用节点不写执行配置、子节点、`Inputs` 与 `Validate`。
- 端口名在同一节点内唯一，端口类型必须是已注册类型；`From` 每个组覆盖全部不带默认值的输入端口，来源必须存在。
- 模型选择名流程内唯一，节点引用的模型选择必须存在，引用的库定义必须存在。
- 节点库容器定义自包含：成员 `From` 只指向定义内部节点或已声明端口。
- 同一执行节点的执行次数达到 `MaxExecutions` 上限后不再启动。
