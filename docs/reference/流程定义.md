# 流程定义

流程模板存在工作目录 `.kuroe/` 的 `flows.json`，可以手工编辑，文件不存在时流程库为空。Kuroe 在导入或启动时校验流程，非法项一次给出。节点字段见[节点](#节点)，引用与接线见[引用与接线](#引用与接线)。

## 文件结构

```json
{
  "Nodes": [ { "Name": "库节点名", "Kind": "Llm", "...": "..." } ],
  "Flows": [
    {
      "Name": "流程名",
      "Description": "可选说明",
      "Start": { "Outputs": [ { "Name": "目标", "Type": "Text" } ] },
      "Nodes": [ { "Name": "根容器名", "Kind": "Container", "Nodes": [] } ]
    }
  ]
}
```

顶层 `Nodes` 是可复用的节点库，`Flows` 是流程，每条流程有且只有一个根节点。

## 节点库

顶层 `Nodes` 是节点定义，作复用单元供流程引用。定义有两个来源：内置节点与文件顶层 `Nodes` 定义的自定义节点，两者同名合并，以文件定义覆盖。内置节点是执行节点「规划」「执行」与容器「交付」。

两种定义：

- 执行节点定义：声明输入端口、输出端口、工具白名单与执行方式，不写接线。
- 容器定义：`Nodes` 子数组组织一组有序成员，`Inputs` 声明传入端口，`Outputs` 声明对外端口。

库定义只声明能力，接线与静态输入绑定在引用处填写。执行节点的模型是静态输入端口 `MODEL_NAME`，值在任务启动时由 Kuroe 给出。

## 开始入口

`Start` 声明流程唯一的来源节点，名与标签都是保留的 `Start`：`Outputs` 与其他节点使用同一端口条目，`Type` 省略时按 `Text`，`Mode` 省略时按类型默认模式。动态端口只能是 `Text` 或 `Signal`，常量端口可以使用任意已注册语义。至少一个端口不带 `Value`。不带 `Value` 的端口在提交任务时逐个给输入，也可由流程级 `HostStartInputs` 绑定到宿主输入；带 `Value` 的端口是写死的固定输出。`Mode: Constant` 的端口是常量端口，值在任务启动时确定，来自 `Value`、宿主输入或提交输入，只能被下游 `Static` 读取，不进入 `From`。开始端口不能使用触发，`Signal` 端口在开始入口需要写 `Mode: Plain` 或 `Mode: Constant`。开始节点不属于任何容器，只在流程作用域可见：根节点的 `From` 与根容器的 `In` 用 `Start@端口` 取用，容器成员经容器的传入端口取用。

流程级 `HostStartInputs` 把开始端口绑定到宿主输入名：键是 `Start.Outputs` 已声明的端口，值由 Kuroe 解释。绑定端口的值在任务启动时由 Kuroe 给出，不接受提交输入，也不能带 `Value`。没有绑定宿主输入且不带 `Value` 的常量端口由提交输入给值。Kuroe 提供三个宿主输入：`WORKSPACE_PATH` 是 `-d` 给出的工作区根目录绝对路径，未指定时为进程当前目录；`TASK_WORK_PATH` 是本次任务目录的绝对路径；`MODEL` 是任务启动时当前选中的模型名。流程示例：

```json
"Start": {
  "Outputs": [
    { "Name": "目标", "Type": "Text" },
    { "Name": "启动路径", "Type": "Text", "Mode": "Constant" }
  ]
},
"HostStartInputs": { "启动路径": "WORKSPACE_PATH" }
```

节点声明静态输入 `启动路径`，用 `Static: { "启动路径": "Start@启动路径" }` 取用；节点在容器内时由容器的静态输入经 `In` 转发。任务目录见[安装与运行](../usage/安装与运行.md#任务目录)。

## 节点

文件必须显式写 `Kind`，取值 `Container`、`Llm`、`FileRead`、`FileWrite`、`Command`、`Input`、`Approval`。

| 类型                     | 作用                                                  |
| ------------------------ | ----------------------------------------------------- |
| `Container`              | 组合成员并限定作用域                                  |
| `Llm`                    | 由模型执行                                            |
| `FileRead` / `FileWrite` | 以 `Variables` 映射路径变量并读取 / 写入文件          |
| `Command`                | 以 `Variables` 映射执行目录并执行命令，把输出作为产出 |
| `Input`                  | 等用户回答                                            |
| `Approval`               | 等用户批准                                            |

共用结构字段：

| 字段            | 含义                                                                            |
| --------------- | ------------------------------------------------------------------------------- |
| `Name`          | 节点名，定义条目的名字，同一容器内唯一且不能为空，不能含 `@` 与 `/`             |
| `Label`         | 节点标签，被使用节点在图里的标识段，同一容器内唯一且不能为空，不能含 `@` 与 `/` |
| `Kind`          | 节点类型名，必填；引用节点不写                                                  |
| `MaxExecutions` | 执行次数上限，见各节点类型                                                      |

`Nodes` 里的条目分两种：没有 `Use` 的是节点定义，写 `Name`；有 `Use` 的是被使用的节点，必须写 `Label`。定义条目的标签取节点名的文本，节点在图里统一以标签标识。

## 执行节点

执行节点是唯一调用模型的节点，由以下结构字段描述。

| 字段            | 含义                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------ |
| `Static`        | 静态输入绑定，目标静态输入端口到来源引用，模型与路径端口都用它                             |
| `Inputs`        | 输入端口表，写 `Name` 与可选 `Type`、`Mode`、`Description`、`Default`、`Role`              |
| `Outputs`       | 输出端口表，写 `Name` 与可选 `Type`、`Mode`、`Value`、`Ref`                                |
| `From`          | 上游启动组，见[上游接线](#上游接线)                                                        |
| `Validate`      | 输出校验，见[输出校验](#输出校验)                                                          |
| `Emission`      | 产出模式：`Repeated` 逐次发布，`Once` 首次发布后冻结                                       |
| `MaxExecutions` | 最高执行次数，未写继承最近容器统一配置，最后默认 100                                       |

执行节点接收 `Inputs` 声明的输入，以及 `From` 目标在类型允许时引入的 `Text` 内容输入。`Llm`、`Input`、`Approval` 接受推断输入，其他类型要求 `From` 目标在 `Inputs` 中声明。输入角色 `Role` 取 `Content`、`Configuration` 或 `Control`，分别表示执行内容、按名配置与只作触发；角色不随模式改变。未写 `Role` 时，常量端口按 `Configuration`，动态 `Signal` 端口按 `Control`，其余按 `Content`。`Mode` 取 `Plain`、`Trigger` 或 `Constant`，支持范围由端口类型注册声明。`Plain` 是普通动态端口，`Trigger` 在动态交回时携带触发值并门控启动组，`Constant` 是任务内只确定一次值的单值端口。`Text` 支持三种模式，`Signal` 支持三种模式，`Context` 只支持 `Plain` 与 `Constant`。`Signal` 未写 `Mode` 时默认 `Trigger`，其他类型默认 `Plain`。执行节点在结束时交回 `Outputs` 声明的全部动态端口与由执行产出的常量端口，模型经契约工具 `SubmitPortValues` 交回；每个执行节点还附 `GetStatus` 与 `ReportCannotComplete` 上报本轮状态。契约工具见[内置工具](内置工具.md#契约工具)。

输入全部静态或没有输入、且没有 `From` 的执行节点，在静态输入全部就绪后执行。没有输入时静态输入集合为空，同样就绪。静态输入在任务启动时已确定时立即执行，绑定到运行期常量时等待该常量产出。静态输入是启动条件，不是不执行的标记。`Emission: Once` 的节点只能声明常量输出，至少有一个由执行产出的常量输出，不能声明动态输入或 `From`，可以一次产出多个不同类型的常量。`Once` 节点首次成功发布后冻结，未发布时可以失败重试与返工，`MaxExecutions` 表示尝试上限。`Repeated` 节点不能声明没有 `Value` 与 `Ref` 的常量输出。下游只能用 `Static` 读取常量输出，不进入 `From`。只声明静态 `MODEL_NAME` 的 Llm 节点会正常执行；如果只需要配置值，直接在下游 `Static` 绑定到开始端口或容器输入，不必经过节点。

## 类型参数

类型专属声明与结构字段同级写在节点对象里，引用节点不声明类型参数。

| 参数             | 类型     | 归属                         | 含义                                                                                             |
| ---------------- | -------- | ---------------------------- | ------------------------------------------------------------------------------------------------ |
| `Prompt`         | string   | Llm                          | 对本次执行的额外要求，构成本轮指令                                                               |
| `Tools`          | string[] | Llm                          | 能力工具白名单，按工具路径前缀匹配，写上级路径放行整棵子树，见[工具配置](工具配置.md#工具白名单) |
| `ToolPorts`      | object   | Llm                          | 工具路径到路径变量映射的对象，键可按工具路径前缀匹配，见[工具变量](#工具变量)                    |
| `SystemPrompt`   | string[] | Llm                          | 恒定系统指令块                                                                                   |
| `Question`       | string   | Input、Approval              | 等待型节点的提示文本                                                                             |
| `Path`           | string   | FileRead、FileWrite          | 可含 `{变量}` 的文件路径，变量由 `Variables` 映射到输入端口                                      |
| `Variables`      | object   | FileRead、FileWrite、Command | 路径变量名到 `Text` 输入端口的映射，键必须与 `Path` 或 `Directory` 的占位符一一对应              |
| `MaxChars`       | int      | FileRead、FileWrite、Command | 单次读写或命令输出的字符上限，0 不限制；读取与命令未写 8000，写入未写不限制                      |
| `Program`        | string   | Command                      | 要执行的程序名或路径，必填                                                                       |
| `Arguments`      | string[] | Command                      | 传给程序的参数，不经 shell 解释                                                                  |
| `Directory`      | string   | Command                      | 命令执行目录，可含 `{变量}`；未写时执行目录即 `root` 变量或工作区根                              |
| `TimeoutSeconds` | int      | Command                      | 命令等待上限秒数，未写 120                                                                       |

文件与命令节点用 `Variables` 声明路径变量到 `Text` 输入端口的映射。静态输入端口用 `Static` 绑定取来源，动态端口在每组 `From` 里连接。`Path` 与 `Directory` 的占位符必须由 `Variables` 完整覆盖，映射端口必须已声明且为 `Text`。文件读取节点的 Text 输入必须全部是路径变量端口；文件写入节点恰好有一个未被映射的 Text 内容端口；命令节点没有内容端口。路径变量值按工作区根解析，`root` 变量作为相对路径的基准，解析结果必须落在工作区根内。

## 节点类型

### 输入节点

`Kind: Input` 不启动执行、没有模型静态输入：收到上游通知后停在待输入，回答写入唯一输出端口。只声明 `Question`，输入端口取 `Text` 或 `Signal`，输出至多一个 `Text` 端口。

### 审批节点

`Kind: Approval` 不启动执行：输入齐备后停在待批准，停驻时的输入取值与触发值在放行后按同名输出端口放出。只声明 `Question`，对外端口由自身 `Inputs` 派生。

### 文件读取节点

`Kind: FileRead` 不启动执行：`From` 任一组齐备且来源有新产出时按 `Variables` 解析 `Path` 并读取文件，内容写入唯一 `Text` 输出端口。Text 输入全部是路径变量端口，另需至少一个 `Signal` 触发。文件不存在、路径越出工作区或读取失败时停在阻塞。

### 文件写入节点

`Kind: FileWrite` 不启动执行：把唯一未被映射的内容 `Text` 输入覆盖写入按 `Variables` 解析的 `Path` 指向的文件，路径变量端口与 `Signal` 触发可以有多个。输出端口可省略，也可声明一个：`Text` 给出写入内容，`Signal` 只表示写入完成。路径越出工作区或写入失败时停在阻塞。

### 命令执行节点

`Kind: Command` 不启动模型执行：`From` 任一组齐备且来源有新产出时在按 `Variables` 解析的执行目录内执行一次命令，合并 stdout 与 stderr 写入唯一 `Text` 输出端口。Text 输入全部是路径变量端口，另需至少一个 `Signal` 触发。退出码非零、超时、路径越出工作区或无法启动时停在阻塞。

### 容器定义

容器组合执行节点并为子节点限定作用域，自身不执行。声明传入端口、输出端口与静态输入，构成封装边界。

| 字段      | 含义                                                                                   |
| --------- | -------------------------------------------------------------------------------------- |
| `Nodes`   | 有序子节点，至少一个                                                                   |
| `Inputs`  | 传入端口条目，静态输入写 `Mode: "Constant"`，成员用 `Static` 引用或 `From` 取内容     |
| `In`      | 传入端口绑定，端口名到当前作用域来源的映射，写在容器节点上                             |
| `Outputs` | 输出端口条目，写 `Name` 与可选 `Type`、`Mode`、`Value`、`Ref`；`Ref` 写 `成员@端口`    |

`In` 属于容器节点，内联容器与引用容器写在同一位置：内联容器绑定自身声明的 `Inputs`，引用容器绑定库定义声明的 `Inputs`。值写 `来源@端口` 或 `@更外层端口`，按容器所在作用域解析，根容器的 `In` 可以取 `Start@端口`。声明的传入端口必须全部给出绑定，未绑定的端口在导入流程时报错；根容器没有更外层作用域，`In` 只能取 `Start@端口`。库定义是模板，不写 `In`，绑定由引用处给出。

容器成员只引用本容器子树内的节点与容器声明的传入端口，容器外的节点与端口不可见。容器对外只暴露 `Outputs` 声明的端口，没有整份产出。容器不可声明执行配置、`Question`、`From` 与 `Emission`，也不接受任何类型参数。需要人工放行时在容器下游接审批节点。

容器输出与其他节点使用同一 `Outputs` 形状和同一输出来源模型。`Ref` 的来源可以是本节点静态输入或子树内成员的输出端口，常量性与类型必须一致；动态输出的触发模式由容器输出自身声明。`Type` 省略时按 `Text`。容器不执行，成员齐备时发布输出；动态输出转发成员产出，常量输出由 `Value` 或成员常量提供。容器输出使用 `Mode: "Trigger"` 时按成员产出的触发值门控下游，`Mode: "Plain"` 时容器输出恒触发。

## 端口

### 端口类型

| 类型      | 含义                                                         | 支持模式                 |
| --------- | ------------------------------------------------------------ | ------------------------ |
| `Text`    | 输出：模型交回命名段；输入：来源取值按序进入目标输入         | `Plain`、`Trigger`、`Constant` |
| `Context` | 输出：来源执行输入侧内容逐步保留出处；输入：置于目标输入最前 | `Plain`、`Constant`      |
| `Signal`  | 不承载内容，只通知下游                                       | `Plain`、`Trigger`、`Constant` |

端口类型只表达内容语义，模式由端口声明选择。类型注册声明支持的模式，端口写不支持的模式在导入时报错。`Signal` 未写模式时默认 `Trigger`，其他类型默认 `Plain`。`Trigger` 端口由模型交回触发值，省略为 `true`；不承载触发的端口触发值恒为 `true`。开始端口不能使用触发，`Context` 不能使用触发。常量端口的值统一以文本承载，语义只决定动态消费方式与静态内容的归属。

### 工具变量

工具声明路径变量名，节点用 `ToolPorts` 给出变量到输入端口的映射：

```json
"Inputs": [{ "Name": "任务路径", "Type": "Text", "Mode": "Constant" }],
"Static": { "任务路径": "@任务路径" },
"Tools": ["build"],
"ToolPorts": { "build": { "root": "任务路径" } }
```

规则：

- `ToolPorts` 的键是工具路径，按段前缀匹配，最长前缀生效。写 `git` 即覆盖整棵子树。
- 键必须匹配至少一个白名单放行的工具；匹配不到工具或只匹配白名单外的工具都在导入流程时报错。
- 映射的变量名必须与工具声明的路径变量完全一致，未知变量与缺变量都在导入流程时报错。
- 映射的端口必须在节点 `Inputs` 中声明且为 `Text`；映射到静态端口时值由 `Static` 绑定给出。
- 被白名单放行且没有路径变量的工具不写映射，写了映射在导入流程时报错。
- 工具没有默认映射，被白名单放行且带路径变量的工具缺少映射时导入流程报错；未映射的变量在调用时被拒绝。

### 输入端口

输入端口声明目标侧的输入名。`Inputs` 可省略，省略时 `From` 连接键按 `Text` 处理；声明后 `From` 每个组必须覆盖全部不带默认值的动态输入端口。输入端口可以声明 `Default`，静态端口未绑定时使用，动态 `Text` 端口未连接时进入执行输入。

### 输出端口与系统指令

`Outputs` 声明输出端口，执行节点由模型经 `SubmitPortValues` 交回动态 `Text` 与 `Signal` 端口，`Mode: "Trigger"` 的端口同时交回触发值；动态 `Context` 输出由来源透传，不需要模型交回。由执行产出的常量端口同样交回文本。未交回时同一执行内追问补交最多两次，仍缺才停在阻塞待返工。

`SystemPrompt` 声明系统指令块，按序拼接后整段作为请求的系统指令；声明块应是跨轮不变的约束，不要拼入动态值。

## 静态输入与常量输出

静态输入由 `Mode: "Constant"` 声明，不进入 `From`、版本与触发。常量端口是单值端口，任务内只确定一次，只供下游 `Static` 读取。开始端口的常量值在任务启动时确定；节点的常量输出可以写 `Value`、引用静态输入，或在 `Emission: "Once"` 下没有来源并由该节点执行产出。容器常量输出转发成员常量。

静态输入的来源可以是：

- 开始端口的 `Value`、宿主输入或提交输入。
- 任意常量输出的 `Value`。
- 常量输出对自身静态输入的 `Ref`。
- 容器常量输出对子树常量的 `Ref`。
- 节点在 `Emission: "Once"` 下唯一一次执行产出的常量输出。
- 静态输入端口的 `Default`。

静态绑定写 `Static` 对象，键是目标静态输入端口，值是 `Start@端口`、`@外层端口` 或 `容器@端口`。静态绑定不产生版本；绑定到任务启动时已确定的常量时不影响启动，绑定到运行期常量时该常量产出成为启动条件。`From` 只读取动态产出与版本，常量输出不进入 `From`。`Value` 本身不使端口成为常量端口，读取常量值需要 `Mode: Constant`。常量输出可以使用任意已注册语义；动态输出不能写 `Value`，非组织子节点的动态输出不能写 `Ref`，组织子节点的动态输出必须写 `Ref`。开始端口的固定值直接使用，绑定到宿主输入的端口取任务启动时给出的值，没有 `Value` 且未绑定宿主输入的常量端口取提交输入。静态输入端口可以是 `Text`、`Context` 或 `Signal`，`Context` 只能使用 `Plain` 与 `Constant`，`Signal` 常量只作为配置文本。`Emission: Once` 的节点声明一个或多个常量输出，不能有动态输入与 `From`，输入可以没有，首次成功发布后冻结。运行期常量依赖不能形成环。容器静态输入只由 `In` 绑定提供值，不能声明 `Default`。开始端口不能写 `Trigger`；容器输出可以使用 `Mode: Trigger`，只有为 true 时才把成员产出的触发值传给下游。

模型是 Llm 类型声明的静态输入端口 `MODEL_NAME`。标准写法是在开始端口声明 `MODEL_NAME` 并绑定宿主输入 `MODEL`，容器用静态输入经 `In` 转发，Llm 节点用 `Static` 绑定取同一个任务模型。需要在流程里固定模型时，也可以给常量开始端口写 `Value`。任务启动后模型不再变化；改变 `Runtime:Model` 只影响新任务与重建的内置对话任务。

环境路径 `WORKSPACE_PATH` 与 `TASK_WORK_PATH` 按同样方式声明、转发与绑定。文件与命令节点的路径变量、Llm 节点的工具变量映射到静态输入端口时，值来自该端口的 `Static` 绑定，执行时只读取静态输入值。执行节点的静态输入没有绑定且没有默认值时导入流程报错，容器静态输入必须由 `In` 绑定；宿主输入缺失时提交任务报错，不回退。

```json
"Start": { "Outputs": [
  { "Name": "目标", "Type": "Text", "Mode": "Constant" },
  { "Name": "MODEL_NAME", "Type": "Text", "Mode": "Constant" }
] },
"HostStartInputs": { "MODEL_NAME": "MODEL" },
"Nodes": [{
  "Name": "整体", "Kind": "Container",
  "Inputs": [
    { "Name": "目标", "Type": "Text", "Mode": "Constant", "Role": "Content" },
    { "Name": "MODEL_NAME", "Type": "Text", "Mode": "Constant" }
  ],
  "In": { "目标": "Start@目标", "MODEL_NAME": "Start@MODEL_NAME" },
  "Nodes": [{
    "Name": "撰写", "Kind": "Llm", "Emission": "Once",
    "Static": { "目标": "@目标", "MODEL_NAME": "@MODEL_NAME" },
    "Inputs": [{ "Name": "目标", "Type": "Text", "Mode": "Constant", "Role": "Content" }],
    "Outputs": [{ "Name": "结果", "Type": "Text", "Mode": "Constant" }]
  }]
}]
```

## 引用与接线

引用节点写 `Label`、`Use`，在引用处填写接线与静态输入绑定。

```json
{ "Label": "实施", "Use": "执行", "Static": { "MODEL_NAME": "Start@MODEL_NAME" } }
```

| 字段            | 含义                                                          |
| --------------- | ------------------------------------------------------------- |
| `Use`           | 引用的节点库定义名，引用容器时用 `In` 绑定静态与动态输入      |
| `Static`        | 引用执行节点时绑定定义声明的静态输入端口                      |
| `In`            | 引用容器时绑定定义声明的传入端口，写法见[容器定义](#容器定义) |
| `From`          | 仅引用执行节点时注入接线                                      |
| `Emission`      | 覆盖库定义的产出模式，取值 `Repeated` 或 `Once`               |
| `MaxExecutions` | 覆盖库定义的自身上限（执行节点）或组内统一上限（容器）        |

引用同一个容器定义多次必须给不同 `Label`。引用执行节点时，定义未给默认值的静态输入必须由 `Static` 绑定；引用容器时，`In` 必须绑定全部传入端口。引用容器不写 `Static`，容器对外只暴露 `Outputs` 声明的端口，下游消费写 `容器标签@端口`。常量输出只能被下游 `Static` 读取，不进入 `From`；运行期常量在该节点实例产出后可用。声明 `Emission: Once` 的库定义被引用时同样只发布一次。

## 上游接线

`From` 是执行节点的唯一接线字段，数组元素是一个启动组，组内是目标输入端口名到来源端口引用的映射。

```json
"From": [
  { "计划": "计划@结论" },
  { "计划": "评审@结论" }
]
```

组间任一齐备即启动，组内全部齐备。组内可省略带默认值的输入端口。来源可以是执行节点或容器：容器写 `容器标签@端口`，执行节点写 `来源@端口`。执行节点按来源的新产出判定启动，同一产出不重复启动；组内有信号输入时只由该组信号来源的新产出驱动。组内任一 Trigger 绑定取到 `false` 时该组不驱动启动。

容器成员的来源只落在本容器子树内，取容器传入内容写 `@端口`。容器成员的 `In` 与 `From` 同在一个作用域求值，容器外的节点与端口对成员不可见，跨边界传值一律经容器的 `In` 与 `@端口`。

## 输出校验

`Validate` 给执行节点一条输出校验规则：执行结束后按声明端口拼接出的文本判定，不通过则停在阻塞等待返工。

| 字段        | 含义                                                           |
| ----------- | -------------------------------------------------------------- |
| `Predicate` | `NonEmpty`、`TextContains`、`TextNot`、`TextEquals`、`Pattern` |
| `Argument`  | 谓词参数，`NonEmpty` 不需要                                    |

声明 `Validate` 的节点必须声明至少一个可交回的产出端口。执行节点引用可以互相指回构成环，环必须有环外来源或环内输入节点才能启动，收敛由输出校验或 `MaxExecutions` 兜底。

## 关键约束

导入或启动时逐条校验，非法项一次给出。要点：

- 每条流程有且只有一个根节点，必须声明 `Start`，至少一个不带 `Value` 的 `Text` 端口；`HostStartInputs` 的键必须是已声明的开始端口，绑定端口不能带 `Value`，宿主输入名不能为空。常量开始端口没有 `Value` 且未绑定宿主输入时由提交输入给值。
- 每个会执行的节点都必须能从开始或静态输入启动条件到达。全静态输入或没有输入且没有 `From` 的执行节点在静态输入就绪后执行；绑定到运行期常量时等待该常量产出。
- 节点名与标签不能为空、不能含 `@` 与 `/`、不能用保留的 `Start`，同一容器内唯一，库定义名库内唯一。
- `Kind` 必填且取值必须是支持的节点类型；引用节点不写执行配置、子节点、`Inputs` 与 `Validate`。
- 端口名在同一节点内唯一，端口类型必须是支持的端口类型，模式必须是该类型注册支持的模式；`From` 每个组覆盖全部不带默认值的动态输入端口，来源必须存在。`Llm`、`Input`、`Approval` 接受未声明的 `From` 目标并按 `Text` 内容输入处理，其他类型要求目标已声明。
- `Trigger` 只用于动态 `Text` 与 `Signal` 端口。开始端口、`Context` 端口与常量端口不能使用触发。承载触发的输出在交回时给触发值，承载触发的输入在来源触发值为 false 时抑制所在启动组。
- 所有节点的输出条目使用同一形状，`Type` 省略时按 `Text`，`Mode` 省略时按类型默认模式。`Value` 与 `Ref` 互斥，常量输出接受 `Value`、常量来源，或在 `Emission: Once` 下没有来源并由执行产出。动态输出不接受 `Value`，非组织子节点的动态输出不接受 `Ref`。`Emission: Once` 的节点只声明常量输出，至少一个运行期常量，不能有动态输入与 `From`，可以声明多个常量输出。
- 容器输出转发成员端口时，常量性与类型必须一致，动态输出的触发模式由容器输出声明。常量输出只能作为 `Static` 来源，动态输出只能作为 `From` 来源。
- 静态输入绑定到运行期常量时，目标节点等待该常量产出后再启动；常量依赖不能形成环。
- `Once` 节点发布后冻结，不再参与返工；未发布的阻塞节点可以重试与返工。其余节点保持原有返工语义。
- 执行节点必须由静态输入端口 `MODEL_NAME` 得到值，静态来源可以是开始端口、容器输入或任意常量输出，引用的库定义必须存在。标准来源是宿主输入 `MODEL`。
- 容器成员的 `From` 与容器的 `In` 都在所属容器作用域里求值：来源只落在该容器子树内的节点或该容器声明的传入端口，容器外的节点与端口不可见。
- 开始端口只在流程作用域出现，写在根节点的 `From` 或根容器的 `In` 里，容器成员不能直接引用。
- 同一执行节点的执行次数达到 `MaxExecutions` 上限后不再启动。
