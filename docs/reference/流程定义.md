# 流程定义

节点库存工作目录 `.kuroe/` 的 `nodes.json`，流程模板存 `flows.json`，宿主给值的开始端口存 `hostStartInputs.json`，三个文件都可以手工编辑，文件不存在时对应部分为空。导入或启动时校验流程与节点库，非法项一次给出。完整示例见[流程示例](流程示例.md)。

## 文件结构

`nodes.json` 存放可复用的节点库，顶层只写 `Nodes`：

```json
{
  "Nodes": [ { "Name": "库节点名", "Kind": "Llm" } ]
}
```

`flows.json` 存放流程，顶层只写 `Flows`：

```json
{
  "Flows": [
    {
      "Name": "流程名",
      "Description": "可选说明",
      "Ports": [ { "Name": "目标", "Type": "Text" } ],
      "Root": { "Name": "根节点名", "Kind": "Llm" }
    }
  ]
}
```

节点文件只写 `Nodes`，流程文件只写 `Flows` 且每条流程的根节点写在 `Root`。每条流程有且只有一个根节点，根节点可以是执行节点或容器。

## 节点库

`nodes.json` 的顶层 `Nodes` 定义可复用的节点，供流程内写 `Use` 引用。内置节点是执行节点「规划」「执行」与容器「交付」，与文件定义同名时以文件定义覆盖。

| 名称   | 类型        | 输入                 | 行为                                                |
| ------ | ----------- | -------------------- | --------------------------------------------------- |
| `规划` | `Llm`       | `目标`、`MODEL_NAME` | 提示词要求把目标写成可实施的计划，输出端口 `计划`   |
| `执行` | `Llm`       | `任务`、`MODEL_NAME` | 按计划实施，工具白名单只有 `GetLocalTime`           |
| `交付` | `Container` | `计划`、`MODEL_NAME` | 成员 `实施` 引用 `执行`，把 `计划` 接到 `任务` 输入 |

- 执行节点定义声明输入端口、输出端口、工具白名单与类型参数，不写接线与 `Bindings`。
- 容器定义用 `Nodes` 组织有序成员，用 `Inputs` 声明传入端口，用 `Outputs` 声明对外端口。

## 开始入口

流程开始端口写在顶层 `Ports`，不是节点，也不进入节点树。每个端口与其他节点使用同一端口条目：`Type` 省略时按 `Text`，`Mode` 省略时按类型默认模式。`Ports` 可以省略或为空。

- 动态端口只能是 `Text` 或 `Signal`，常量端口可以使用任意已注册语义。
- 不带 `Value`、承载内容且未由宿主给值的端口在提交任务时逐个给值，值在任务启动时确定。不承载内容的开始端口不进入提交。
- 带 `Value` 的端口是固定输出。
- 带 `Default` 的承载内容端口仍是提交输入，`Default` 是输入表的预填值与省略时的回退值，不能为空白。该端口由宿主给值时 `Default` 不再生效。
- `Default` 只用于承载内容的开始端口，不承载内容的开始端口不能写 `Default`。
- 不承载内容的常量开始端口必须写 `Value`。
- `Signal` 默认 `Plain`，不承载内容，任务启动时自动放行，不进入提交。
- `Value` 与 `Default` 不能同时写。
- 常量端口只能被下游 `Bindings` 读取，不进入 `From`。
- 开始端口不能使用触发，`Signal` 端口只能使用 `Plain` 或 `Constant`。

```json
{ "Name": "分支", "Type": "Text", "Default": "main" }
```

流程只声明开始端口，哪些开始端口由宿主给值写在 `.kuroe/hostStartInputs.json`，不进入流程文件与流程模型。端口名不受宿主输入名约束，表的结构、规则与校验见[宿主开始输入](宿主开始输入.md)。

开始端口不属于任何容器，只在流程作用域可见：根节点的 `From` 与根容器的 `From`、`Bindings` 用 `@端口` 取用，容器成员经容器传入端口取用。

```json
"Ports": [
  { "Name": "目标", "Type": "Text" },
  { "Name": "启动路径", "Type": "Text", "Mode": "Constant" }
]
```

节点声明静态输入 `启动路径`，用 `Bindings: { "启动路径": "@启动路径" }` 取用；节点在容器内时由容器的静态输入经 `Bindings` 转发。`启动路径` 在宿主开始输入表里绑定 `WORKSPACE_PATH` 时由 Kuroe 给值。任务目录见[任务与执行](../usage/任务与执行.md#任务数据)。

## 节点

文件必须显式写 `Kind`，取值与各类型字段见[节点](nodes/index.md)。

节点的 `Outputs` 声明输出端口；类型给出输出端口时不写 `Outputs`，端口由类型给出。

共用结构字段：

| 字段            | 含义                                                                |
| --------------- | ------------------------------------------------------------------- |
| `Name`          | 定义名，同一容器内唯一，不能为空，不能含 `@` 与 `/`                 |
| `Label`         | 引用节点在图里的标识段，同一容器内唯一，不能为空，不能含 `@` 与 `/` |
| `Kind`          | 节点类型，定义必填，引用不写                                        |
| `Bindings`      | 输入绑定，静态输入端口到来源引用                                    |
| `From`          | From 连接：执行节点按组启动，容器作为传入端口接线                   |
| `Emission`      | 产出模式，`Repeated` 逐次发布，`Once` 首次发布后冻结                |
| `MaxExecutions` | 执行或发布次数上限，执行节点未写时 100，容器未写时没有上限          |

没有 `Use` 的条目是定义，写 `Name`；有 `Use` 的条目是引用，写 `Label`。定义条目的标签取节点名。

类型参数与结构字段同级写在节点对象里，引用节点不写，字段见各节点页。

## 执行节点

执行节点按类型执行：`Llm` 调用模型，`Command`、`FileRead`、`FileWrite` 执行外部动作。`Inputs` 声明输入端口，`Outputs` 声明输出端口，`From` 连接上游，`Bindings` 绑定静态输入。

输入端口写 `Name` 与可选 `Type`、`Mode`、`Description`、`Default`、`Role`。`Role` 取 `Content`、`Configuration` 或 `Control`，分别表示执行内容、按名配置与只作触发；未写时，常量端口按 `Configuration`，动态 `Signal` 端口按 `Control`，其余按 `Content`。

`Llm`、`Input`、`Approval` 接受 `From` 引入的未声明 `Text` 输入，其他类型要求目标已在 `Inputs` 声明。输入按上游发布原样装配，引擎不截断。

执行节点在输入全部静态或没有输入且没有 `From` 时，静态输入就绪后执行；绑定到运行期常量时等待该常量产出。

`Emission: Once` 的节点只声明常量输出，至少一个由执行产出，不能声明动态输入与 `From`。首次成功发布后冻结，发布前可以失败重试与重新执行，`MaxExecutions` 是尝试上限。`Repeated` 节点不能声明没有 `Value` 与 `Ref` 的常量输出。

节点结束时经契约工具 `SubmitPortValues` 交回动态端口与由执行产出的常量端口，`Context` 输出由来源透传，不需要交回。另附 `GetStatus` 与 `ReportCannotComplete`，见[契约工具](tools/contract.md)。未交回时同一执行内追问最多两次，仍缺则停在阻塞等待重新执行。

恢复继承来源执行已交回的端口与无法完成原因，是否允许恢复由节点类型判断，见[任务与执行](../usage/任务与执行.md#暂停与恢复)。

## 容器

容器组合成员并限定作用域，自身不执行，对外只暴露 `Outputs` 声明的端口。成员、传入端口、绑定与发布规则见[容器](nodes/container.md)。

## 引用与接线

引用节点写 `Label` 与 `Use`，在引用处填写接线与输入绑定。

```json
{ "Label": "实施", "Use": "执行", "Bindings": { "MODEL_NAME": "@MODEL_NAME" } }
```

| 字段            | 含义                             |
| --------------- | -------------------------------- |
| `Use`           | 引用的节点库定义名               |
| `Bindings`      | 静态输入与容器静态传入端口的绑定 |
| `From`          | 动态输入与容器动态传入端口的连接 |
| `Emission`      | 覆盖库定义的产出模式             |
| `MaxExecutions` | 覆盖库定义的上限                 |

引用同一个容器定义多次必须给不同 `Label`。引用执行节点时，定义未给默认值的静态输入必须绑定。引用容器时，静态传入端口由 `Bindings` 绑定，动态传入端口写在唯一一组 `From`，下游用 `容器标签@端口` 消费。`Emission: Once` 的库定义被引用时同样只发布一次。

## 上游接线

`From` 是所有节点的动态输入接线字段，数组元素是一组连接，组内是目标输入端口到来源端口的映射。执行节点按组启动，容器只写一组，作为成员的传入端口绑定方案。

```json
"From": [
  { "计划": "计划@结论" },
  { "计划": "评审@结论" }
]
```

组间任一齐备即启动，组内全部齐备。来源写 `执行节点@端口` 或 `容器标签@端口`。执行节点按来源的新产出判定启动，同一产出不重复启动。组内有信号输入时只由该组信号来源的新产出驱动。控制输入不承载内容，未出现在某个组里时不影响该组。

`Trigger` 连接的发送条件写在 `From` 连接处。值是引用文本时按 `Positive`，来源触发值为 `true` 时放行。需要翻转时把值写成对象：

```json
"From": [
  { "否决": { "Ref": "评审@结论", "Condition": "Negative" } }
]
```

`Negative` 表示来源触发值为 `false` 时放行、`true` 时抑制该组。条件只作用于这条绑定所在的组，不改变来源产出，也不影响同一来源的其他下游。来源端口必须是触发端口。

容器成员的来源只落在本容器子树内，取容器传入内容写 `@端口`。

## 端口与模式

| 类型      | 含义                                                         | 支持模式                       |
| --------- | ------------------------------------------------------------ | ------------------------------ |
| `Text`    | 输出：模型交回命名段；输入：来源取值按序进入目标输入         | `Plain`、`Trigger`、`Constant` |
| `Context` | 输出：来源执行输入侧内容逐步保留出处；输入：置于目标输入最前 | `Plain`、`Constant`            |
| `Signal`  | 不承载内容，只通知下游                                       | `Plain`、`Trigger`、`Constant` |

`Plain` 是普通动态端口，`Trigger` 交回时携带触发值并门控启动组，`Constant` 在任务内只确定一次值。端口类型只表达内容语义，写不支持的模式在导入时报错。所有类型未写 `Mode` 时默认 `Plain`，需要门控时显式写 `Trigger`。开始端口与 `Context` 不能使用触发，容器输入可以使用触发，触发只门控容器发布，不驱动发布。所有输出条目的 `Type` 省略时按 `Text`，`Mode` 省略时按类型默认模式。

门控条件属于 `From` 连接，不属于端口声明。同一条来源可以被不同下游以不同条件连接。`Negative` 只能写在触发端口上，来源端口也必须是触发端口，未写时按 `Positive`。`Bindings` 只写引用文本，不写 `Condition`。

## 工具变量

工具声明路径变量名，节点用 `ToolPorts` 给出变量到输入端口的映射：

```json
"Inputs": [{ "Name": "任务路径", "Type": "Text", "Mode": "Constant" }],
"Bindings": { "任务路径": "@任务路径" },
"Tools": ["build"],
"ToolPorts": { "build": { "root": "任务路径" } }
```

- `ToolPorts` 的键按工具路径段前缀匹配，最长前缀生效，写 `git` 覆盖整棵子树。
- 键必须匹配至少一个白名单放行的工具。
- 变量名必须与工具声明的路径变量一致。
- 映射的端口必须在 `Inputs` 中声明且为 `Text`；映射到静态端口时值由 `Bindings` 给出。
- 被白名单放行且带路径变量的工具必须完整映射，否则导入报错；没有变量的工具不写映射。

## 静态输入与常量输出

静态输入由 `Mode: Constant` 声明，任务内只确定一次值，只供下游 `Bindings` 读取。来源可以是：

- 开始端口的 `Value`、宿主给值或提交输入
- 任意常量输出的 `Value`
- 常量输出对自身静态输入的 `Ref`
- 容器常量输出对子树常量的 `Ref`
- `Emission: Once` 节点执行产出的常量输出
- 静态输入端口的 `Default`

输入绑定写 `Bindings`，值是 `@开始端口`、`@外层端口` 或 `容器@端口`，只用于静态输入。动态输入写在 `From`，容器的动态传入端口写在唯一一组 `From`，触发连接可以写 `Condition`。绑定到运行期常量时，该常量产出成为启动条件；常量依赖不能形成环。`From` 只读取动态产出，常量输出不进入 `From`。

执行节点的静态输入没有绑定且没有默认值时导入报错，容器静态输入必须由 `Bindings` 绑定。宿主输入在提交任务时缺失或与开始入口不一致时报错。

执行节点的模型来自静态输入端口 `MODEL_NAME`。标准写法是在开始端口声明一个常量端口，在宿主开始输入表里把它绑定到 `MODEL`，容器经 `Bindings` 转发，执行节点用 `Bindings` 取用。需要在流程里固定模型时，给常量开始端口写 `Value`，该端口不进宿主开始输入表。任务启动后模型不再变化，见[模型接入](../usage/模型接入.md)。

## 路径与任务目录

`WORKSPACE_PATH` 与 `TASK_WORK_PATH` 按模型同样的方式声明、转发与绑定。文件节点的 `Path` 与命令节点的 `Directory`、`Arguments` 用 `Variables` 把变量映射到静态 `Text` 输入端口，`root` 变量是相对路径的基准，解析结果必须落在工作区根内。在宿主开始输入表里把某个开始端口绑定到 `TASK_WORK_PATH` 并转发到节点，再把 `Path` 或 `Directory` 写成 `{root}/...`，路径就落在本次任务目录下，绑定写法见[宿主开始输入](宿主开始输入.md)。

Llm 节点的工具用 `ToolPorts` 把 `root` 映射到 `TASK_WORK_PATH`，工具即以任务目录为基准。任务目录见[任务与执行](../usage/任务与执行.md#任务数据)。

## 关键约束

- 每条流程有且只有一个根节点，写在 `Root`。`Ports` 可以省略或为空。
- 流程文件与流程模型不含宿主输入绑定；宿主开始输入表的键必须是已声明的 `Text` 开始端口，绑定端口不能带 `Value`，宿主输入名必须是受支持的名字。
- 每个会执行的节点都必须能从开始端口、静态输入启动条件或自身静态输入到达。
- 节点名与标签不能为空、不能含 `@` 与 `/`，同一容器内唯一，库定义名库内唯一。
- `Kind` 必填且必须是支持的类型；引用节点不写执行配置、子节点与 `Inputs`。
- 端口名在同一节点内唯一，类型与模式必须是支持组合；`From` 覆盖动态输入，执行节点只要求不带默认值的动态内容输入，控制输入不要求每组覆盖，容器要求全部动态输入；`Bindings` 只绑定静态输入，来源必须存在。
- `Trigger` 只用于动态 `Text` 与 `Signal` 端口，开始端口、`Context` 端口与常量端口不能使用触发。
- 容器只写一组 `From`。`From` 条件只用于触发端口，来源端口必须是触发端口，`Condition` 未写时按 `Positive`，`Negative` 表示来源触发值为 `false` 时放行。
- `Value` 与 `Ref` 互斥。动态输出不接受 `Value`，非组织子节点的动态输出不接受 `Ref`。
- 需要模型的执行节点必须由静态输入端口 `MODEL_NAME` 得到值，引用的库定义必须存在。
- 容器成员的命名来源限制在本容器子树与传入端口，`@端口` 在所属容器作用域求值。容器自身的 `From` 与 `Bindings` 在父作用域求值，根容器因此可以取 `@开始端口`。
- 执行节点引用可以构成环，环必须有环外来源或环内输入节点才能启动，收敛由 `MaxExecutions` 兜底。
- 达到 `MaxExecutions` 的节点或容器不再启动或发布。
