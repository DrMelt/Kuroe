# 流程定义

流程模板存在工作目录 `.kuroe/` 的 `flows.json`，可以手工编辑，文件不存在时流程库为空。文件由 JSON 层读成描述，再由编译器装配成执行视图。节点字段见[节点](#节点)，引用与接线见[引用与装配](#引用与装配)。

## 文件结构

```json
{
  "Nodes": [ { "Name": "库节点名", "Kind": "Llm", "...": "..." } ],
  "Flows": [
    {
      "Name": "流程名",
      "Description": "可选说明",
      "Start": { "Outputs": [ { "Name": "目标", "Type": "Text" } ] },
      "Nodes": [ { "Name": "根容器名", "Kind": "Container", "Nodes": [] } ]
    }
  ]
}
```

顶层 `Nodes` 是可复用的节点库，`Flows` 是流程，每条流程有且只有一个根节点。

## 节点库

顶层 `Nodes` 是节点定义，作复用单元供流程引用。定义有两个来源：程序内置节点随启动提供，文件顶层 `Nodes` 定义自定义节点，两者同名合并，以文件定义覆盖。内置节点是执行节点「规划」「执行」与容器「交付」。

两种定义：

- 执行节点定义：声明输入端口、输出端口、工具白名单与执行方式，不写接线。
- 容器定义：`Nodes` 子数组组织一组有序成员，`Inputs` 声明传入端口，`Outputs` 声明对外端口。

库定义只声明能力，接线与静态值由装配层输入。执行节点的模型是静态输入端口 `MODEL_NAME`，值由宿主在任务启动时经开始输入 `MODEL` 给出。

## 开始入口

`Start` 声明流程唯一的来源节点，名与标签都是保留的 `Start`：`Outputs` 条目写 `Name`、`Type` 与可选 `Value`、`Static`，`Type` 只能是 `Text`。至少一个端口不带 `Value`。不带 `Value` 的端口在提交任务时逐个给输入，也可由流程级 `HostStartInputs` 绑定到宿主输入；带 `Value` 的端口是写死的固定输出。`Static: true` 的端口只供节点的 `Static` 绑定读取，不进入 `From`，其值来自 `Value` 或宿主输入。开始节点不属于任何容器，只在流程作用域可见：根节点的 `From` 与根容器的 `In` 用 `Start@端口` 取用，容器成员经容器的传入端口取用。

流程级 `HostStartInputs` 把开始端口绑定到宿主输入名：键是 `Start.Outputs` 已声明的端口，值由宿主解释。绑定端口的值在任务启动时由宿主给出，不接受提交输入，也不能带 `Value`。Kuroe 提供三个宿主输入：`WORKSPACE_PATH` 是 `-d` 给出的工作区根目录绝对路径，未指定时为进程当前目录；`TASK_WORK_PATH` 是本次任务目录的绝对路径；`MODEL` 是任务启动时当前选中的模型名。流程示例：

```json
"Start": {
  "Outputs": [
    { "Name": "目标", "Type": "Text" },
    { "Name": "启动路径", "Type": "Text", "Static": true }
  ]
},
"HostStartInputs": { "启动路径": "WORKSPACE_PATH" }
```

节点声明静态输入 `启动路径`，用 `Static: { "启动路径": "Start@启动路径" }` 取用；节点在容器内时由容器的静态输入经 `In` 转发。任务目录见[安装与运行](../usage/安装与运行.md#任务目录)。

## 节点

节点类型名由程序定义，文件必须显式写 `Kind`，取值 `Container`、`Llm`、`FileRead`、`FileWrite`、`Command`、`Input`、`Approval`。`Container` 由引擎提供，其余由装配处注册。

| 类型                     | 作用                                                  |
| ------------------------ | ----------------------------------------------------- |
| `Container`              | 组合成员并限定作用域                                  |
| `Llm`                    | 由模型执行                                            |
| `FileRead` / `FileWrite` | 以 `Variables` 映射路径变量并读取 / 写入文件          |
| `Command`                | 以 `Variables` 映射执行目录并执行命令，把输出作为产出 |
| `Input`                  | 等用户回答                                            |
| `Approval`               | 等用户批准                                            |

共用结构字段：

| 字段            | 含义                                                                            |
| --------------- | ------------------------------------------------------------------------------- |
| `Name`          | 节点名，定义条目的名字，同一容器内唯一且不能为空，不能含 `@` 与 `/`             |
| `Label`         | 节点标签，被使用节点在图里的标识段，同一容器内唯一且不能为空，不能含 `@` 与 `/` |
| `Kind`          | 节点类型名，必填；引用节点不写                                                  |
| `MaxExecutions` | 执行次数上限，见各节点类型                                                      |

`Nodes` 里的条目分两种：没有 `Use` 的是节点定义，写 `Name`；有 `Use` 的是被使用的节点，必须写 `Label`。定义条目的标签取节点名的文本，节点在图里统一以标签标识。

## 执行节点

执行节点是唯一派发模型执行的节点，由以下结构字段描述。

| 字段            | 含义                                                          |
| --------------- | ------------------------------------------------------------- |
| `Static`        | 静态端口绑定，目标静态输入端口到来源引用，模型与路径端口都用它 |
| `Inputs`        | 输入端口表，写 `Name` 与可选 `Type`、`Description`、`Default` |
| `Outputs`       | 输出端口表，写 `Name` 与 `Type`                               |
| `From`          | 上游启动组，见[上游接线](#上游接线)                           |
| `Validate`      | 输出校验，见[输出校验](#输出校验)                             |
| `MaxExecutions` | 最高执行次数，未写继承最近容器统一配置，最后默认 100          |

执行的上下文由上游装配后传入，不继承未声明的内容。执行节点在收口时交回 `Outputs` 声明的全部端口，模型经契约工具 `SubmitPortValues` 交回；每个执行节点还附 `GetStatus` 与 `ReportCannotComplete` 上报本轮状态。契约工具见[内置工具](内置工具.md#契约工具)。

## 类型参数

类型专属声明与结构字段同级写在节点对象里，引用节点不声明类型参数。

| 参数             | 类型     | 归属                         | 含义                                                                                         |
| ---------------- | -------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| `Prompt`         | string   | Llm                          | 对本次执行的额外要求，构成本轮指令                                                           |
| `Tools`          | string[] | Llm                          | 能力工具白名单，按工具路径前缀匹配，写上级路径放行整棵子树，见[工具配置](工具配置.md#工具面) |
| `ToolPorts`      | object   | Llm                          | 工具路径到路径变量映射的对象，键可按工具路径前缀匹配，见[工具变量](#工具变量)                |
| `SystemPrompt`   | string[] | Llm                          | 恒定系统指令块                                                                               |
| `Question`       | string   | Input、Approval              | 等待型节点的提示文本                                                                         |
| `Path`           | string   | FileRead、FileWrite          | 可含 `{变量}` 的文件路径，变量由 `Variables` 映射到输入端口                                  |
| `Variables`      | object   | FileRead、FileWrite、Command | 路径变量名到 `Text` 输入端口的映射，键必须与 `Path` 或 `Directory` 的占位符一一对应          |
| `MaxChars`       | int      | FileRead、FileWrite、Command | 单次读写或命令输出的字符上限，0 不限制；读取与命令未写 8000，写入未写不限制                  |
| `Program`        | string   | Command                      | 要执行的程序名或路径，必填                                                                   |
| `Arguments`      | string[] | Command                      | 传给程序的参数，不经 shell 解释                                                              |
| `Directory`      | string   | Command                      | 命令执行目录，可含 `{变量}`；未写时执行目录即 `root` 变量或工作区根                          |
| `TimeoutSeconds` | int      | Command                      | 命令等待上限秒数，未写 120                                                                   |

文件与命令节点用 `Variables` 声明路径变量到 `Text` 输入端口的映射。静态端口用 `Static` 绑定取来源，动态端口在每组 `From` 里连接。`Path` 与 `Directory` 的占位符必须由 `Variables` 完整覆盖，映射端口必须已声明且为 `Text`。文件读取节点的 Text 输入必须全部是路径变量端口；文件写入节点恰好有一个未被映射的 Text 内容端口；命令节点没有内容端口。路径变量值按工作区根解析，`root` 变量作为相对路径的基准，解析结果必须落在工作区根内。

## 节点类型

### 输入节点

`Kind: Input` 不启动执行、没有模型静态输入：收到上游通知后停在待输入，回答写入唯一输出端口。只声明 `Question`，输入端口取 `Text` 或 `Signal`，输出至多一个 `Text` 端口。

### 审批节点

`Kind: Approval` 不启动执行：输入齐备后停在待批准，停驻时的输入取值与触发值在放行后按同名输出端口放出。只声明 `Question`，对外端口由自身 `Inputs` 派生。

### 文件读取节点

`Kind: FileRead` 不启动执行：`From` 任一组齐备且来源有新版本时按 `Variables` 解析 `Path` 并读取文件，内容写入唯一 `Text` 输出端口。Text 输入全部是路径变量端口，另需至少一个 `Signal` 触发。文件不存在、路径越出工作区或读取失败时停在阻塞。

### 文件写入节点

`Kind: FileWrite` 不启动执行：把唯一未被映射的内容 `Text` 输入覆盖写入按 `Variables` 解析的 `Path` 指向的文件，路径变量端口与 `Signal` 触发可以有多个。输出端口可省略，也可声明一个：`Text` 给出写入内容，`Signal` 只表示写入完成。路径越出工作区或写入失败时停在阻塞。

### 命令执行节点

`Kind: Command` 不启动模型执行：`From` 任一组齐备且来源有新版本时在按 `Variables` 解析的执行目录内执行一次命令，合并 stdout 与 stderr 写入唯一 `Text` 输出端口。Text 输入全部是路径变量端口，另需至少一个 `Signal` 触发。退出码非零、超时、路径越出工作区或无法启动时停在阻塞。

### 容器定义

容器组合执行节点并为子节点限定作用域，自身不执行。声明传入端口、输出端口与静态端口，构成封装边界。

| 字段      | 含义                                                                                  |
| --------- | ------------------------------------------------------------------------------------- |
| `Nodes`   | 有序子节点，至少一个                                                                  |
| `Inputs`  | 传入端口条目，静态输入写 `Static: true`，成员用 `Static` 引用或 `From` 取内容         |
| `In`      | 传入端口绑定，端口名到当前作用域来源的映射，写在容器节点上                            |
| `Outputs` | 命名输出端口条目，写 `Name` 与 `Ref`，`Ref` 写 `成员@端口`；静态输出写 `Static: true` |

`In` 属于容器节点，内联容器与引用容器写在同一位置：内联容器绑定自身声明的 `Inputs`，引用容器绑定库定义声明的 `Inputs`。值写 `来源@端口` 或 `@更外层端口`，按容器所在作用域解析，根容器的 `In` 可以取 `Start@端口`。声明的传入端口必须全部给出绑定，未绑定的端口是装载错误；根容器没有更外层作用域，`In` 只能取 `Start@端口`。库定义是模板，不写 `In`，绑定由引用处给出。

容器成员只引用本容器子树内的节点与容器声明的传入端口，容器外的节点与端口不可见。容器对外只暴露 `Outputs` 声明的端口，没有整份产出。容器不可声明执行配置、`Question` 与 `From`，也不接受任何类型参数。需要人工放行时在容器下游接审批节点。

## 端口

### 端口类型

| 类型            | 含义                                                         |
| --------------- | ------------------------------------------------------------ |
| `Text`          | 输出：模型交回命名段；输入：来源取值按序进入目标输入         |
| `TextTrigger`   | 与 `Text` 相同文本语义，另带是否触发下游的布尔值             |
| `Context`       | 输出：来源执行输入侧内容逐步保留出处；输入：置于目标输入最前 |
| `Signal`        | 不承载内容，只以发布版本驱动下游                             |
| `SignalTrigger` | 与 `Signal` 相同驱动语义，另带是否触发下游的布尔值           |

端口类型注册时自动产生普通版与 Trigger 版。普通端口触发值恒为 `true`，Trigger 版由模型交回，省略为 `true`。

### 工具变量

Llm 节点的工具在每次执行时按执行上下文创建。工具定义声明路径变量名，节点用 `ToolPorts` 给出变量到输入端口的映射：

```json
"Inputs": [{ "Name": "任务路径", "Type": "Text", "Static": true }],
"Static": { "任务路径": "@任务路径" },
"Tools": ["build"],
"ToolPorts": { "build": { "root": "任务路径" } }
```

规则：

- `ToolPorts` 的键是工具路径，按段前缀匹配，最长前缀生效。写 `git` 即覆盖整棵子树。
- 键必须匹配至少一个白名单放行的工具；匹配不到工具或只匹配白名单外的工具都是装载错误。
- 映射的变量名必须与工具定义声明的 `PathVariables` 完全一致，未知变量与缺变量都在装载时报错。
- 映射的端口必须在节点 `Inputs` 中声明且为 `Text`；映射到静态端口时值由 `Static` 绑定给出。
- 被白名单放行且没有路径变量的工具不写映射，写了映射是装载错误。
- 工具没有默认映射，被白名单放行且带路径变量的工具缺少映射时装载失败。运行期仍保留防御性错误。

### 路径变量迁移

旧的文件与命令节点用 `BasePath` 输入端口作为路径基准。新写法改为 `Variables` 映射，`Path` 与 `Directory` 用 `{变量}` 引用：

| 旧写法                                     | 新写法                                                        |
| ------------------------------------------ | ------------------------------------------------------------- |
| `Inputs: [{ "Name": "BasePath" }]`         | `Inputs: [{ "Name": "任务路径", "Static": true }]`              |
| `From: [{ "BasePath": "Start@流程路径" }]` | `Static: { "任务路径": "Start@流程路径" }`                     |
| `Path: "result.md"`                        | `Variables: { "root": "任务路径" }, Path: "{root}/result.md"` |
| `Directory: "src"`                         | `Variables: { "root": "任务路径" }, Directory: "{root}/src"`  |
| `tools.json` 不写变量                      | `Variables: ["root"], Directory: "{root}/src"`                |
| Llm `Tools: ["git"]`                       | 增加 `ToolPorts: { "git": { "root": "工作区" } }`             |
| 文件工具默认工作区根                       | 节点声明路径端口并给出映射                                    |

### 输入端口

输入端口声明目标侧的输入名。`Inputs` 可省略，省略时 `From` 连接键按 `Text` 处理；声明后 `From` 每个组必须覆盖全部不带默认值的输入端口。派发执行的节点可以为普通 `Text` 输入端口声明 `Default`，未连接时进入执行输入。

### 输出端口与系统指令

`Outputs` 声明输出端口，派发执行的节点由模型经 `SubmitPortValues` 交回 `Text`、`TextTrigger`、`Signal`、`SignalTrigger` 端口；`Context` 输出由来源透传，不需要模型交回。未交回时同一执行内追问补交最多两次，仍缺才停在阻塞待返工。

`SystemPrompt` 声明系统指令块，按序拼接后整段作为请求的系统指令；声明块应是跨轮不变的约束，不要拼入动态值。

## 静态端口

静态端口是只提供值、不参与版本与触发的端口。`Inputs` 条目写 `Static: true` 声明静态输入，`Outputs` 条目写 `Static: true` 声明静态输出。静态来源必须是静态端口：

- 开始端口的 `Value`。
- 开始端口绑定的宿主输入。
- 容器静态输入，经 `In` 绑定。
- 容器静态输出。
- 执行节点静态输入端口的 `Default`。

静态绑定写 `Static` 对象，键是目标静态输入端口，值是 `Start@端口`、`@外层端口` 或 `容器@端口`。静态绑定不进入 `From`，不产生版本，不参与就绪与触发。`Value` 本身不使端口成为静态端口，读取静态值需要 `Static: true`。静态绑定在编译视图保留为来源引用，运行期沿绑定链取值；开始端口的固定值直接使用，绑定到宿主输入的端口取任务启动时注入的值。静态输入端口只允许 `Text`，静态开始端口必须有 `Value` 或宿主输入绑定。容器静态输入只由 `In` 绑定提供值，不能声明 `Default`。

模型是 Llm 类型声明的静态输入端口 `MODEL_NAME`。标准写法是在开始端口声明 `MODEL_NAME` 并绑定宿主输入 `MODEL`，容器用静态输入经 `In` 转发，Llm 节点用 `Static` 绑定取同一个任务模型。需要在流程里固定模型时，也可以给静态开始端口写 `Value`。任务启动后模型不再变化；改变 `Runtime:Model` 只影响新任务与重建的内置对话任务。

环境路径 `WORKSPACE_PATH` 与 `TASK_WORK_PATH` 按同样方式声明、转发与绑定。文件与命令节点的路径变量、Llm 节点的工具变量映射到静态输入端口时，值来自该端口的 `Static` 绑定，运行期不读取动态输入。执行节点的静态输入没有绑定且没有默认值时装载报错，容器静态输入必须由 `In` 绑定；宿主值缺失时提交任务报错，不回退。

旧版流程文件的 `Models`、`Model` 与 `ModelSlots` 字段不再识别，装载会报未知字段。旧定义需改写为开始端口的静态端口、容器静态输入与节点的 `Static` 绑定。

```json
"Start": { "Outputs": [
  { "Name": "目标", "Type": "Text" },
  { "Name": "MODEL_NAME", "Type": "Text", "Static": true }
] },
"HostStartInputs": { "MODEL_NAME": "MODEL" },
"Nodes": [{
  "Name": "整体", "Kind": "Container",
  "Inputs": [{ "Name": "目标" }, { "Name": "MODEL_NAME", "Type": "Text", "Static": true }],
  "In": { "目标": "Start@目标", "MODEL_NAME": "Start@MODEL_NAME" },
  "Nodes": [{
    "Name": "撰写", "Kind": "Llm",
    "Static": { "MODEL_NAME": "@MODEL_NAME" },
    "From": [{ "目标": "@目标" }]
  }]
}]
```

## 引用与装配

引用节点写 `Label`、`Use`，接线与静态值由装配层输入。

```json
{ "Label": "实施", "Use": "执行", "Static": { "MODEL_NAME": "Start@MODEL_NAME" } }
```

| 字段            | 含义                                                          |
| --------------- | ------------------------------------------------------------- |
| `Use`           | 引用的节点库定义名，引用容器时用 `In` 绑定静态与动态输入      |
| `Static`        | 引用执行节点时绑定定义声明的静态输入端口                      |
| `In`            | 引用容器时绑定定义声明的传入端口，写法见[容器定义](#容器定义) |
| `From`          | 仅引用执行节点时注入接线                                      |
| `MaxExecutions` | 覆盖库定义的自身上限（执行节点）或组内统一上限（容器）        |

引用同一个容器定义多次必须给不同 `Label`。引用执行节点时，定义未给默认值的静态输入必须由 `Static` 绑定；引用容器时，`In` 必须绑定全部传入端口。引用容器不写 `Static`，容器对外只暴露 `Outputs` 声明的端口，下游消费写 `容器标签@端口`。静态输出只供下游 `Static` 绑定读取，不进入 `From`。

## 上游接线

`From` 是执行节点的唯一接线字段，数组元素是一个启动组，组内是目标输入端口名到来源端口引用的映射。

```json
"From": [
  { "计划": "计划@结论" },
  { "计划": "评审@结论" }
]
```

组间任一齐备即启动，组内全部齐备。组内可省略带默认值的输入端口。来源可以是执行节点或容器：容器写 `容器标签@端口`，执行节点写 `来源@端口`。执行节点按来源产出版本判定启动，同一版本不重复启动；组内有信号输入时只由该组信号来源的新版本驱动。组内任一 Trigger 绑定取到 `false` 时该组不驱动启动。

容器成员的来源只落在本容器子树内，取容器传入内容写 `@端口`。容器成员的 `In` 与 `From` 同在一个作用域求值，容器外的节点与端口对成员不可见，跨边界传值一律经容器的 `In` 与 `@端口`。

## 输出校验

`Validate` 给执行节点一条输出校验规则：执行收口后按声明端口拼接出的文本判定，不通过则停在阻塞等待返工。

| 字段        | 含义                                                           |
| ----------- | -------------------------------------------------------------- |
| `Predicate` | `NonEmpty`、`TextContains`、`TextNot`、`TextEquals`、`Pattern` |
| `Argument`  | 谓词参数，`NonEmpty` 不需要                                    |

声明 `Validate` 的节点必须声明至少一个文本语义的输出端口。执行节点引用可以互相指回构成环，环必须有环外来源或环内输入节点才能启动，收敛由输出校验或 `MaxExecutions` 兜底。

## 关键约束

加载时逐条校验，非法项一次给出。要点：

- 每条流程有且只有一个根节点，必须声明 `Start`，至少一个不带 `Value` 的 `Text` 端口；`HostStartInputs` 的键必须是已声明的开始端口，绑定端口不能带 `Value`，宿主输入名不能为空。静态开始端口必须有 `Value` 或宿主输入绑定。
- 每个执行节点、输入节点与审批节点都必须能从开始经 `From` 引用边到达。
- 节点名与标签不能为空、不能含 `@` 与 `/`、不能用保留的 `Start`，同一容器内唯一，库定义名库内唯一。
- `Kind` 必填且取值必须是已注册类型；引用节点不写执行配置、子节点、`Inputs` 与 `Validate`。
- 端口名在同一节点内唯一，端口类型必须是已注册类型；`From` 每个组覆盖全部不带默认值的非静态输入端口，来源必须存在且不能是静态端口。
- 派发执行的节点必须由静态端口 `MODEL_NAME` 得到值，静态来源必须是静态端口，引用的库定义必须存在。标准来源是宿主输入 `MODEL`。
- 容器成员的 `From` 与容器成员的 `In` 都在所属容器作用域里求值：来源只落在该容器子树内的节点或该容器声明的传入端口，容器外的节点与端口不可见。
- 开始端口只在流程作用域出现，写在根节点的 `From` 或根容器的 `In` 里，容器成员不能直接引用。
- 同一执行节点的执行次数达到 `MaxExecutions` 上限后不再启动。
