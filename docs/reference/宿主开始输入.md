# 宿主开始输入

`.kuroe/hostStartInputs.json` 声明哪些开始端口由 Kuroe 给值。顶层只写 `HostStartInputs`，键是流程名，值是开始端口名到宿主输入名的映射：

```json
{
  "HostStartInputs": {
    "实施与检查": { "启动路径": "WORKSPACE_PATH", "模型": "MODEL" },
    "仓库实施与检查": { "任务目录": "TASK_WORK_PATH", "MODEL_NAME": "MODEL" }
  }
}
```

| 宿主输入         | 值                                       |
| ---------------- | ---------------------------------------- |
| `WORKSPACE_PATH` | 工作区根目录绝对路径，即 `-d` 给出的目录 |
| `TASK_WORK_PATH` | 本次任务目录绝对路径                     |
| `MODEL`          | 任务启动时选中的本地模型名               |

## 规则

- 端口名不受宿主输入名约束，绑定只由这张表决定。
- 表里的开始端口必须承载 `Text`，且不能带 `Value`。
- 带 `Default` 的开始端口可以进表，进表后由宿主值优先。
- 表里的端口在任务提交时由 Kuroe 给值，不接受用户输入。
- 表之外承载内容的开始端口按普通用户输入处理，不承载内容的开始端口不进入提交，端口名与宿主输入名相同也不例外。
- 没有表项的流程不获得宿主输入。
- 流程展示与提交表单使用同一份表。

## 校验

表随启动读取，启动时校验结构与名字。表与流程开始入口的一致性在任务提交时校验。流程导入与流程编译不涉及这份表，需要宿主给值的流程在导入后补表。

## 使用

流程只声明开始端口，不写宿主绑定。标准写法是声明常量开始端口，在表里绑定到 `MODEL`，容器经 `Bindings` 转发，执行节点用 `Bindings` 取用。模型来源见[模型接入](../usage/模型接入.md)，路径绑定的写法见[流程定义](流程定义.md#路径与任务目录)，任务目录的位置见[安装与运行](../usage/安装与运行.md#工作目录)。
