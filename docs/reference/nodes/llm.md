# Llm

`Kind: Llm` 是唯一调用模型的节点类型，派发执行并按端口交回产出。

## 端口

- 必须声明静态输入端口 `MODEL_NAME`，类型 `Text`，模式 `Constant`，角色 `Configuration`。标准写法是由开始端口取模型，并在宿主开始输入表里把该端口绑定到 `MODEL`，见[模型接入](../../usage/模型接入.md)。
- 输入与输出端口取 `Text`、`Context` 与 `Signal`。所有类型未写 `Mode` 时默认 `Plain`，需要门控时显式写 `Trigger`。
- `Context` 输入置于目标输入最前。`Context` 输出由来源透传，不需要交回。
- `Llm` 接受 `From` 引入的未声明 `Text` 输入。

## 类型参数

| 参数           | 类型     | 含义                                                                    |
| -------------- | -------- | ----------------------------------------------------------------------- |
| `Prompt`       | string   | 本次执行的要求，与轮次一起构成本轮指令                                  |
| `Tools`        | string[] | 工具白名单，按工具路径前缀匹配，见[工具配置](../工具配置.md#工具白名单) |
| `SystemPrompt` | string[] | 恒定系统指令块，按序拼接置于请求最前                                    |
| `ToolPorts`    | object   | 工具路径变量到输入端口的映射，见[工具变量](../流程定义.md#工具变量)     |

`SystemPrompt` 的内容必须恒定，才能命中服务商前缀缓存。空白块在导入时报错。

## 执行

节点在静态输入就绪或有 `From` 新产出时启动。`Prompt` 写在指令最前，第 2 轮起追加轮次说明。`Emission: Once` 的节点首次成功发布后冻结，`Repeated` 节点逐次发布；`MaxExecutions` 未写时为 100。

每次请求都带完整工具面。模型请求工具时，节点在同一执行内执行工具并把结果交回模型，直到模型不再请求工具。工具调用轮次不设上限，终止、停止与暂停仍会中断执行。

节点结束时经契约工具 `SubmitPortValues` 交回动态端口与由执行产出的常量端口。未交回时同一执行内追问最多两次，仍缺则停在阻塞等待重新执行。`GetStatus` 与 `ReportCannotComplete` 始终可用，见[契约工具](../tools/contract.md)。

## 中断与恢复

模型请求由 SDK 自动重试 3 次，重试仍失败才进入执行收口。请求因暂停任务、停止执行、任务终止、进程退出、超时或传输中断而结束时，已收到的文本与思考内容作为助手消息留在会话历史中，并写入存档执行记录的恢复数据。正常完成的执行也在收口时写入最终会话历史作为恢复数据。

可恢复条件由 Llm 类型判断：

- 历史末尾是用户消息、工具消息，或仅含文本与思考内容的助手消息。
- 会话末尾没有等待结果的工具调用。
- 恢复数据格式可读，模型与当前声明一致。
- 来源执行未上报无法完成。

引擎另外只在节点仍阻塞且未取消、执行未完成、未达到执行上限、任务未完成或终止时建立恢复计划。

可恢复的中断收口后任务自动暂停。恢复任务会派发恢复计划，新建一次执行，沿用来源执行的输入、工具面与已交回端口，以存档的会话历史继续同一轮对话，不重新发送节点指令。已交回端口无需再次提交，重复提交会被拒绝；执行详情里的请求次数只统计本次执行。无法完成原因随执行契约继承，但 Llm 不恢复已上报无法完成的执行。

不可恢复的中断按普通阻塞处理，只能重新执行。重新执行会让当前阻塞不再可恢复、作废该节点已发布产出，并新建一次执行，不继承原会话历史；已保存的恢复数据保留。中断发生在本地工具执行期间时，会话末尾是未回填的工具调用，不提供恢复。

恢复依赖 OpenAI 兼容接口接受以助手消息结尾的历史。服务端拒绝时该次恢复失败，节点重新停在阻塞，可以再次恢复，也可以改走重新执行。恢复数据是否产生只取决于会话历史，与失败种类无关；恢复准备由 Llm 类型按历史、模型与来源契约判断，已上报无法完成的执行不提供恢复。

正常退出、暂停任务与停止执行会走执行收口，半截内容能写入存档。进程被强制终止时，最后一次落盘之后的内容可能丢失。恢复执行已经派发但尚未收口时被强制终止，该次恢复没有新的恢复数据；存档若已记录本次请求用量，恢复时不再回退到来源执行，否则仍可使用来源执行的恢复数据再次恢复。

只有能给出可继续恢复数据的节点类型才能恢复。恢复数据本身在每次收口都保留，是否恢复由任务编排按节点阻塞与执行状态决定，已完成与已终止任务的执行不恢复。`Command`、`FileRead` 与 `FileWrite` 不提供恢复数据，中断后只能重新执行；`Approval` 与 `Input` 恢复的是等待回答，不属于执行恢复。

## 请求与用量

一次执行内的模型请求次数、token 用量与上下文随执行记录保留，执行详情与 `KuroeInfo/GetExecution` 可查。请求次数与 token 用量在运行中给出当前累计，收口后为最终值。执行详情里的请求次数只统计本次执行。

- 请求次数按真正发出的请求计，工具往返与契约追问各计一次。未返回用量的请求数附在次数后。
- token 用量取自 provider 返回的 usage，分输入、输出与合计，另记缓存输入与推理 token。
- 缓存输入是输入的子集，推理是输出的子集，都不重复计入合计。
- 展示分输入、输出与合计三项，缓存输入写在输入项内，推理写在输出项内。输入与输出给出占合计的比例，缓存输入给出占输入的比例，推理给出占输出的比例；基数未知、为 0 或子项大于母类时不显示比例。
- 上下文取最近一次返回用量的请求的输入 token 数，表示该请求发送的上下文规模，不随请求累计；该请求没有给出输入 token 数时显示未提供。
- provider 不返回 usage 时该请求计入未返回用量，不按 0 计；此时清除上下文，显示未提供。

## 工具

`Tools` 只放行写出的路径子树，未写时不给出白名单内的工具，契约工具仍会附上。被放行且带路径变量的工具必须用 `ToolPorts` 完整映射，否则导入报错。工具分组与函数见[内置工具](../tools/index.md)。

```json
"Inputs": [{ "Name": "任务路径", "Type": "Text", "Mode": "Constant" }],
"Bindings": { "任务路径": "@任务路径" },
"Tools": ["file/read", "GetLocalTime"],
"ToolPorts": { "file/read": { "root": "任务路径" } }
```

## 示例

```json
{
  "Name": "撰写",
  "Kind": "Llm",
  "Emission": "Once",
  "Prompt": "按目标撰写正文。",
  "SystemPrompt": ["回答使用简体中文。"],
  "Inputs": [
    { "Name": "目标", "Type": "Text", "Mode": "Constant", "Role": "Content" },
    { "Name": "MODEL_NAME", "Type": "Text", "Mode": "Constant" }
  ],
  "Bindings": { "目标": "@目标", "MODEL_NAME": "@MODEL_NAME" },
  "Outputs": [{ "Name": "正文", "Type": "Text", "Mode": "Constant" }]
}
```
