## Kernel 定位

Kernel 提供中性契约、值对象、任务与表现模型、任务运行时、任务持久化、输入通道，以及执行单元的机制实现。Kernel 不出现图与节点词汇，不定义具体流程种类，不包含具体流程记录。流程种类常量与流程记录由流程实现拥有。

图流程、代码流程与 MAF 流程各自提供记录项目与编解码器。新增流程实现不需要修改 Kernel 的任务记录契约。

## 执行模型

执行身份、执行状态、执行产出与恢复负载只在 `Kuroe.Execution.Shared` 定义。图侧只保留 `GraphExecutionInput` 与 `GraphExecutionContract` 两个图语义类型；执行状态、标识、产出与恢复负载直接使用中性类型。

执行状态迁移只在 `Kuroe.Execution` 的 `ExecutionInstance` 类内，写方法为 `internal`。过程记录、用量、恢复数据的附加与运行器接线由执行派发器完成。

`ExecutionIndex` 只分配执行号并登记归属，执行实例由调用方提供的创建委托建立。

`IExecutionRuntime` 只暴露控制面：建立、恢复、准备恢复、运行收口、中断、拒绝未收口执行与退出收口。流程控制不直接调用状态迁移方法。

`IExecutionContractWriter` 是执行契约写入口，只接受端口产出交回与无法完成上报。

`GraphExecution` 是图侧适配层：把图执行输入装配为中性执行请求，并在图端口契约与中性执行契约之间转换，不持有执行状态机写能力，也不持有执行运行期。

`ExecutionInputValue.Source` 是执行详情的来源描述。`ExecutionInputValue.SourceKey` 是执行记录使用的来源标识，由流程控制解释。图流程把输入出处编码为 `SourceKey`，执行记录捕获优先使用它，来源描述只进入展示。

## 流程身份与提交

`FlowIdentity` 由流程名、流程种类与实现标识组成，保存在流程记录上。恢复按身份选择流程实现，提交按流程名选择流程实现。

`TaskActions` 只有按流程名与按流程实现两条提交入口，两者都经 `IFlowSubmission.Prepare`。流程实现负责自己的开始输入校验与初始状态。

## 控制实例生命周期

`FlowRuntime` 按 `IFlowControl.Completion` 维护活跃控制索引。`Loop` 是工作循环，退出不代表控制实例不再需要。代码定义流程在终止与退出中断时完成 `Completion`；图流程的 `Completion` 等于 `Loop`；MAF 流程在终止、退出中断与流程走完时停止推进循环，循环退出后完成 `Completion`。

`IFlowControl` 只含各流程共同的启动、暂停、恢复、终止与收口。按步骤重跑由 `IFlowRerun` 提供，只有支持重跑的流程实现才实现它；图流程按节点重跑，MAF 流程放弃检查点从入口重跑；`IFlowRuntime.Rerun` 对不提供的流程返回零。图流程的 `Input` 与 `Approval` 由执行函数内部等待外部输入，输入交付完成等待，执行收口后由控制实例推进下游。执行被暂停或退出中断时，控制实例重新派发等待执行。宿主只交付输入，不调用流程推进。

启动与恢复先建立控制实例，把控制附加到任务并登记活跃索引，再调用 `Start` 或 `Restore`。控制实例在启动期间读取任务状态、快照与自身控制时，任务已经能返回完整控制。启动或恢复完成后才开始跟踪 `Completion`，图流程的 `Loop` 因此已经换成实际推进循环。

## 任务域访问

流程控制只通过 `ITaskFlowContext` 读写任务。`ITaskFlowContext` 继承只读的 `ITaskFlowView`，表现与任务快照只依赖 `ITaskFlowView`。`WorkTask` 只公开宿主与任务域需要的成员，任务 Gate、过程记录写入、完成标记、暂停恢复与执行记录登记通过接口显式实现或保持程序集内部。

等待步骤只有 `ITaskFlowView.Pending` 一个来源，由任务从任务域的输入登记读取。`IFlowPresentation` 只提供流程视图，不提供等待步骤。等待步骤的执行函数以任务标识与流程步骤路径登记输入，任务清理时同步清空登记。

任务快照由 `TaskSnapshotFactory` 统一装配。它读取只读任务视图、开始文本与流程视图，流程实现不构造 `TaskSnapshot`。

任务域按执行号通过 `TaskRegistry.FindOwnedExecution` 取得执行与归属任务。任务动作与信息工具不反解析执行请求里的归属文本。

## 执行契约工具

执行契约工具只依赖 `IFlowExecutionGateway`、`IExecutionContractWriter`、`ExecutionRequest` 与 `ExecutionContractRules`。端口交回、无法完成上报与状态读取不引用具体流程控制，不强制转换为图控制。

流程实现只要在执行请求的 `OutputPorts` 声明输出端口，就能使用同一套契约工具。状态读取按执行请求的端口与执行记录的契约计算缺口，轮次上限来自 `ExecutionRequest.MaxAttempts`。

## MAF 流程

MAF 流程把步骤推进交给 `Microsoft.Agents.AI.Workflows` 运行期，Kuroe 保留任务外壳与执行单元。每个步骤对应一次 Kuroe 执行，执行记录、用量、中断与恢复数据仍由任务域持有。

流程定义由宿主以代码给出，经 `IMafFlowSource` 提供。提交与恢复先校验定义：步骤标识唯一且不含 `/`，连接两端存在，每个步骤至多一个上游，开始端口包含 `MODEL_NAME` 且不重复。步骤标识同时是执行目标标识，宿主给出的执行目标标识必须与它一致。

步骤的输入是直接上游步骤的输出，入口步骤的输入是开始端口文本，`MODEL_NAME` 不进入执行输入。分叉后的步骤可以并行执行，收敛需要多个上游，当前不支持。

流程状态片段保存开始状态、运行期检查点与未走完的步骤。检查点不作为第二份权威状态，任务存档仍是任务级权威记录。检查点存储按会话与父检查点维护索引。

执行被中断时，推进循环停止当前 MAF 运行，任务停在暂停等待恢复；恢复放弃当前检查点，从入口重新执行全部步骤。步骤之间的暂停从最近检查点继续。步骤失败让任务停在阻塞，重新执行放弃检查点并从入口重跑。

宿主经 `AddKuroeMafFlows` 注册流程实现、编解码与模板来源，核心装配不引用 MAF 运行期。MAF 流程进入流程目录，可以从 Console 与 CLI 提交。MAF 项目位于 `Source/Kuroe.Maf`，不属于 `Kuroe.Flow` 区域，对 `Kuroe.Flow` 没有项目引用。

MAF 流程不登记输入通道，其任务没有等待步骤。

## 存档编解码

任务存档文档只保存通用任务字段、执行记录、流程身份与两段流程片段。流程片段由 `IFlowRecordCodec` 解释，中央序列化不按流程种类分支。

执行记录由任务域从执行快照捕获。流程实现只提供 `FlowRecord`，包含流程定义与流程状态，不捕获执行记录。

图流程、代码流程与 MAF 流程各自提供记录项目与编解码项目，注册到宿主时与 `FlowProvider` 并列；需要进入流程目录的实现另注册 `IFlowTemplateSource`。编解码端口 `IFlowRecordCodec` 与 `FlowRecordData` 位于 `Kuroe.Tasks.Records.Shared`。新增流程实现提供自己的定义记录、状态记录、种类常量与编解码器即可，不修改中央序列化项目 `Kuroe.Tasks.Persistence.Serialization.Shared` 与 `Kuroe.Tasks.Persistence.Json`。编解码错误经返回值报告，不穿透 `FormatException`。

存档版本为 15。JSON 读取入口只接受版本 15，其他版本按版本不符拒绝。

## 新增流程实现

1. 实现 `IFlowIdentity`，按流程名与 `FlowIdentity` 认领提交与恢复。
2. 实现 `IFlowSubmission`、`IFlowState`、`IFlowControlFactory` 与 `IFlowControl`；需要恢复时另实现 `IFlowStateBinder`，支持按步骤重跑时另实现 `IFlowRerun`。
3. 需要外部输入时，由步骤的执行函数以任务标识与流程步骤路径向 `IInputChannel` 登记等待。交付完成等待，执行收口后由控制实例继续推进。等待执行被暂停或退出中断时，控制实例重新派发执行。
4. 实现 `IFlowPresentation` 的 `CaptureView` 与 `IFlowRecordSource` 的 `CaptureRecord`。等待步骤由任务视图提供，表现不另设入口。
5. 把端口组合为 `FlowProvider` 注册。状态绑定与流程记录来源按需提供，不需要的能力以空值表达，不使用空实现对象。
6. 提供自有定义记录、状态记录与流程种类常量，实现 `IFlowRecordCodec` 并注册。编解码错误经返回值报告。
7. 需要进入流程模板目录时单独注册 `IFlowTemplateSource`，由中性模板目录聚合。
8. 在 `ExecutionRequest.OutputPorts` 声明输出端口后直接使用中性契约工具。
9. 由 MAF 运行期承载推进时，把步骤执行桥接到 `IFlowExecutionGateway`，每个步骤建立一次执行。

新增流程实现不构造 `TaskSnapshot`，不捕获执行记录。任务快照装配与执行记录捕获由任务域完成。
