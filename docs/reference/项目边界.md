## 执行模型

执行身份、执行状态、执行产出与恢复负载只在 `Kuroe.Execution.Shared` 定义。图侧只保留 `GraphExecutionInput` 与 `GraphExecutionContract` 两个图语义类型；执行状态、标识、产出与恢复负载直接使用中性类型。

执行状态迁移只在 `Kuroe.Execution` 的 `ExecutionInstance` 类内，写方法为 `internal`。过程记录、用量、恢复数据的附加与运行器接线由执行派发器完成。

`ExecutionIndex` 只分配执行号并登记归属，执行实例由调用方提供的创建委托建立。

`IExecutionRuntime` 只暴露控制面：建立、恢复、准备恢复、运行收口、中断、拒绝未收口执行与退出收口。流程控制不直接调用状态迁移方法。

`IExecutionContractWriter` 是执行契约写入口，只接受端口产出交回与无法完成上报。

`GraphExecution` 是图侧适配层：把图执行输入装配为中性执行请求，并在图端口契约与中性执行契约之间转换，不持有执行状态机写能力，也不持有执行运行期。

`ExecutionInputValue.Source` 是执行详情的来源描述。`ExecutionInputValue.SourceKey` 是执行记录使用的来源标识，由流程控制解释。图流程把输入出处编码为 `SourceKey`，执行记录捕获优先使用它，来源描述只进入展示。

## 流程身份与提交

`FlowIdentity` 由流程名、流程种类与实现标识组成，保存在流程记录上。恢复按身份选择流程实现，提交按流程名选择流程实现。

`TaskActions` 只有按流程名与按流程实现两条提交入口，两者都经 `IFlowSubmission.Prepare`。流程实现负责自己的开始输入校验与初始状态。

## 控制实例生命周期

`FlowRuntime` 按 `IFlowControl.Completion` 维护活跃控制索引。`Loop` 是工作循环，退出不代表控制实例不再需要。代码定义流程在终止与退出中断时完成 `Completion`；图流程的 `Completion` 等于 `Loop`。

启动与恢复先建立控制实例，把控制附加到任务并登记活跃索引，再调用 `Start` 或 `Restore`。控制实例在启动期间读取任务状态、快照与自身控制时，任务已经能返回完整控制。启动或恢复完成后才开始跟踪 `Completion`，图流程的 `Loop` 因此已经换成实际推进循环。

## 任务域访问

流程控制只通过 `ITaskFlowContext` 读写任务。`WorkTask` 只公开宿主与任务域需要的成员，任务 Gate、过程记录写入、完成标记、暂停恢复与执行记录登记通过接口显式实现或保持程序集内部。

任务快照由 `TaskSnapshotFactory` 统一装配。它读取任务身份、开始输入、开始文本、任务状态、执行列表、过程记录与时间，并接收流程实现提供的流程视图与等待步骤。流程实现不构造 `TaskSnapshot`。

任务域按执行号通过 `TaskRegistry.FindOwnedExecution` 取得执行与归属任务。任务动作与信息工具不反解析执行请求里的归属文本。

## 执行契约工具

执行契约工具只依赖 `IFlowExecutionGateway`、`IExecutionContractWriter`、`ExecutionRequest` 与 `ExecutionContractRules`。端口交回、无法完成上报与状态读取不引用具体流程控制，不强制转换为图控制。

流程实现只要在执行请求的 `OutputPorts` 声明输出端口，就能使用同一套契约工具。状态读取按执行请求的端口与执行记录的契约计算缺口，轮次上限来自 `ExecutionRequest.MaxAttempts`。

## 存档编解码

任务存档文档只保存通用任务字段、执行记录、流程身份与两段流程片段。流程片段由 `IFlowRecordCodec` 解释，中央序列化不按流程种类分支。

执行记录由任务域从执行快照捕获。流程实现只提供 `FlowRecord`，包含流程定义与流程状态，不捕获执行记录。

图流程与代码流程各自提供编解码项目，注册到宿主时与 `FlowProvider` 并列。新增流程实现提供自己的定义记录、状态记录与编解码器即可，不修改 `Kuroe.Flow.Persistence.Serialization.Shared` 与 `Kuroe.Flow.Persistence.Json`。

存档版本为 14。JSON 读取入口接受版本 14，迁移版本 13 的流程字段后交给同一映射器。

## 新增流程实现

1. 实现 `IFlowIdentity`，按流程名与 `FlowIdentity` 认领提交与恢复。
2. 实现 `IFlowSubmission`、`IFlowState`、`IFlowStateBinder`、`IFlowControlFactory` 与 `IFlowControl`。
3. 实现 `IFlowPresentation` 的 `CaptureView` 与 `Pending`，实现 `IFlowRecordSource` 的 `CaptureRecord`。
4. 把端口组合为 `FlowProvider` 注册。
5. 提供 `IFlowRecordCodec` 与自有定义、状态记录并注册。
6. 在 `ExecutionRequest.OutputPorts` 声明输出端口后直接使用中性契约工具。

新增流程实现不构造 `TaskSnapshot`，不捕获执行记录。任务快照装配与执行记录捕获由任务域完成。

## 边界检查

新增项目引用、跨层类型或执行写入口时先确认 `Tests/Architecture/RepositoryLayoutTests.cs` 的对应断言。该测试覆盖项目引用白名单、源码命名空间扫描、执行状态机归属、执行模型唯一性、宿主依赖、契约工具中性、持久化图依赖、流程记录编解码边界、任务快照装配归属与执行记录来源标识。
