# Kuroe.Maf.Control

MAF 流程控制：把流程定义构造成工作流运行，由 MAF 运行期决定步骤推进，每一步对应一次 Kuroe 执行，并负责检查点、视图、存档捕获与提交恢复。

## 职责

- 流程控制实例：启动与恢复 MAF 运行，消费运行事件，按步骤建立执行，终止与重新执行。
- 工作流构造：开始执行器接全部入口，步骤节点来自定义，连接来自定义，执行器标识取自步骤标识。
- 步骤节点：按输入绑定累积来源，按启动组判定齐备，组内 AND、组间 OR、触发条件、端口种类与同端口多来源在节点内处理；执行状态随工作流状态保存，从检查点恢复不会重复执行。
- 步骤执行桥接：一次步骤运行对应一次执行，按端口聚合输入，交回的端口与触发位作为消息交给下游。
- 执行请求：输出计划决定输出端口的种类、触发与交回要求；开始端口种类与模式进入视图与模板。
- 重新执行：放弃检查点与旧运行，等旧运行退出后从入口启动新运行。
- 第一阶段不接入容器、等待、结构节点、环与多次执行。
- 检查点：把运行期检查点写入流程状态，写入受任务锁与检查点冻结控制，索引留在内存。
- 运行事件：把 MAF 运行事件转成流程运行事件，执行器标识还原为步骤。
- 提交与恢复：校验开始输入、建立流程状态、从存档重建执行。
- 流程表现：步骤来自定义，状态与执行来自任务。
- 存档捕获：流程身份、定义摘要与运行期检查点。
- 模板来源：宿主定义的流程进入流程模板目录。
- 步骤运行面：向步骤给出停止推进信号与中断上报入口。

## 边界外

- 不含流程定义。
- 不含流程记录与编解码。
- 不含执行实现与任务域。
- 不依赖图、节点与图流程。
