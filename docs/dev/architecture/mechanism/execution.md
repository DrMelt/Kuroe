# 执行模型

一次执行从流程控制装配、经运行器跑到收口，执行核只消费装配结果，执行记录由任务域捕获。本文说明这条链路上的跨模块约定，单个模块的职责见[边界文档](../architecture.md#项目文档索引)。

## 装配到运行

节点在执行函数里建立执行参数，并以执行器工厂实例给出装配结果。装配结果包含执行步骤标识、运行器工厂与类型参数。执行核只消费装配结果，不按字符串或键选择运行器。

运行器只读取执行请求、执行参数与执行号，不引用节点项目、节点类型或节点路径结构。节点项目引用自身运行器实现项目，等待型运行器使用的流程步骤键由节点侧放入执行参数。

`ExecutionInvocation` 是同一份装配结果的形状，图流程、代码流程与 MAF 流程都构造它。

## 请求入口

`IExecutionRequestEntry` 是执行契约的写入口，只接受端口产出交回、无法完成上报与状态读取。执行运行建立入口并交给运行器，运行器再交给契约工具。运行器与工具都不持有全局提交器。

恢复由同一执行器工厂实现 `IExecutionRestorer` 时提供，恢复准备与恢复运行都使用装配结果。

## 控制面

`IExecutionRuntime` 只暴露控制面：建立、恢复、准备恢复、运行收口、中断、拒绝未收口执行与退出收口。流程控制不直接调用状态迁移方法。

`ExecutionIndex` 只分配执行号并登记归属，执行实例由调用方提供的创建委托建立。归属任务按执行号查询，任务域与信息工具都经 `TaskRegistry.FindOwnedExecution` 取执行与归属。

## 运行包裹

过程记录、用量、恢复数据与契约状态的附加，以及运行器接线，由执行运行包裹完成。执行派发器只负责排队与调度。

展示所需的历史由 `IExecutionConversationReader` 从恢复数据读取为中性消息，Llm 项目提供实现，读取不发起模型请求。展示层只消费中性消息与执行快照，决定角色、内容种类、截断与省略。存档内容见[存档与持久化](persistence.md)。

## 图侧适配

`GraphExecution` 把图执行输入装配为中性执行请求，并在图端口契约与中性执行契约之间转换，不持有执行状态机写能力，也不持有执行运行期。

`ExecutionInputValue.Source` 是执行详情的来源描述，`ExecutionInputValue.SourceKey` 是执行记录使用的来源标识，由流程控制解释。图流程把输入出处编码为来源标识，执行记录捕获优先使用它，来源描述只进入展示。
