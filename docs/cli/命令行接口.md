# 命令行接口

Kuroe.Cli 是一次性命令行入口：每次调用完成一个操作后退出，不保留进程内状态。CLI 不装配内置助手，也不使用随产物导出的源码与文档。CLI 只注册 `Container` 与 `Llm` 节点，包含 `Input` 或 `Approval` 的流程在 CLI 中不可用。入口差异见[入口与分工](../usage/入口与分工.md)，产物与工作目录见[安装与运行](../usage/安装与运行.md)。

## 运行

在产物目录执行：

```powershell
dotnet Kuroe.Cli.dll <命令> [-d <工作目录>]
```

`-d` 省略时用进程当前目录。`-h` 打印用法，参数错误以非零退出码结束。CLI 不读取 stdin，也不显示交互提示。参数值以连字符开头时用 `--` 结束选项解析，如 `config set Runtime:Temperature -d <工作目录> -- -0.5`，全局选项写在 `--` 之前。`run`、`config set`、`provider add` 与 `provider key` 在有剩余参数位置时会把未定义的选项当作参数值，不报错，拼写错误需自行核对；`provider add` 与 `provider key` 的误写会被当作凭据。解析失败时用法写 stderr，stdout 只承载命令结果。

## 命令

| 命令 | 说明 |
| --- | --- |
| `run --flow <流程> [--title <标题>] <目标>` | 提交任务并在本进程内驱动到结束 |
| `flow list` | 列出流程与规模 |
| `flow show <流程>` | 打印流程字段与节点树 |
| `flow add <文件>` | 导入流程与节点库，可编译的同名流程覆盖 |
| `model list` | 列出已注册模型并标记当前模型 |
| `model use <模型>` | 切换模型，要求已注册 |
| `model none` | 取消模型选择 |
| `model add <模型> <提供商>` | 把模型注册到提供商 |
| `model rm <模型>` | 注销模型，是当前模型时一并取消选择 |
| `provider list` | 列出提供商 |
| `provider add <名> <端点> [凭据]` | 新增提供商 |
| `provider key <名> [凭据]` | 更换提供商凭据 |
| `provider rm <名>` | 删除提供商，仍被模型引用时拒绝 |
| `catalog list` | 列出提供商与模型 |
| `catalog export <文件>` | 导出目录，凭据替换为占位符 |
| `catalog import <文件>` | 合并导入目录，已有条目不受影响 |
| `config list` | 打印生效配置与来源 |
| `config set <路径> <值>` | 写入用户层设置；`Runtime:LogLevel` 下次运行生效，`Assistant:Language` 只作用于 Kuroe.Console，见[入口与分工](../usage/入口与分工.md) |
| `config unset <路径>` | 删除用户层中的该项 |

`flow`、`model`、`provider`、`catalog`、`config` 不带子命令时分别列出流程、当前模型、提供商、目录与配置。

`provider add` 与 `provider key` 的凭据参数省略时读环境变量 `KUROE_PROVIDER_KEY`。凭据写在命令行会进入 shell 历史，脚本与 CI 中优先用环境变量。

## run

`run` 在一个进程内完成提交与推进：

1. 按流程提交任务，任务工作目录仍建立在 `.kuroe_tasks/` 下。
2. 全部执行节点的模型文本流式写 stdout，工具调用写 stderr。
3. 等待任务进入完成、阻塞或取消。
4. 给出退出码。

`run` 不接受 `--answer` 与 `--approve`，也不读取 stdin；这两个选项及其别名 `-a`、`-y` 写在 `--` 之前会报错，写在 `--` 之后按目标文本处理。流程包含 `Input` 或 `Approval` 节点时无法在 CLI 中编译，`run` 返回 1 并输出编译错误。

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 参数、装配或操作失败，含任务取消 |
| 3 | 任务阻塞 |

任务是内存态。进程退出时全部任务取消，`run` 不能中断后跨进程恢复。CLI 因此不提供 `task list`、`task show`、`task answer` 这类跨进程任务命令。需要逐级查看、批准或返工时用 Kuroe.Console，见[入口与分工](../usage/入口与分工.md)。

## 流程支持范围

CLI 的流程编译器只注册 `Container` 与 `Llm`。包含 `Input` 或 `Approval` 的流程仍可出现在 `.kuroe/flows.json`，`flow list` 把它们列在「不可用流程」下并给出原因。`flow show` 与 `run` 对这类流程返回编译错误。

`flow add` 只保存可编译的流程。导入文件里不可编译的流程不导入，逐条写到 stderr，不影响同一文件里的其他流程；与已有流程同名但不可编译时保留原流程。节点库本身不合法时整个导入不生效。等待型节点由 Kuroe.Console 运行，见[入口与分工](../usage/入口与分工.md)。

## 输出

- stdout：模型文本与命令结果。
- stderr：进度、工具调用、提示行与错误。
- 列表使用制表符分列，表格首行是列名。
- 命令自身返回的错误写成 `错误：<Code>：<Description>`；参数解析错误与用法提示使用 System.CommandLine 的格式，任务状态行不带错误码。
- CLI 自身输出不添加 ANSI 样式，日志不使用颜色；模型文本与工具输出原样透传，可能包含终端控制字符。重定向到文件或管道不改变 CLI 自身输出的内容。
