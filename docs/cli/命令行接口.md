# 命令行接口

Kuroe.Cli 是一次性命令行入口：每次调用完成一个操作后退出，不保留进程内状态。CLI 不提供内置助手。产物与工作目录见[安装与运行](../usage/安装与运行.md)。

## 运行

在产物目录执行：

```powershell
dotnet Kuroe.Cli.dll <命令> [-d <工作目录>]
```

`-d` 省略时用进程当前目录。`-h` 打印用法，参数错误以非零退出码结束。CLI 不读取 stdin，也不显示交互提示。

参数值以连字符开头时用 `--` 结束选项解析，如 `flow add -- -流程.json`，全局选项写在 `--` 之前。解析失败时用法写 stderr，stdout 只承载命令结果。

## 命令

| 命令                                                        | 说明                                 |
| ----------------------------------------------------------- | ------------------------------------ |
| `run --flow <流程> [--title <标题>] --input <端口>=<值>...` | 提交任务并在本进程内执行到结束       |
| `flow list`                                                 | 列出流程与规模                       |
| `flow show <流程>`                                          | 打印流程字段与节点树                 |
| `flow add <文件>`                                           | 导入节点库或流程，可用的同名项覆盖   |
| `model list`                                                | 列出已注册模型并标记当前模型         |
| `model use <模型>`                                          | 切换模型，要求已注册                 |
| `model none`                                                | 取消模型选择                         |
| `model add <本地模型名> <提供商> [提供商模型名]`            | 把模型注册到提供商                   |
| `model rm <模型>`                                           | 注销模型，是当前模型时一并取消选择   |
| `provider list`                                             | 列出提供商                           |
| `provider add <名> <端点> [凭据]`                           | 新增提供商                           |
| `provider key <名> [凭据]`                                  | 更换提供商凭据                       |
| `provider rm <名>`                                          | 删除提供商，仍被模型引用时拒绝       |
| `catalog list`                                              | 列出提供商与模型                     |
| `catalog export <文件>`                                     | 导出目录，凭据替换为占位符           |
| `catalog import <文件>`                                     | 合并导入目录，已有条目不受影响       |
| `config list`                                               | 打印生效配置与来源                   |
| `config set <路径> <值>`                                    | 写入用户层设置                       |
| `config unset <路径>`                                       | 删除用户层中的该项                   |

`flow`、`model`、`provider`、`catalog`、`config` 不带子命令时分别列出流程、当前模型、提供商、目录与配置。

`provider add` 与 `provider key` 的凭据参数省略时读环境变量 `KUROE_PROVIDER_KEY`。凭据写在命令行会进入 shell 历史，脚本与 CI 中优先用环境变量。

## run

`run` 在一个进程内完成提交与推进：

1. 按流程提交任务，每个不带 `Value`、不带 `Default` 且不在 `.kuroe/hostStartInputs.json` 里的开始端口给出一项 `--input`。带 `Default` 的端口可以省略，省略时使用默认值。表里绑定到 `WORKSPACE_PATH`、`TASK_WORK_PATH` 与 `MODEL` 的端口由 Kuroe 提供，不能用 `--input` 给出。表里的键是流程名，见[宿主开始输入](../usage/安装与运行.md#宿主开始输入)。
2. 模型文本流式写 stdout，工具调用写 stderr。
3. 等待任务进入完成、阻塞、暂停或终止。暂停时给出失败说明、用量与恢复提示。
4. 给出退出码。

`run` 不接受 `--answer` 与 `--approve`；流程包含 `Input` 或 `Approval` 节点时返回 1 并输出原因。

| 码  | 含义                             |
| --- | -------------------------------- |
| 0   | 成功                             |
| 1   | 参数、启动或操作失败，含任务终止 |
| 2   | 任务暂停，等待恢复               |
| 3   | 任务阻塞                         |

`run` 写任务存档并占用租约，进程退出后存档保留。CLI 不加载存档，因此不提供 `task list`、`task show`、`task answer` 这类跨进程任务命令。`run` 生成的任务由 Console 加载：已完成的任务显示为已完成，阻塞与未完成的任务以暂停状态出现，可在 Console 中继续或重新执行。

## 流程支持范围

CLI 只支持 `Container`、`Llm`、`FileRead`、`FileWrite` 与 `Command` 节点。包含 `Input` 或 `Approval` 的流程仍可出现在 `.kuroe/flows.json`，`flow list` 把它们列在「不可用流程」下并给出原因，`flow show` 与 `run` 返回不可用原因。节点库写在 `.kuroe/nodes.json`。

`flow add` 按文件顶层字段判定导入节点库还是流程。流程导入只保存可用的流程，不可用的流程不导入，逐条写到 stderr，不影响同一文件里的其他流程；与已有流程同名但不可用时保留原流程。节点库导入要求节点库本身合法且不破坏当前可用的流程，否则整个导入不生效。

## 输出

- stdout：模型文本与命令结果。
- stderr：进度、工具调用、提示行与错误。
- `run` 完成或阻塞时按执行给出请求次数、token 用量与上下文，没有模型请求的执行不输出。请求次数后附未返回用量的次数。token 用量分输入、输出与合计三项，缓存输入写在输入项内，推理写在输出项内；输入与输出给出占合计的比例，缓存输入给出占输入的比例，推理给出占输出的比例；基数未知、为 0 或子项大于母类时不显示比例。上下文取最近一次返回用量的请求的输入 token 数，不随请求累计；该请求没有给出输入 token 数，或其后有请求未返回用量时显示未提供。
- 列表使用制表符分列，表格首行是列名。
- 命令自身返回的错误写成 `错误：<Code>：<Description>`；参数解析错误与用法提示由参数解析器输出。
- CLI 自身输出不添加 ANSI 样式，日志不使用颜色；模型文本与工具输出原样透传，可能包含终端控制字符。
